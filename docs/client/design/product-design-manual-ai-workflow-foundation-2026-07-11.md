# 产品设计：手动 AI 工作流基础决策（2026-07-11）

状态：**当前有效的产品决策基线；尚处于能力发散阶段，不代表所有工作流和页面已进入开发。**

适用范围：AI创品客户端的产品设计、素材处理、图编辑、后续 Agent，以及中台能力目录和业务 API。

真实样例验证、能力现状和生产门禁见：[产品设计需求聚合与真实能力验证矩阵](product-design-requirement-map-and-validation-2026-07-11.md)。

## 1. 先统一产品定义

AI创品不是单纯的 AI 出图工具，也不只是把图片贴到杯子上的 POD 页面。它要帮助用户把照片、图案、品牌资产、故事和灵感，变成可生产、可交付、能表达个性的产品。

品牌口径：

- 信念：**个性，不该被模板定义。**
- 使命：**让每一个想法，都有实现价值的机会。**
- 愿景：**让个性，成为每个人都能定义和创造的日常。**
- 价值观：表达、创造、实现、品质。
- Slogan：**有品，必不同。**

产品语言：**你定义个性，AI 协助创作，供应链负责实现。**

## 2. 手动模式和 Agent 模式不是两套产品

### 2.1 已确认边界

| 模式 | 用户心智 | 系统职责 | 不应发生的事 |
| --- | --- | --- | --- |
| 手动模式 | 我清楚要做什么，希望自己选择和调整 | 提供可见、可逆、可组合的 AI 工作流与编辑控制 | 退化为没有 AI 的上传表单，或把关键生产动作藏起来 |
| Agent 模式 | 我表达目标，希望系统帮我规划和执行 | 理解需求、追问、选择工作流、预填参数、串联能力、给出可确认方案 | 私自消耗积分、替用户做不可逆选择、自动提交生产或订单 |

核心定义：

> **手动模式 = 用户主动选择并控制的 AI 工作流。**
> **Agent 模式 = 理解用户目标后，选择、填参、串联和调用同一批工作流。**

因此，先打磨手动模式不是绕开 Agent，而是在建立 Agent 将来可调用的能力、状态、参数和确认门。后续 Agent 不能另起一套图片能力或生产链路。

### 2.2 后端控制边界

前端负责让用户看懂、选择、编辑、预览和确认；中台与业务后端是最终执行控制面，必须负责：

- 工作流和工具白名单；
- 参数 Schema、产品规格和图片尺寸校验；
- 权限、版权提示、积分/成本预算和并发限制；
- 幂等、任务状态、失败重试、结果回填；
- 生产前确认、审计记录和所有结果沉淀到自有 OSS。

任何模型建议、提示词或 Agent 规划都不能绕过这些控制点。

## 3. 产品设计的共同对象模型

### 3.0 VL 是输入不确定性下的“眼睛和脑子”

用户不可能被要求先把素材解释清楚：他们可能上传商品实拍、低清截图、人物照片、多个零散元素、带文字海报，也可能没有图片。业务端应先调用 VL，把不可控输入转换为可解释的结构化事实和候选路径，而不是要求用户填写技术表单。

VL 的职责包括：

- 识别图片类型、主体、人物/宠物/Logo/文字/二维码/花纹、背景复杂度和可提取区域；
- 识别尺寸、清晰度、比例、透明通道、重复纹样可能性和生产风险；
- 对多图判断每张图片更可能承担的角色，以及素材之间是否存在冲突或重复；
- 没有图片时，根据用户目标判断应进入模板、文字创作、灵感、素材库还是 AI 生成起点；
- 输出候选业务流、所需补充信息、不可自动判断的风险和置信度。

VL **不能**替用户确认版权/授权、最终设计方案、扣费、生产或下单。它只负责提出“我看到了什么、为什么建议这条路、还缺什么”，再由业务流按风险和成本级别决定自动继续、请求用户确认或转人工编辑。

```text
任意输入（图片 / 多图 / 文本 / 无图）
  -> VL 素材理解与风险识别
  -> 业务流选择器（候选路径、置信度、需确认项）
  -> 用户确认或直接进入低风险步骤
  -> 中台原子能力 / ComfyUI 工作流 / Image 2
  -> 结果、生产校验、预览、设计篮
```

### 3.1 图片不是“附件”，必须先确定角色

每张上传图片都要允许用户选择或修正其用途。多图上传不是把文件堆进一个列表。

| 图片角色 | 用途 | 默认能否进入生产图 |
| --- | --- | --- |
| 主设计图 | 成为杯身、正面或局部主体 | 可以，仍需生产校验 |
| 装饰图 | 边框、贴纸、小元素、背景补充 | 可以，按版面组合 |
| 参考图 | 提供配色、风格、材质或构图方向 | 不可以，除非用户改为设计图 |
| Logo / 品牌资产 | 品牌标识、口号、图形规范 | 可以，需安全区与清晰度校验 |
| 文本来源 | 海报、截图、手写字、标语 | 先 OCR 或重建排版后进入设计 |
| 二维码 | 活动、导流、信息触达 | 可以，需保留静区、尺寸与对比度 |
| 待提取资产 | 商品图、实拍图、复杂背景中的花纹或元素 | 先处理后再作为设计资产 |

### 3.2 需要保留的中间资产

从输入到交付不能只留最终杯子预览。至少应可追踪：原始素材、清理/提取结果、标准化设计稿、连续图（如有）、生产校验结果、3D 预览、商品效果图、生产文件和关联任务 ID。

第三方生成或供应商返回的资源必须先沉淀为自有 OSS 资产，再作为对外展示和后续履约依据。

## 4. 用户输入不匹配时的正确处理

不匹配不能只报“尺寸不符合”。系统应说明问题、给出可选解决方式，并让用户确认。

| 场景 | 常见问题 | 手动 AI 工作流应提供的选择 |
| --- | --- | --- |
| 小图或低清图 | 放大后模糊、印刷风险 | 超分修复；局部贴图；拼贴布局；保留原图并提示风险 |
| 横图放到竖向杯身 | 主体被裁掉 | 主体保护智能裁切；向上下扩图；留白海报布局；分区排版；局部贴图 |
| 竖图要做环绕满版 | 两侧接缝明显 | 自动延展；双向连续；四方连续；改为局部贴图 |
| 方形插画或花纹 | 覆盖面积不足 | 满版裁切；延展；二方/四方连续；重复平铺 |
| 人像、宠物、多人物 | 脸、文字或主体落在接缝/把手区 | 人脸和主体保护；安全区提示；自动分区草案；用户确认主次关系 |
| 旧照片、噪点图 | 清晰度和色彩不稳定 | 修复、降噪、超分、色彩还原，并允许保留原始年代感 |
| 截图、海报、手写字 | 字小、倾斜、不可生产 | OCR；文字重建；排版重做；保留原图作为参考 |
| 透明 Logo 或小 Logo | 边缘不清、反差不足 | 去白边；底板/描边；最小可印尺寸；安全区预览 |
| 二维码 | 扫不出或被裁切 | 强制静区、最小尺寸、黑白对比校验，禁止随意 AI 变形 |
| 商品实拍图 | 反光、透视、杯型遮挡 | 花纹/元素提取；去反光；透视校正；背景移除；再适配生产画布 |
| 大文件或特殊格式 | 移动端加载慢、格式兼容差 | 本地预览压缩，生产继续保留原图；兼容 HEIC/PNG/JPG/WEBP 与透明通道 |

版权和权利边界：不提供去水印能力。系统应让用户确认其拥有素材、IP 或品牌内容的使用权；不能以“同款”为名自动复制来源不明的内容。

## 5. 面向用户的工作流按目标命名

用户不应先理解“二方连续”“扩图”这类技术词。页面先按目标组织，进入后再让用户看到必要的选项和生产提示。

当前应持续发散、后续再收敛的候选工作流：

1. **商品图做同款**：从商品图中提取可用花纹或元素，适配自己的产品。
2. **一张图片做满版杯**：把插画、照片或图案延展并铺满目标杯身。
3. **一张照片做纪念杯**：照片、姓名、日期、文字和小元素组合为可生产版面。
4. **多张照片做故事杯**：按人物、时间、地点或事件生成拼贴与版面草案。
5. **Logo 做企业礼品**：锁定品牌规范，批量生成可替换姓名/部门/活动信息的礼品版式。
6. **旅行/文旅做伴手礼**：地标、地图、城市文字、当地纹样和多语言信息组合。
7. **二次元主题杯**：人物主体、台词、背景和授权提示共同约束，不把脸和文字放入接缝或把手区。
8. **已有花纹适配多个杯型**：一次处理后按不同杯型的生产画布输出。
9. **没有图片也能做**：从灵感、文字、模板、品牌资产或 AI 生成背景开始，再由用户编辑和确认。

这不是最终导航清单。后续需要结合真实任务量、成功率、成本、可生产率和用户理解度收敛。

## 6. 电商“做同款”是关键规范流程

该场景不能把“同款”简化成复制。应明确两条用户意图：

| 用户选择 | 对应处理 | 结果边界 |
| --- | --- | --- |
| 我拥有图片/花纹的使用权，想尽量还原 | 提取、清理、透视/反光修正、生产适配 | 尽量还原用户自有内容，并保留来源和处理证据 |
| 我只想参考这种风格，生成新的设计 | 风格与配色分析、生成新方案、用户选择 | 生成新的设计，不直接复刻来源内容 |

推荐主链路：

```text
商品图或设计源
  -> 确认使用权与“还原 / 参考”意图
  -> 判断是花纹、主体、文字还是风格参考
  -> 提取和清理（去反光、透视校正、背景处理）
  -> 保留版 / 变化版候选
  -> 二方或四方连续（仅在需要满版生产时）
  -> 目标产品生产画布
  -> 生产校验
  -> 3D 预览 + 商品效果图
  -> 用户选择并放入设计篮
```

## 7. 可复用的手动 AI 微能力库

手动模式中 AI 应以明确动作出现，并能被工作流和 Agent 共用：

- 主体、人脸、宠物和商品的智能裁切与安全区保护；
- 背景去除、元素提取、反光/透视修正；
- 扩图、延展、补边和背景生成；
- 超分、修复、降噪、色彩还原；
- OCR、文字提取和生产级文字重建；
- 多图拼贴、图层融合、图文排版和版面草案；
- 配色提取、杯体底色匹配、对比度检查；
- 二方连续、四方连续、重复花纹和接缝预检；
- 目标产品/设计面画布适配；
- 生产文件生成、生产校验、3D 预览和商品效果图生成。

## 8. 手动布局与高频人群场景

### 8.1 需要覆盖的布局族

- 单图贴图：照片、头像、Logo，支持尺寸、位置、边框和底色；
- 图文海报：一句话、日期、签名、纪念语；
- 照片拼贴：多照片故事、时间轴、分镜和九宫格；
- 满版平铺：插画、摄影、背景、抽象图；
- 重复花纹：二方或四方连续，面向环绕杯身；
- 分区设计：正面、背面、把手/局部设计面；
- 品牌模板：Logo、标准色、口号、可变姓名/部门/活动字段；
- 纯文字模板：活动、城市、毕业、纪念、社群；
- 素材组合：主图、装饰图、参考图和文字共同组成设计；
- 生产级连续图：用于需要无接缝满版印刷的最终生产图。

### 8.2 必须纳入样例库的人群与任务

| 人群/行业 | 典型目标 | 特别约束 |
| --- | --- | --- |
| 个人送礼 | 旅行、情侣、婚礼、生日、宝宝、宠物、家庭、毕业、老师 | 情绪表达、照片质量差异、姓名日期、一次性成品质量 |
| 文旅与城市礼品 | 地标、地图、地方纹样、博物馆、节日、多语言 | IP/授权、文化元素准确性、多语言排版、批量 SKU |
| 二次元与社群 | 人物、台词、徽章、应援、同好活动 | IP 和公开/商用状态；人物、文字和把手/接缝安全区 |
| 企业礼品 | Logo、品牌色、二维码、活动、员工姓名/部门 | 品牌规范锁定、审批、变量批量替换、预算与版本管理、敏感信息不公开 |
| 电商卖家与创作者 | 商品图做同款、花纹适配多个杯型、上新素材 | 来源权利、批量效率、生产尺寸、一致的效果图和可复用资产 |
| 学校、社团、餐饮、线下活动 | 班级、球队、门店、纪念活动 | 多人信息、有限预算、快速出样、可复用模板 |

## 9. 生产和预览必须分层

1. 每个产品/设计面以供应链 Excel 和商品配置中的生产尺寸为唯一事实源。
2. 3D 模型的 UV/贴图比例只用于预览映射，不能反过来改变生产画布尺寸。
3. 3D 预览和商品效果图用于帮助用户理解，不等于生产校验通过。
4. 生产前必须校验像素尺寸、DPI、清晰度、覆盖范围、接缝、裁切、文字安全区、二维码规则和设计面完整性。
5. 在创作阶段轻提示，在加入设计篮/提交生产前做硬性拦截；每个风险必须给出可执行的修复路径。
6. 后续供应链返回的实物效果图应作为订单证据保存到自有 OSS，并优先用于订单核对和展示。

## 10. 交互底线

- 没有图片时不能死路：提供灵感、文字、模板、品牌资产、素材库和可选 AI 创作入口。
- 每次 AI 处理必须可看前后对比、可取消、可回退、可从候选中选择；不要暗中替换原图。
- “AI 推荐 3 个可编辑版式”仍属于手动模式的 AI 辅助，不等于 Agent。
- 技术概念按需解释；普通用户不需要看到模型、节点、runId、OSS、UV 或内部尺寸换算原理。
- 生产限制不应在第一屏压过创作，但必须在影响结果时清楚出现。
- 对可能产生积分/成本的动作，执行前明确说明消耗和预期输出；失败不能扣费，取消和重试规则可追踪。

## 11. 当前不做的事

- 不在业务前端直接接第三方模型或供应商；所有能力经中台和业务后端调用。
- 不让 Agent 自动提交生产、自动下单或自动消耗不可逆成本。
- 不把“去水印”作为产品能力。
- 不把所有用户都强行导向对话模式；手动工作流必须独立成立。
- 不根据 3D 模型贴图大小推导供应链生产尺寸。

## 12. 下一步：继续发散后再收敛

下一轮先完成以下研究和样例盘点，再决定首批开发范围：

1. 多图设计的布局宇宙：拼贴、主次关系、人物/宠物/文字/Logo 的组合方式。
2. 杯型和设计面的差异：哪些产品需要正反面、把手面、局部区域或环绕连续图。
3. 每一类输入的标准样例集：成功样例、极端样例、不可生产样例和用户修复路径。
4. 将上述用户目标映射为中台工作流、输入 Schema、错误契约、成本和验收标准。
5. 再基于真实样例选择第一批可交付的手动 AI 工作流；之后 Agent 只调用这批已验证能力。
