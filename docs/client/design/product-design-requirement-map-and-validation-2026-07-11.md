# 产品设计需求聚合与真实能力验证矩阵（2026-07-11）

状态：**当前有效；第一轮真实验证已启动。**

关联决策：[产品设计：手动 AI 工作流基础决策](product-design-manual-ai-workflow-foundation-2026-07-11.md)。

本文将“用户说的话”“业务端要完成的事”和“中台可复用能力”拆开。目的不是列模型清单，而是明确每条业务流该如何用真实样本验证可行性。

## 1. 三层边界

```text
用户输入（图片 / 多图 / 文本 / 无图）
  -> VL 素材理解和意图判断
  -> 业务端业务流（状态、确认、设计篮、订单、支付、履约）
  -> 中台能力编排（能力版本、任务、路由、成本、OSS、审计）
  -> 执行能力（ComfyUI 工作流 / Image 2 / 其他模型）
```

| 层 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| VL 素材理解与业务流选择 | 看懂图片和用户意图；输出素材事实、风险、候选业务流、缺失信息和置信度 | 直接扣费、直接生产、替用户确认版权或最终方案 |
| 业务端 | 把用户目标组织成可理解的流程；承接确认、积分、设计篮、订单、支付、蜂鸟履约和用户可见状态 | 直接调用第三方模型；暴露模型/节点/OSS 等工程细节 |
| 中台 | 注册能力、路由执行节点、参数校验、任务队列、结果入 OSS、成本与审计 | 杯子页面、购物车、订单支付规则 |
| ComfyUI / Image 2 等执行能力 | 完成单项图像处理或生成 | 判断商业流程，也不保存产品业务状态 |

硬结论：**ComfyUI 的 workflow 是“能力实现”，不是“业务流”。** 例如“商品图做同款”是业务流；其中的印花提取、反光清理、连续图、扩图和生产图适配，分别是可替换、可测试、可复用的中台能力。

## 2. 需求聚合结果

### A. 任意输入理解与起点选择

| 聚合的用户需求 | 业务端功能需求 | VL 应输出的事实 | 后续业务流 |
| --- | --- | --- | --- |
| 我上传了一张图，不知道怎么做 | 识别后推荐下一步，而不是让用户先选工具 | 图像类型、主体、文字、Logo、二维码、花纹可能性、清晰度、比例、生产风险、置信度 | 贴图 / 满版 / 同款 / 图片精修 / 多图设计 |
| 我上传了多张图 | 识别每张图的可能角色并提示用户确认 | 主设计、装饰、参考、Logo、文本源、二维码、重复/冲突图 | 拼贴 / 品牌模板 / 旅行故事杯 / 企业礼品 |
| 我没有图，但想做杯子 | 不能死路；给出创作起点 | 用户目标中的主题、受众、场景、是否有品牌约束 | 文字模板 / 灵感素材 / AI 生成草案 / Agent 可选入口 |
| 图片看不清、比例不对 | 解释问题并给可选修复路径 | 分辨率、主体安全区、可裁切性、适合延展或适合局部贴图的判断 | 超分 / 智能裁切 / 扩图 / 局部贴图 / 拼贴 |

| 聚合的用户需求 | 业务端功能需求 | 必须调用或候选的中台能力 |

### C. 电商“商品图做同款”

| 用户意图 | 业务端必须确认 | 能力链 | 生产边界 |
| --- | --- | --- | --- |
| 我拥有图案使用权，想尽量还原 | 权利确认、想提取的是花纹还是完整主体、目标产品 | VL 识别 -> 印花提取 -> 去反光/透视修正 -> 连续图或局部设计 -> 生产校验 | 保留原图、处理证据和最终生产图；不可静默改成“风格参考” |
| 我只想参考风格，做一款新的 | 参考范围、不得直接复制的确认、目标风格 | VL 风格/配色分析 -> Image 2 或图裂变生成候选 -> 用户选稿 -> 生产校验 | 输出必须作为新设计，不复刻来源中的文字、Logo 或受保护主体 |

### D. 从设计到履约

| 业务需求 | 业务端负责 | 中台负责 |
| --- | --- | --- |
| 进入设计篮 | 记录产品、设计面、数量、用户选择的方案 | 保存标准化设计稿、生产图、预览图和能力调用证据 |
| 下单支付 | 积分/金额、地址、支付状态、订单可见状态 | 不参与支付决策；仅提供必要资产和生产校验结果 |
| 运营确认并推蜂鸟 | 订单核对、人工确认、状态同步 | 供应链提交前的生产文件、效果图回传、OSS 保存、调用审计 |

## 3. VL 路由契约

### 3.1 VL 输出不是自由文本

每次进入产品设计前，业务端应拿到一份可校验的结构化 `design_intake`，至少包括：

```json
{
  "intent": "same_style_product | memorial_cup | full_wrap | photo_collage | brand_gift | no_image_start",
  "confidence": 0.0,
  "assets": [
    {
      "assetId": "...",
      "suggestedRole": "main_design | decoration | reference | logo | text_source | qr | extract_source",
      "facts": ["product_photo", "floral_pattern", "contains_text"],
      "quality": {"width": 0, "height": 0, "clarity": "low|medium|high"},
      "risks": ["copyright_confirmation_required", "subject_near_edge"]
    }
  ],
  "candidateFlows": [
    {"id": "same_style_extract", "reason": "...", "requiresConfirmation": true}
  ],
  "questions": ["..."],
  "recommendedProductionMode": "local_decal | full_wrap | two_way_seamless | four_way_seamless"
}
```

后端必须校验枚举、置信度阈值、产品可用设计面、图片尺寸、风险等级和积分预算。VL 只提出候选，不能授权最终调用。

### 3.2 自动继续与必须确认

| 情形 | 处理 |
| --- | --- |
| 低风险：已知花纹图、尺寸合格、用户已明确“满版” | 可直接进入预览级处理，但费用动作前仍展示消耗 |
| 中风险：图片比例不符、需要裁切/扩图、识别到多张图片角色冲突 | 展示 2-3 条可选路径，由用户选择 |
| 高风险：商品图做同款、可能有版权/IP/Logo、人物/二维码/文字、生产尺寸不合格 | 强制权利/用途确认与生产前确认，不能静默执行 |

| 语义精修与复杂参考图迁移 | Image 2，经中台 `image_edit` / KIE 受控接入 | 局部修改、文字/品牌元素重建、复杂多参考图编辑 | 待用真实样本验证；不得由业务端直连 |
| 生产校验与产品图适配 | 中台自有确定性能力 + 业务规格 | 固定像素尺寸、DPI、接缝、安全区、二维码、文字、设计面完整性 | 待把蜂鸟 Excel 尺寸规则和实际图片断言合并为可执行校验 |

### 4.1 生产图能力族：业务流可以不同，底层能力不重复造

| 原子能力 | 输入 | 输出 | 是否允许模型决定 | 适用业务流 |
| --- | --- | --- | --- | --- |
| `vl_design_intake` | 文本、0-N 张 OSS 素材、目标产品 | 素材事实、角色、风险、候选业务流、缺失信息、置信度 | 仅提出候选，不决定版权、工艺、价格或下单 | 全部入口 |
| `asset_quality_and_role_check` | 素材、目标设计面 | 清晰度、比例、安全区、Logo/人物/二维码/参考图角色 | 否，规则和 VL 共同给证据 | 全部有图入口 |
| `pattern_flatten` | 商品实拍或复杂背景图 | 可编辑平面花纹候选 | 是，生成候选；用户确认用途 | 商品图做同款、文旅纹样提取 |
| `artwork_variation` | 花纹/参考图、变化约束 | 新风格或同系列候选 | 是，生成候选 | 电商裂变、二次元/文旅风格化 |
| `periodic_candidate_generate` | 平面花纹、目标方向、提示词 | 二方/四方连续候选图 | 是，生成候选 | 满版杯、布料、壁纸、包装图案 |
| `seamless_production_normalize` | 已选候选图、方向 | 边缘像素证据、锁边后图、平铺预览 | **否**，纯确定性处理 | 所有需要连续生产的业务流 |
| `production_canvas_compose` | 已确认设计资产、蜂鸟设计面规格 | 精确像素画布、DPI、分面生产图 | 否，按模板数据执行 | 所有下单前设计 |
| `print_preflight` | 生产图、产品/工艺规则 | 接缝、尺寸、DPI、文字、二维码、安全区、颜色风险 | 否，规则引擎执行 | 进入设计篮、下单、蜂鸟推单 |
| `mockup_and_product_shot` | 生产图、产品模型或供应商效果图 | 用户预览/商品卡/订单核对图 | 可使用模型生成氛围图；生产图不受其影响 | 商品列表、设计篮、订单、灵感广场 |

原则：模型能力一律输出“候选资产”；只有 `production_canvas_compose` 与 `print_preflight` 可以把资产升级为生产图。业务端只选择和串联能力，不复制图像算法。

### 4.2 同一能力族在不同业务流中的组装

| 业务流 | 典型用户输入 | 组装方式 |
| --- | --- | --- |
| 商品图做同款 | 实拍杯/商品页截图 | `vl_design_intake` -> 权利确认 -> `pattern_flatten` -> `periodic_candidate_generate`（需要满版时）-> `seamless_production_normalize` -> `production_canvas_compose` -> `print_preflight` |
| 一张图做满版杯 | 插画、花纹、摄影图 | `vl_design_intake` -> `asset_quality_and_role_check` -> 平铺/延展/连续图选择 -> `periodic_candidate_generate`（仅需要时）-> 后续生产能力 |
| 照片纪念杯 | 人像、宠物、旧照片 | `vl_design_intake` -> 主体保护/修复/裁切 -> `production_canvas_compose` -> `print_preflight`；默认不进入连续图 |
| 多图故事杯 | 多张照片、地图、日期、装饰 | `vl_design_intake` -> 多图角色确认 -> 布局草案/多图融合 -> 用户编辑 -> 后续生产能力 |
| 企业礼品 | 无图或 Logo、名单、二维码 | `vl_design_intake` -> 补齐品牌资产与变量数据 -> 规则化排版 -> `production_canvas_compose` -> `print_preflight`；工艺与交期由蜂鸟模板约束 |
| 二次元/文旅主题 | 参考图、IP 图、文案或无图 | `vl_design_intake` -> 授权/参考用途确认 -> `artwork_variation` 或素材组合 -> 后续生产能力 |

## 6. 当前真实验证记录

### `same-style-wildflower-cup` 第一阶段：商品实拍 -> 印花提取

- 输入：AI创品自有公开杯子商品图，`1536×1024`。
- 用户目标：提取杯身橙黄色野花印花，后续用于环绕杯身生产图。
- 调用：`yinhua_tiqu`，158/5090/`117.50.80.158`。
- 输出：`1800×1800` PNG，耗时约 `112s`，ComfyUI prompt ID `ai-chuangpin-product-extract-dba33cb07759`。
- 人工检查：杯体、把手、吸管、背景和反光已被移除；花朵、枝叶与蜜蜂主体基本保留；输出为可继续编辑的平面图。
- 结论：**可作为“商品图做同款”的提取阶段候选能力，不可直接判定为生产图。** 原因是尚未验证边缘连续性、目标杯型尺寸、安全区和用户是否拥有该花纹的使用权。

### `same-style-wildflower-cup` 第二阶段：印花提取 -> 二方连续候选图

- 输入：上一阶段提取的 `1800×1800` 印花图；原始执行结果和候选图均已回存至 AI创品 OSS，隔离在 `capability-validation-20260711` 测试用户资产下。
- 调用：`sifang_lianxu`，233/4090/`117.50.216.233`，`pattern_type=two_way`，目标 `1800×1800`。
- 输出：`1800×1800` PNG，耗时约 `184s`，ComfyUI prompt ID `ai-chuangpin-two-way-seamless-3bc710a66f63`。
- 人工检查：生成结果保留了花纹主题，左右边缘存在可重复的花朵片段，但不能仅凭肉眼认定接缝合格。
- 像素检查：左右边缘 RGB 平均绝对差为 `14.71/255`，不满足 AI创品“生产连续图边缘像素必须完全一致”的标准。
- 结论：**可作为可编辑的连续图候选，不能进入生产或被标记为“无缝合格”。**

后续中台必须新增确定性的 `seamless_production_normalize` 能力：先由模型生成候选，再执行目标画布裁切/缩放、左右或四边边缘锁定、像素级边缘断言、平铺预览与人工/自动视觉复检。只有 `maxEdgeDiff=0` 且视觉接缝检查通过的输出才能成为生产图。不能把这项生产门禁交给生成模型自行保证。

### `same-style-wildflower-cup` 第三阶段：Flux2 8 步四方连续替代链路

- 调用：`flux2_9b_liebian_sifang`，固定执行于 158/5090/`117.50.80.158`。运行前队列为空，显存空闲约 `32GB / 34GB`，没有使用已移交且不稳定的 233/4090 执行面。
- 现有模型/节点：`flux-2-klein-9b-fp8.safetensors` + Qwen CLIP + Flux2 VAE，工作流已使用 `8` 步采样；无需新增模型或 ComfyUI 节点。
- 输出：`1024×1024` PNG，耗时约 `89s`，ComfyUI prompt ID `3314b8c1-071e-47af-bb48-e6f79cadbbdc`。视觉平铺能保持花朵、蜜蜂、白底和稀疏节奏，适合作为花纹候选生成器。
- 原始像素检查：左右边缘平均差约 `16.52/255`、最大差 `203`；上下边缘平均差约 `5.63/255`、最大差 `216`。因此生成图本身仍不合格。
- 确定性连续化验证：新增内部 `seamless_normalizer`，不增加模型或节点，只对候选图执行边界锁定与像素测量。对同一输出处理后，四边最大差均为 `0`，平铺预览未出现由锁边导致的新视觉变化。
- 结论：**替代链路可作为四方连续候选生成主路径，且应固定路由到 158/5090。** 生产路径必须追加 `seamless_production_normalize`、目标产品画布适配和平铺预览审核；不能把 Flux2 的结果直接发往生产。

### `same-style-wildflower-cup` 第四阶段：Flux2 8 步两方连续候选

- 调用：`flux2_9b_liebian_sifang`，输入明确“左右连续、适合圆柱杯身环绕、不要求上下连续”的提示词；实际执行节点为 `executor_comfyui_pattern_extract_158`（158/5090/`117.50.80.158`）。

- 锁边：调用 `podi_seamless_production_normalize` 且 `repeat_axis=horizontal`。左右边缘平均差 `26.125/255`、最大差 `175` 处理为 `0/0`；上下边缘保持约 `24.98/255`、最大差 `179`，符合两方连续只承诺横向接缝的定义。
- 结论：**两方候选链路可行，且 5090 空闲时速度正常。** 当前业务默认 `/api/business/seamless` 不能直接切到该候选能力，因为它仍接收用户指定 `width/height`，而 Flux2 候选固定输出 `1024×1024`。先补 `production_canvas_compose` 和 `print_preflight`，把用户规格落实到生产图后再发布业务版本；禁止为了切流而静默忽略目标尺寸。

### `same-style-wildflower-cup` 第零阶段：VL 真实调用前置检查

- 业务端现有产品设计 Agent 已对该样例给出“提取花纹并制作环绕图”的建议，但响应明确标注为本地规则分析，原因是业务服务没有配置直接火山视觉 Key。
- 随后从 47 服务器调用中台 `POST /api/admin/tests/volcengine/chat`，初次返回 `VOLCENGINE_API_KEY_MISSING`；这证明此前业务端并没有真实 VL 可用。
- 已将火山 Ark Key 仅录入中台 `api_keys` 受控 Key 池，标记为 `middle-platform-only`，并由 `executor_volcengine_default` 取用；业务端没有该 Key，也不通过环境变量直连厂商。
- 使用同一自有 OSS 商品图重新实测，模型 `doubao-seed-2-0-lite-260428` 正确返回：商品实拍类型、可生产判断、满版环绕建议、需要连续图、`0.9` 置信度、把手遮挡/曲面透视/底部压缩风险，以及“是否拥有原始源文件、后侧是否补全、是否调整比例”的待确认问题。
- 统一原子能力 `POST /api/abilities/vl_analyze_image/invoke` 也已用同一素材实测成功，耗时约 `27s`，产生可追溯调用日志。该调用证明了“业务 -> 中台能力 -> 受控 Key -> vendor-api-ops -> 商业 VL”的链路可用。
- 关键问题：通用 VL 输出曾把“用户声明拥有使用权”扩写为“无侵权风险、可自由商用”。这是模型越权，不是可信结论。业务层必须把权利状态固定为 `user_claimed / verified / unknown` 等后端字段；VL 最多标记“检测到 Logo/IP/人物/文字/二维码，需确认”，永远无权把素材放行。
- 结论：**真实 VL 路由可行，但当前只是管理端受控实测。** 业务端下一步必须调用中台的结构化 `vl_design_intake`，不能继续使用“看似 VL 的本地规则分析”。
- 上线门禁：以本样例把自由文本响应收敛为第 3 节 `design_intake` Schema，并补齐低置信度、结构不合法、视觉不可用和高风险素材时的退化与确认行为。

### `no-image-brand-gift`：无图企业伴手礼需求理解

- 输入：无图片；用户描述“公司五周年、80 个伴手礼杯、品牌蓝、Logo、姓名和可扫码二维码”。
- 调用：中台火山 VL 文本/规划调用，模型 `doubao-seed-2-0-lite-260428`，耗时约 `29s`。
- 输出：识别出企业批量礼品场景，要求收集 Logo 源文件、姓名清单和二维码源文件；提出杯型/容量、版面、交付期问题，并识别二维码清晰度、名单变更、标准色缺失的风险。
- 关键问题：模型同时擅自给出了材质和工艺建议。这些建议没有经过蜂鸟模板、工艺和可印刷面约束验证，不能直接显示为“可生产方案”。
- 结论：**无图入口可行，且必须作为独立业务流。** `vl_design_intake` 需要有文本模式，并仅返回候选流、缺失资产和待确认事项；产品、模板、工艺、价格、交期只能由业务规则与供应链数据补全。

## 7. 实施顺序

1. 在中台新增受控 `vl_design_intake` 原子能力：只接受 OSS 资产、用户目标和产品规格，输出第 3 节 Schema；由中台 Key 池调用商业 VL，不允许业务端持有厂商 Key。
2. 定义 `VL_UNAVAILABLE`、`VL_OUTPUT_INVALID`、`VL_LOW_CONFIDENCE`、`VL_RISK_CONFIRMATION_REQUIRED` 错误与退化行为。前三者只能引导用户手选工作流，不能伪造 VL 结果。
3. 新增 `seamless_production_normalize` 确定性能力和像素级验收。生成模型的输出一律先标为候选图。
4. 用上表六类样例验证已有 ComfyUI / Image 2 能力，形成“可上线、候选、淘汰”的证据表。
5. 将验证通过的能力组合为业务流模板，并补齐错误契约、成本、确认门和 OSS 资产关系。
6. 手动模式先上线通过验证的业务流；Agent 后续仅编排这些经过验证的能力和模板。
