# 01. 产品推导机制

最后更新：2026-06-02

## 1. 推导顺序

客户端需求不能从页面目录或模型能力倒推，必须按以下顺序推导：

```text
用户角色
  -> 真实生产任务
  -> 当前输入物
  -> 期望产出
  -> 判断标准
  -> 下一步动作
  -> 成本与风险
  -> 页面和接口需求
```

## 2. 每个功能必须回答的问题

新增或修改任何客户端功能前，必须回答：

| 问题 | 判断标准 |
| --- | --- |
| 用户是谁？ | 设计师、运营、交付、内部产品中的哪一类 |
| 用户此刻要完成什么？ | 必须能写成一个生产动作 |
| 用户已有输入是什么？ | 图片、图案、款式、文字、历史结果或空输入 |
| 用户期望输出是什么？ | 图案、候选图、产品图、视频、文本、交付包 |
| 用户如何判断好坏？ | 是否可用、是否可继续、是否可交付 |
| 用户下一步可能做什么？ | 继续创作、重做、保存、下载、导出、付费 |
| 需要展示哪些数据？ | 状态、runId、结果、消耗、余额、错误原因 |
| 哪些技术信息要隐藏？ | executor、workflow、LoRA、模型、内部 URL |

答不清这些问题，不进入开发。

## 3. 用户定位

第一阶段优先用户：

| 用户 | 需求 | 页面重点 |
| --- | --- | --- |
| 服装/印花设计师 | 从参考图提取图案、做改款、继续加工 | 素材输入、结果质量、继续创作 |
| 电商运营 | 生成营销素材、套图、主图、视频前置素材 | 高频动作、任务状态、下载和复用 |
| 内部交付/产品 | 验证业务能力是否能支撑真实客户流程 | runId、状态、失败原因、gap |

非第一阶段用户：

- 能力配置人员
- Workflow 工程师
- 模型调参人员
- 管理端运营人员

这些角色的入口在管理端或测评端，不放进客户端主路径。

## 4. 主动线

当前主线固定为：

```text
进入 Workbench
  -> 选一个生产动作
  -> 创建/打开工作单
  -> 上传或选择素材
  -> 填最少必要参数
  -> 查看预计消耗
  -> 提交
  -> 查看状态和 runId
  -> 查看结果
  -> 保存为资产
  -> 继续下一个能力 / 重做 / 导出草稿
```

页面不服务这条链路的内容，默认下沉或删除。

## 5. 页面一眼原则

每个页面首屏必须让用户一眼知道：

- 我在哪。
- 我现在能做什么。
- 我需要先提供什么。
- 结果会在哪里出现。
- 失败或余额不足时怎么办。

不允许首屏主要由概念解释、品牌叙事、指标装饰或大面积无动作视觉组成。

## 6. 文案原则

使用业务动作语言：

- 提取花纹
- 生成裂变候选
- 选择候选
- 继续生成产品图
- 打包交付
- 查看任务
- 保存资产

避免作为主文案出现：

- workflow
- executor
- LoRA
- vendor
- node
- atomic ability
- raw response

这些信息只允许出现在折叠调试区或 gap 证据里。
