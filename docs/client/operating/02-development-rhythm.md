# 02. 开发节奏机制

最后更新：2026-06-02

## 1. 每轮开发固定阶段

每轮客户端开发按 6 步走：

1. 需求推导：明确用户、任务、动线、页面和 API。
2. 范围收敛：确定本轮只做哪些页面、功能和状态。
3. 实现：代码、样式、数据结构、API 调用。
4. 自测：lint/build/单测/UI 测试/手动浏览器走查。
5. 交付：说明改了什么、验证了什么、风险是什么。
6. 记录：更新文档、gap、决策和下一轮任务。

## 2. 每轮开始前必须明确

| 项 | 必填内容 |
| --- | --- |
| 本轮目标 | 用一句话说明用户价值 |
| 用户动作 | 用户从哪里开始，到哪里结束 |
| 涉及页面 | 路由和页面职责 |
| 涉及 API | 只列业务 API 和媒体 API |
| 禁止触碰 | admin/eval/abilities/ComfyUI/vendor 等边界 |
| 验收标准 | 用户能完成什么动作 |
| 风险 | API 缺口、状态缺失、素材缺失、计费缺失 |

## 3. 第一阶段任务拆法

第一阶段不按“页面好不好看”拆任务，而按生产闭环拆：

| 任务包 | 目标 |
| --- | --- |
| T1 Workbench 骨架 | 用户能看到生产动作和最近工作单 |
| T2 工作单创建/打开 | 用户能建立一个后端证据容器，但不感知为项目管理 |
| T3 素材上传/登记 | 用户能提供源图，资产能挂到工作单 |
| T4 花纹提取闭环 | 提交、轮询、结果、runId、失败状态 |
| T5 结果资产化 | 成功结果进入资产，可从资产继续 |
| T6 裂变候选 | 从资产提交裂变，展示候选 |
| T7 候选选择 | 选择结果并写入 selection |
| T8 导出草稿 | 生成 export package 或记录 gap |

## 4. 每轮不做什么

除非另有明确决策，第一阶段不做：

- 营销首页
- 模板市场
- 团队空间
- 复杂项目管理
- 能力配置
- 模型选择
- executor/workflow/LoRA 暴露
- 复杂钱包页

## 5. 开发前沟通格式

我每轮开工前应给出：

```text
本轮我会处理：
- 用户目标：
- 页面范围：
- API 范围：
- 预期交付：
- 验收方式：
```

如果用户已授权“直接推进”，则只做简短说明，不反复询问。

## 6. 开发后汇报格式

每轮完成后按 `06-delivery-report-template.md` 汇报，必须包含：

- 本轮用户价值
- 已实现页面/功能
- API 调用范围
- 测试结果
- 浏览器走查结果
- gap 和风险
- 下一轮建议
