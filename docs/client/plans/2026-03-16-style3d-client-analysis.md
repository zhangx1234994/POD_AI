# Style3D 客户端对标分析（2026-03-16）

> 目标：参考 [Style3D AI](https://www.style3d.ai/?lang=zh-CN&refer=guanwang) 做一个“面向业务用户的客户端”，底层复用我们现有中台能力。
> 范围：先不做“3D 精准设计”，其余模块按“能直接复用 / 可组合实现 / 需要新增能力”三层来拆。
> 调研方式：浏览公开页面与功能页，重点查看 `/aiassistant/index`、`/innostyle/*`、`/stylenext/*`、`/ai-tools/*`。
>
> 文档状态：历史基线。
> 用途是保留第一轮竞品拆解结论，不代表当前客户端仍逐条按本文执行。
> 现行方向请优先看：
> - `docs/client/plans/2026-03-17-style3d-client-current-status.md`
> - `docs/plans/2026-03-19-style3d-client-rearchitecture-design.md`

## 1. 对标网站现在的产品骨架

Style3D 的前台不是简单的“功能列表”，而是一个很清楚的 4 层结构：

1. **工作室**
   - 首页就是一个“智能创作入口”。
   - 有智能体卡片、输入框、快捷任务、白板创作入口、我的白板。
   - 本质上是“总入口 + 最近工作台 + 智能助手”。
2. **AI 研发设计**
   - 偏“设计师生产工具”。
   - 以文生款、以款生款、局部改款、图案提取这类都在这里。
3. **AI 视觉商拍**
   - 偏“电商图、上身图、营销图、视频图”。
   - 更接近商家和运营同学的高频需求。
4. **AI 工具箱**
   - 偏通用图像处理。
   - 超清、消除、抠图、扩图、转矢量、调色。

它的页面风格也比较统一：

- 顶部是固定导航，用户始终知道自己在哪一类工作。
- 每个功能页基本都是 **左边功能列表 + 中间参数表单 + 右边效果案例/预览**。
- 页面不是“技术面板”，而是“业务动作”：比如“换模特背景”“图案提取”“服装上身”。
- 很强调“模板化”和“案例驱动”，用户不需要理解底层模型。

这点非常适合我们现在的方向：**中台保留技术复杂度，客户端只暴露业务动作。**

## 2. 我们建议的新客户端信息架构

建议新项目直接按下面的结构做，不要沿用评测端/管理端的技术风格：

### 2.1 顶部一级导航

- 工作室
- AI 研发设计
- AI 视觉商拍
- AI 工具箱
- 我的项目
- 任务中心

### 2.2 共用底座

所有模块都共用这几个底层能力：

- 统一登录
- OSS 文件上传
- 统一任务中心（同步结果 + 异步结果）
- 素材库 / 最近使用
- 模板库 / 提示词预设
- 能力调用日志
- 点数或套餐展示位

### 2.3 客户端和中台的关系

前台不要直接暴露“工作流”“执行节点”“LoRA”“评测分类”这些内部概念，而是转成业务词：

- 工作流 -> 功能动作
- Ability / Workflow -> 工具能力
- LoRA -> 风格模板 / 图案模板 / 高级选项
- Executor -> 系统自动分配
- Eval workflow -> 内部回归链路，不暴露给客户

## 3. 功能对照：哪些我们已经有，哪些能拼出来，哪些还缺

下面按 Style3D 的三个主要业务模块拆。

### 3.1 AI 研发设计

| 对标功能 | 业务含义 | 我们现在的实现判断 | 说明 |
| --- | --- | --- | --- |
| 以文生款 | 输入文字生成服装效果图/款式图 | **可组合实现** | 可用多模型生图 + Seedream/KIE 图生图链路，前台再加“款式图/模特图/比例/透明底”封装。 |
| 以款生款 | 输入参考款图，生成新款 | **已具备主能力** | 我们已有 KIE Nano Banana / Flux2 图生图，也有多模型生图工作流。 |
| 线稿成款 | 线稿变成成衣效果图 | **可组合实现** | 可走图生图，但需要单独做“线稿模式”提示词模板和输入限制。 |
| 款生线稿 | 款图转线稿 | **缺关键能力** | 现在没有稳定的线稿抽取/矢量线稿工作流。 |
| 融合创款 | 多参考图融合生成新款 | **已具备主能力** | 已有 `ComfyUI · 多图融合`，再加提示词模板即可。 |
| 局部改款 | 局部重绘/局部编辑 | **可组合实现** | 有图生图基础，但还缺面向业务用户的遮罩编辑器和“局部改款”专用前台。 |
| 服装配色 | 同款换色 | **可组合实现** | 可先用图像编辑模型 + 固定提示词做 MVP，但还不是独立标准能力。 |
| AI 图案 | 文生图案/透明底图案 | **可组合实现** | 可用文生图模型生成方形图案，再配透明背景/平铺模板。 |
| 图案融合 | 多图案混合新图案 | **已具备主能力** | `ComfyUI · 多图融合` 可直接复用。 |
| 图案提取 | 从实物图提取花纹/印花 | **已具备** | `ComfyUI · 印花提取` 已经是我们的强项。 |
| 图案配色 | 图案换色 | **可组合实现** | 技术上可做，但需要专门产品化。 |
| AI 图案工艺 | 图案+工艺效果表达 | **缺关键能力** | 这不是单一模型能力，更像“图案生成 + 工艺模板 + 材质渲染”组合链路。 |

**结论：**

- “AI 研发设计”这条线，我们已经有比较好的底子。
- 最适合优先落地。
- 真正缺的不是底层调用，而是 **前台产品封装、参数模板、局部编辑体验、线稿链路**。

### 3.2 AI 视觉商拍

| 对标功能 | 业务含义 | 我们现在的实现判断 | 说明 |
| --- | --- | --- | --- |
| 服装上身 | 平铺服装/单品换到真人模特上 | **缺关键能力** | 这是典型 try-on 能力，我们当前没有成熟服装上身工作流。 |
| 换模特背景 | 换模特、换背景或同时更换 | **可组合实现** | 可先走图像编辑链路做 MVP，但要做人像保护、边缘处理、场景模板。 |
| 换姿势 | 保留服装和人物，换姿态 | **缺关键能力** | 需要姿态控制或专门人像编辑模型。 |
| 服装精修 | 去瑕疵、增强细节、优化展示图 | **可组合实现** | 现有超清、局部编辑、去噪、增强可拼出一版。 |
| 鞋子上身 | 鞋类上脚 | **缺关键能力** | 需要专门鞋类 try-on。 |
| 包包上身 | 包类上身 | **缺关键能力** | 需要专门包类 try-on。 |
| 帽子上身 | 帽类上身 | **缺关键能力** | 需要头部配饰 try-on。 |
| 裂变套图 | 一张图快速出多套营销图 | **已具备主能力** | 我们已有图裂变、多模型生图、多图融合，可做运营批量图。 |
| 服装转平铺 | 真人图转平铺 | **缺关键能力** | 需要服装几何还原或行业专用模型。 |
| 平铺转 3D | 平铺图转 3D 展示 | **暂不纳入当前版本** | 和 3D 方向强相关，建议跟“3D 精准设计”一起再做。 |
| 服装细节图 | 从主图生成领口/袖口/面料细节图 | **可组合实现** | 可通过裁切策略 + 超清增强 + 模板出图完成。 |
| 图案上身 | 把图案挂到服装上 | **可组合实现** | 需要图案提取/生成 + 上身/贴图合成链路。前提还是要有 try-on 或 mockup 工作流。 |
| 面料上身 | 面料纹理上身 | **可组合实现** | 和图案上身类似，更偏材质替换。 |
| 图生视频 | 静态图生成视频 | **已具备主能力** | 我们已有 KIE/火山的视频模型。 |
| 窗帘试挂 | 家居场景挂样 | **缺关键能力** | 本质上是行业专用的场景试挂/替换。 |

**结论：**

- “AI 视觉商拍”里，**裂变套图、图生视频、细节图、基础精修** 我们比较容易先做出来。
- 真正难的是 **服装上身 / 鞋包帽上身 / 换姿势 / 转平铺**，这些不是简单提示词能补出来的。
- 所以商拍线建议分两层：
  - 第一层：先上“营销图生成能力”
  - 第二层：再补“行业专用上身能力”

### 3.3 AI 工具箱

| 对标功能 | 业务含义 | 我们现在的实现判断 | 说明 |
| --- | --- | --- | --- |
| AI 超清 | 提升清晰度 | **已具备** | 百度无损放大、8K 放大、PODI 高质量缩放都能支撑。 |
| AI 消除 | 去水印/去杂物/局部擦除 | **可组合实现** | 需要补一套显式“涂抹消除/选区消除”前台和后端能力封装。 |
| 智能抠图 | 去背景/主体分离 | **缺关键能力** | 目前没有标准化前台产品能力。 |
| 无损放大 | 放大且尽量不糊 | **已具备** | 现有能力可直接复用。 |
| 转矢量图 | 位图转 SVG / 可编辑线稿 | **缺关键能力** | 目前没有成熟实现。 |
| 调色 | 换色 / 统一风格色调 | **可组合实现** | 可做轻量版，但要补产品壳。 |
| AI 扩图 | 向外延展补全图像 | **已具备主能力** | 我们已有扩图工作流、扩边占位图、ComfyUI 花纹扩图。 |

**结论：**

- AI 工具箱是我们最容易快速上线的一条线。
- 里面已经有不少现成能力可以直接包装成客户可用产品。

## 4. 结合我们现有中台，建议怎么落地

### 4.1 第一批直接可做成客户端功能

这批功能不需要等新的模型体系，可以直接产品化：

- AI 超清
- 无损放大
- AI 扩图
- 图案提取
- 四方连续 / 两方连续
- 多图融合
- 图裂变套图
- 图生视频
- 高质量缩放 / DPI 处理
- 多模型生图（包装成“以文生款 / 以款生款”的一部分）

### 4.2 第二批适合“提示词 + 现有模型能力”包装上线

这批能做，但要靠产品封装和模板来提体验：

- 线稿成款
- 局部改款
- 服装配色
- 图案配色
- AI 图案
- 换模特背景
- 服装精修
- 服装细节图

这一类要重点做三件事：

1. 固定模板
2. 场景化提示词
3. 极简参数表单

也就是说，不要让客户直接填一大段技术参数，而是给出：

- 风格模板
- 类目模板
- 输出方向
- 高级选项折叠

### 4.3 第三批必须新增专用能力

这批不能只靠前台包装：

- 服装上身
- 鞋子上身
- 包包上身
- 帽子上身
- 换姿势
- 服装转平铺
- 款生线稿
- 转矢量图
- 窗帘试挂
- AI 图案工艺

这些需要我们后面单独立项做“行业专用工作流”。

## 6. 产品体验上要学 Style3D 的地方

不是只学它“有哪些按钮”，而是学它的产品组织方式：

### 6.1 不暴露技术名词

客户看到的是：

- “换背景”
- “提取图案”
- “生成细节图”

不是：

- “ComfyUI workflow”
- “KIE”
- “LoRA”
- “回调任务”

### 6.2 每个功能都要有“示例”

Style3D 很重视“生成前 / 生成后”和“精选案例”。

我们客户端也必须有：

- 参考案例
- 一键套用
- 参数模板
- 最近成功结果

### 6.3 要有工作台，不要只有工具页

Style3D 的“工作室”很重要，它让人感觉这是个平台，不是零散工具箱。

所以我们前台必须有一个“工作室首页”，至少要放：

- 推荐功能
- 最近任务
- 最近素材
- 快捷入口
- 常用模板

### 6.4 要把“任务感知”做得更自然

我们的中台已经是异步能力为主，所以客户端要天然支持：

- 提交中
- 排队中
- 运行中
- 成功
- 失败
- 结果回填

不能再让业务用户理解“回调 task id”这类内部词。

## 7. 对我们现阶段最现实的结论

一句话总结：

**如果现在马上做客户端，我们最应该先复制的是 Style3D 的“产品结构和交互方式”，而不是硬追它所有算法能力。**

更具体一点：

- 我们已经有一批能打的能力，尤其是图案提取、四方连续、扩图、融合、生图、裂变、视频。
- 我们短板主要在“服装上身类”和“行业专用几何变换类”。
- 所以正确打法不是一口气把全部功能做齐，而是：
  - 先把已经能跑的能力做成一个漂亮、顺手、业务化的客户端
  - 再逐个补难能力

## 9. 第一期开发表（按页面拆）

为了避免一上来做成“又一个管理端”，第一期页面建议直接按业务页面拆：

### 9.1 工作室首页

**页面目标：** 做成平台入口，而不是技术首页。

**页面模块：**

- 顶部欢迎区
- 智能体入口卡片
- 快捷功能入口
- 最近任务
- 最近素材
- 我的项目
- 常用模板

**依赖后端：**

- 登录态接口
- 最近任务接口
- 我的素材接口
- 模板接口（可先本地静态）

### 9.2 AI 研发设计页

**第一期先放这些卡片：**

- 以文生款
- 以款生款
- 融合创款
- 图案提取
- 图案融合
- 四方连续

**交互结构：**

- 左：功能菜单
- 中：参数区
- 右：案例区 / 结果区

**后端对接：**

- `GET /api/abilities`
- `POST /api/abilities/{abilityId}/invoke`
- `POST /api/ability-tasks`
- `GET /api/ability-tasks/{id}`

### 9.3 AI 工具箱页

**第一期先放：**

- AI 超清
- 无损放大
- AI 扩图
- 高质量缩放
- DPI 处理

**这一页可以先做成最快落地模块**，因为它最像标准图片处理工具。

### 9.4 任务中心页

**必须独立做。**

因为我们的能力很多是异步任务，如果没有任务中心，用户会觉得“点了没反应”。

**建议字段：**

- 任务名称
- 来源页面
- 提交时间
- 当前状态
- 结果预览
- 失败原因
- 再来一次

### 9.5 我的素材页

这是业务用户长期使用的关键，不然后面所有功能都像临时工具。

**建议至少支持：**

- 原图
- 结果图
- 视频
- 收藏
- 下载
- 再次创作

## 10. 第一批接口适配建议

前台如果直接裸调现在所有内部接口，会很乱。
建议加一层“客户端聚合接口”，专门给新客户端用。

### 10.1 建议新增的客户端接口层

- `GET /api/client/home`
  - 返回工作室首页数据：快捷入口、最近任务、模板、素材
- `GET /api/client/tool-catalog`
  - 返回前台可展示的功能目录，不返回执行节点等内部字段
- `POST /api/client/jobs`
  - 统一提交任务，前台不区分同步/异步
- `GET /api/client/jobs/{id}`
  - 统一查任务
- `GET /api/client/assets`
  - 查询我的素材
- `POST /api/client/assets/{id}/rerun`
  - 基于历史结果再次创作

### 10.2 为什么要加这一层

因为客户端不应该感知这些中台细节：

- 是 Ability 还是 Workflow
- 是同步还是异步
- 是 KIE 还是 ComfyUI
- 走哪个执行节点
- LoRA 是怎么绑定的

这些都应该被客户端接口层吃掉。

## 11. 对研发排期最有帮助的边界建议

为了让这次客户端项目不失控，我建议把第一期边界卡死为：

### 第一期开做

- 工作室首页
- AI 研发设计（6 个功能）
- AI 工具箱（5 个功能）
- 任务中心
- 我的素材
- 统一上传和结果回填

### 第一期开不做

- 服装上身
- 鞋包帽上身
- 换姿势
- 窗帘试挂
- 平铺转 3D
- 款生线稿
- 转矢量图
- AI 图案工艺

这样第一期就会是一个**能上线、能卖、能跑业务**的版本，而不是一个功能名单很大但实际不稳定的版本。
