# 新客户端页面交互说明（2026-03-16）

> 目标：把新客户端做成真正可落地的“交互方案”，而不是只停留在功能列表。
> 设计基准：**整体 UI、页面组织、交互节奏全面参考 Style3D。**
> 本文重点：页面级交互、用户路径、状态变化、积分与充值链路、异常处理。
>
> 文档状态：历史交互基线。
> 本文用于保留第一轮交互设计思路，不代表当前页面细节仍严格按原文呈现。

---

## 1. 交互总原则

客户端所有页面都要遵守 6 条原则：

1. **用户始终知道自己在哪个模块**
2. **用户始终知道下一步该做什么**
3. **用户始终知道当前任务是否在处理**
4. **用户始终知道结果去了哪里**
5. **用户始终知道当前积分还够不够**
6. **失败后用户有明确回路，不会卡死**

这 6 条是整个平台交互体验的底层要求。

---

## 2. 全局布局交互

## 2.1 顶部导航

顶栏建议固定，不随页面切换消失。

### 顶栏左侧

- Logo
- 一级导航：
  - 工作室
  - AI研发设计
  - AI视觉商拍
  - AI工具箱
  - 任务中心
  - 我的素材

### 顶栏右侧

- 搜索入口（后期）
- 当前积分
- 充值按钮
- 消息/活动提示
- 用户头像

### 顶栏交互规则

- 当前模块要有明显高亮
- 积分始终可见
- 充值入口始终一跳可达
- 从任意页面跳任务中心和素材库都不能丢上下文

---

## 2.2 左中右三栏布局

凡是“能力页”，统一采用三栏模型。

### 左栏

作用：切换功能，不离开当前模块。

### 中栏

作用：上传、输入、提交。

### 右栏

作用：看案例、看结果、做下一步动作。

### 为什么必须这么做

因为 Style3D 的体验本质上不是“单页表单”，而是：

- 左侧给选择感
- 中间给操作感
- 右侧给结果感

如果缺一边，页面就会很空、很技术、很难用。

## 3. 首页交互说明

## 3.1 首页目标

首页必须同时服务 3 类人：

- 第一次来的新用户
- 已经会用的老用户
- 只想快速继续上次工作的用户

所以首页不是静态展示页，而是“工作室首页”。

## 3.2 首页模块顺序

建议从上到下是：

1. 欢迎区 / Hero
2. 快捷开始
3. 智能体 / 功能入口卡片
4. 推荐能力
5. 最近任务
6. 最近素材
7. 模板推荐
8. 充值/活动提示

## 3.3 首页主要交互

### 路径 A：新用户

```text
进入首页
  -> 看推荐功能
  -> 点一个入口卡片
  -> 进入对应功能页
```

### 路径 B：老用户

```text
进入首页
  -> 看最近任务
  -> 点开某条历史结果
  -> 下载 / 再次创作
```

### 路径 C：高频用户

```text
进入首页
  -> 直接上传图片
  -> 选择推荐功能
  -> 进入功能页并带入素材
```

## 3.4 首页交互细节

- Hero 区要有明显 CTA，比如“上传图片开始创作”
- 最近任务和最近素材都要是可点击卡片
- 功能卡片点击后，最好带默认模板进入下一页
- 余额不足时，首页右上角和活动区都要能去充值

## 4. AI 研发设计页交互说明

## 4.1 页面目标

这页的目标不是让用户研究参数，而是让他快速出设计图。

## 4.2 左栏交互

左栏展示：

- 以文生款
- 以款生款
- 融合创款
- 图案提取
- 图案融合
- 四方连续

### 左栏规则

- 当前功能高亮
- 点击切换功能时保留当前模块，不回首页
- 如果当前表单已填写但未提交，切换时给出轻提示

## 4.3 中栏交互

中栏每个功能通用结构：

1. 标题和说明
2. 输入区
3. 参数区
4. 高级参数区
5. 提交区

### 输入区交互

支持：

- 上传本地图片
- 粘贴图片
- 从素材库选图
- 从最近结果选图

### 参数区交互

默认只展示基础参数：

- 提示词
- 风格模板
- 输出方向
- 比例

高级参数折叠：

- 模型细节
- LoRA 对应的业务化名称
- 更细的尺寸和模式

**注意：**

- 不要直接给用户看 `workflow_key`
- 不要直接给用户看 `executor`
- 不要直接给用户看 `api_type`

## 4.4 右栏交互

右栏从上到下建议是：

1. 示例案例
2. 当前结果
3. 最近结果

### 示例案例

- 展示 4~8 张精选图
- 每张图都有“做同款”
- 点击后把提示词/模板自动带入中栏

### 当前结果

任务成功后，右栏顶部直接切到结果卡片：

- 大图预览
- 下载
- 保存素材
- 再来一次
- 继续创作

### 最近结果

便于用户不离开页面就回看刚刚做过的东西。

## 4.5 提交按钮交互

按钮文案不要都叫“提交”。

建议按场景：

- 开始生成
- 开始提取
- 开始融合
- 开始连续化

点击后状态演进：

```text
可点击
  -> 提交中
  -> 排队中 / 处理中
  -> 成功 / 失败
```

## 5. AI 工具箱页交互说明

## 5.1 页面目标

工具箱页强调的是“效率感”和“结果确定性”。

## 5.2 页面结构

左栏：

- AI超清
- 无损放大
- AI扩图
- 高质量缩放
- DPI处理

中栏：

- 上传
- 参数
- 开始处理

右栏：

- 前后对比
- 当前结果
- 历史结果

## 5.3 交互重点

### 前后对比要明显

因为这类工具用户最在意“到底变好了没有”，所以右栏必须有前后对比视觉。

### 参数要少

这页不要做成复杂控制台。

比如：

- 超清：只保留清晰度/倍率的必要参数
- 缩放：只保留宽高或倍数
- DPI：只保留目标 DPI

### 结果动作要快

结果出来后最常见动作只有 3 个：

- 下载
- 继续加工
- 重新处理

## 6. AI 视觉商拍页交互说明

一期虽然不做完整“上身体系”，但结构必须先搭好。

## 6.1 一期建议先上的页面

- 裂变套图
- 图生视频
- 细节增强

## 6.2 交互原则

这页比研发设计更偏营销产出，所以更强调：

- 批量感
- 套图感
- 结果可直接下载交付

### 裂变套图

用户路径：

```text
上传主图
  -> 选风格模板
  -> 选输出数量
  -> 提交
  -> 获得一组结果
  -> 批量下载 / 收藏 / 继续筛选
```

### 图生视频

用户路径：

```text
上传图片
  -> 输入或选择提示词模板
  -> 提交视频生成
  -> 进入任务状态
  -> 完成后可预览视频
  -> 下载视频 / 再次生成
```

## 7. 任务中心交互说明

## 7.1 页面目标

任务中心必须像“办事大厅”，而不是“后台日志”。

## 7.2 页面结构

建议上方是筛选区，下方是列表区。

### 筛选区

- 全部
- 排队中
- 处理中
- 已完成
- 失败

可选补充：

- 按功能筛选
- 按时间筛选

### 列表区每项展示

- 缩略图
- 功能名称
- 提交时间
- 状态
- 简短结果说明
- 操作按钮

## 7.3 每条任务的操作

成功任务：

- 查看结果
- 下载
- 再来一次
- 去素材库查看

失败任务：

- 查看原因
- 重新提交
- 修改参数后重试

处理中任务：

- 查看进度
- 返回原页面

## 7.4 任务详情交互

建议用右侧抽屉或详情页。

展示：

- 提交内容摘要
- 当前状态
- 时间轴
- 输出结果
- 错误原因
- 再次创作

## 8. 我的素材页交互说明

## 8.1 页面目标

我的素材页的核心目标不是“存图”，而是“让图继续产生价值”。

## 8.2 页面结构

上方筛选：

- 全部
- 原图
- 结果图
- 视频
- 收藏

卡片内容：

- 缩略图
- 来源功能
- 创建时间
- 标签
- 操作按钮

## 8.3 卡片操作

每张素材卡都建议支持：

- 预览
- 下载
- 收藏
- 查看来源任务
- 用它继续创作

## 8.4 “继续创作”交互

这是素材页最重要的交互。

点击后应弹出一个快捷面板，推荐下一步能做什么：

- 用它扩图
- 用它超清
- 用它做视频
- 用它做图案提取
- 用它做融合

这样素材页就不是死仓库，而是创作分发中心。

## 9. 积分与充值中心交互说明

## 9.1 顶栏积分交互

顶栏建议长期展示一个积分胶囊：

- 当前余额数字
- 一个积分图标
- 点击展开小面板

点击后小面板展示：

- 当前可用积分
- 冻结中积分
- 最近 3 条消费
- 去充值按钮
- 去账单按钮

这能保证用户在任何页面都能快速感知账户状态。

## 9.2 钱包页结构

建议从上到下：

1. 余额总览卡
2. 套餐 / 点数包区
3. 活动赠送区
4. 最近充值记录
5. 最近消费账单
6. 使用统计图

## 9.3 套餐区交互

每个套餐卡建议展示：

- 点数数量
- 价格
- 推荐标签
- 适合场景
- 立即充值按钮

点击“立即充值”后：

```text
创建充值单
  -> 跳支付或等待回调
  -> 成功后刷新余额
  -> 返回原页面可继续操作
```

## 9.4 积分不足拦截交互

这是整个平台很关键的交互。

当用户点击“开始生成”时，如果余额不足：

### 不应该发生的情况

- 直接失败
- 清空表单
- 让用户重新填写

### 正确交互

```text
点击开始生成
  -> 校验余额不足
  -> 弹出积分不足弹窗
  -> 展示当前余额 / 本次预计消耗 / 推荐充值套餐
  -> 点击充值
  -> 充值成功后回到原页面
  -> 保留原表单内容
  -> 用户一键继续提交
```

这是必须做好的。

## 9.5 消费账单交互

账单页不要做成财务系统，而要做成业务可读：

- 时间
- 功能名称
- 消耗积分
- 对应任务
- 结果入口

让用户知道“这笔钱花在哪张图上了”。

## 10. 登录与首次进入交互

## 10.1 登录后落点

建议登录成功默认落到工作室首页。

不要直接进某个工具页。

## 10.2 首次进入的新用户

第一次进入建议有一个轻引导：

- 推荐先试什么
- 怎么上传
- 怎么看任务
- 怎么看积分

不要做太重的新手教程，用 3~4 个轻提示足够。

---

## 11. 状态与反馈交互

## 11.1 上传状态

上传组件要有明确 4 态：

- 等待上传
- 上传中
- 上传成功
- 上传失败

## 11.2 任务状态

统一 4 态：

- 排队中
- 处理中
- 已完成
- 失败

## 11.3 页面反馈

建议统一用 3 层反馈：

### 轻反馈

- 按钮 loading
- 小气泡提示

### 中反馈

- 结果区状态条
- 任务卡状态条

### 重反馈

- 全局弹窗
- 积分不足弹窗
- 任务失败说明弹窗

---

## 12. 页面之间的跳转关系

## 12.1 推荐跳转链

```text
首页
  -> 功能页
  -> 提交任务
  -> 查看结果
  -> 存入素材
  -> 从素材继续创作
```

## 12.2 任务回流链

```text
任务中心
  -> 查看任务详情
  -> 查看结果
  -> 再来一次
  -> 返回功能页
```

## 12.3 充值回流链

```text
功能页提交
  -> 积分不足
  -> 去充值
  -> 充值成功
  -> 返回原功能页
  -> 保留原参数继续提交
```

## 13. 异常场景交互

## 13.1 上传失败

提示：

- 图片上传失败，请重试

可选动作：

- 重新上传
- 更换图片

## 13.2 任务排队过久

提示：

- 当前任务较多，正在排队处理中

可选动作：

- 去任务中心查看
- 稍后回来

## 13.3 任务失败

提示：

- 本次生成失败，请调整参数后重试

可选动作：

- 查看原因
- 再试一次
- 返回编辑

## 13.4 充值未成功

提示：

- 充值未完成，请稍后刷新或重新发起

可选动作：

- 刷新状态
- 重新充值

---

## 14. 第一版最应该优先打磨的交互点

如果要选最关键的 5 个交互点，我建议优先把这几个做到位：

1. 首页的快捷开始
2. 功能页的三栏结构
3. 任务中心的状态反馈
4. 素材页的“继续创作”
5. 积分不足后的充值回流

只要这 5 个点做好，整个平台就会很像一个成熟产品，而不是一堆页面。
