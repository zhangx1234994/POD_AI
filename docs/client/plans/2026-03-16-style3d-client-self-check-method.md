# 客户端自查与纠错方法（2026-03-16）

> 目的：形成客户端自己的“查 - 测 - 改 - 复测 - 记文档”闭环，不靠临时感觉推进。  
> 原则：每做完一轮，都必须留下可复用的方法和记录。
> 文档状态：可复用方法文档。
> 方法论仍有效，但其中提到的具体页面、结构和阶段背景需要结合当前版本理解。

## 1. 基本闭环

客户端后续统一按下面的顺序推进：

1. **查**
   - 看当前页面结构
   - 看文档边界
   - 看是否有明显缺项
2. **测**
   - 本地页面走查
   - 自动化 smoke
   - 手工关键链路测试
3. **改**
   - 修页面问题
   - 修状态流问题
   - 修测试问题
4. **复测**
   - `lint`
   - `build`
   - `test:ui`
5. **记**
   - 更新核查表
   - 更新测试清单
   - 更新版本边界文档

---

## 2. 当前客户端自查分层

### A. 结构层

看这些：

- 三端边界是否清楚
- 客户端文档是否独立
- 页面入口是否完整
- 功能是否漏页

### B. 链路层

看这些：

- 登录是否通
- 上传是否通
- 提交是否通
- 任务是否回
- 素材是否沉淀
- 钱包是否可读

### C. 体验层

看这些：

- 首页是否像产品首页
- 模块页是否像业务工具页
- 钱包页是否像正式账户页
- 不是后台感

### D. 自动化层

看这些：

- `npm run lint`
- `npm run build`
- `npm run test:ui`

---

## 3. 当前约定

### 什么时候算“可继续推进”

- lint 通过
- build 通过
- smoke 通过
- 文档更新了

### 什么时候不允许直接进入 git 提交

- 大面积功能未测
- 明显报错未修
- 文档没有同步
- 版本边界不清楚

---

## 4. 当前自动化最小闭环

当前客户端已具备这套最小自动化自查：

- `npm run lint`
- `npm run build`
- `npm run test:ui`
- `npm run selfcheck:local`
- `npm run selftest:remote`
- `npm run selfcheck:full`

其中 `test:ui` 当前覆盖：

- 首页
- 研发设计页
- 钱包页
- 任务中心
- 素材库
- 工具箱页
- 商拍页
- 项目详情页
