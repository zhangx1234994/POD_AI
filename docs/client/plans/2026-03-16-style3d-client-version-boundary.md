# 客户端当前版本边界说明（2026-03-16）

> 用途：明确“这一版到底做到哪一步了”，避免把“第一版复用链路”误认为“最终成熟版”。
> 这份文档用于开发、测试、部署前统一口径。
> 文档状态：历史边界说明。
> 这份边界判断对应第一轮客户端阶段，不等于当前最新边界。

## 1. 当前版本定位

当前客户端版本不是空原型，也不是最终商业发布版。
更准确的定位是：

- **一个已经具备完整产品骨架的客户端 alpha 版本**
- **非 3D 对标内容基本补齐**
- **第一批核心能力已经接通真实链路**
- **大量剩余功能已接入第一版复用链路**

也就是说，它已经能用来做系统性测试，但还不应被当成“最终成品”。

## 3. 当前版本“不应误判为完成”的部分

### 3.1 第一版复用链路

客户端里有不少功能虽然已经能提交、能返回结果，但本质上是：

- 先复用通用图生图能力
- 或复用通用图像编辑能力
- 或复用文生图能力

这类功能当前可以测：

- 页面完整
- 参数完整
- 提交可用
- 结果可回
- 闭环可走

但不应直接按“最终专用行业效果”做质量验收。

### 3.2 素材库仍是前端本地沉淀

当前素材库已经能形成前台闭环，但仍然是：

- 前端本地沉淀优先
- 还不是完整后端资产中心

### 3.3 充值链路不等于完整支付闭环

当前已经有：

- 充值单创建
- 状态刷新
- 回原页面继续提交

但还没有完整支付网关/支付回调的最终联调闭环。

---

## 4. 当前版本适合做什么

### 适合

- 系统性页面走查
- 功能入口全覆盖检查
- 提交链路检查
- 状态流转检查
- 任务中心与素材中心闭环检查
- 钱包与积分前台体验检查

### 不适合

- 直接当作最终发布版上线
- 直接按最终商业质量做全部效果验收
- 跳过测试直接部署

---

## 5. 当前版本测试目标

这版测试最主要要确认的是：

1. 页面是否完整
2. 入口是否不漏
3. 提交是否通
4. 状态是否回
5. 结果是否沉淀
6. 钱包与积分是否能形成前台闭环

只有这些跑顺了，才有资格进入下一步：

- 修 bug
- 收口版本
- 再考虑 git 提交和部署

---

## 6. 与后续版本的关系

### 当前版本

- 覆盖面优先
- 前台完整优先
- 闭环跑通优先

### 后续版本

- 专用行业链路替换第一版复用链路
- 后端资产中心替换前端本地素材沉淀
- 更细的视觉和交互打磨
- 更完整的商业支付闭环
