# 客户端可集中测试边界说明

> 用途：正式开始集中测试前，明确当前版本“可以测什么、不建议按什么标准测什么”。
> 结论先说：**当前版本已经可以进入集中测试阶段。**
>
> 文档状态：阶段测试包文档。
> 上面的“可以进入集中测试阶段”是 2026-03-17 这轮测试包的结论，不代表当前仍默认开放正式集中测试。
> 如果当前仍在持续重构，请先看：
> - `docs/client/plans/2026-03-17-style3d-client-current-status.md`
> - `docs/plans/2026-03-19-style3d-client-rearchitecture-design.md`

## 1. 当前版本可以集中测试的部分

### 门面与导航

- 首页
- 工作台
- 顶部搜索
- 顶部导航
- 白板 / 项目入口

### 核心业务页

- AI研发设计
- AI视觉商拍
- AI工具箱
- 任务中心
- 我的素材
- 钱包 / 充值
- 项目详情页

### 关键闭环

- 上传 -> 提交 -> 结果回填
- 结果 -> 任务中心
- 结果 -> 素材库
- 素材 -> 继续创作
- 任务中心 -> 查看结果 / 再来一次
- 积分不足 -> 钱包 -> 返回原页面

---

## 2. 当前版本不建议按“最终商业质量”硬验的部分

这些现在可以测“通不通、顺不顺”，但不建议按最终效果死卡：

- 第一版复用链路的能力效果
- 完整支付闭环
- 后端项目归档能力
- 最终行业级专用效果质量

也就是说：

- **现在适合测产品和链路**
- **不适合把所有 AI 效果都按最终商业发布标准一票否决**

---

## 3. 当前版本的通过标准

只要下面这些成立，就说明这轮客户端测试有意义：

### 页面层

- 页面能打开
- 结构清楚
- 高概率入口能点击

### 链路层

- 上传正常
- 提交正常
- 状态回填正常
- 结果可见

### 闭环层

- 任务中心可回看
- 素材库可继续创作
- 钱包回流顺

---

## 4. 当前版本的回归基线

- 本地 `selfcheck:local`：通过
- 本地 UI smoke：`18 / 18`
- 远端 `selfcheck:full`：通过
- 百度 / 火山 / KIE / ComfyUI 样本：通过

---

## 5. 建议你测试时的心态

建议按这个思路：

- 先看“像不像产品”
- 再看“顺不顺手”
- 再看“通不通”
- 最后再看“哪里需要继续抠细节”

这样更符合当前版本阶段，也更容易把问题分类清楚。
