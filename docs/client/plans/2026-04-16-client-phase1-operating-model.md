# 客户端 Phase 1 产品经营模型（2026-04-16）

## 定位

客户端 Phase 1 不再按“前端页面集合”理解，而按“面向服装设计与电商运营团队的行业 SaaS 设计生产平台前台”理解。

当前第一阶段只做最小商用闭环：

1. 首页解决转化
2. Studio 解决激活
3. 工作台解决生产
4. 任务中心解决回看与重做
5. 资产与模板中心解决沉淀与复用
6. 钱包页解决余额感知与付费入口

## 当前主路径

```text
首页理解价值
  -> 进入 Studio
  -> 选择高频工作流
  -> 发起首任务
  -> 回看结果
  -> 结果进入资产中心
  -> 继续创作 / 复跑 / 看余额
```

## 当前页面职责

### 首页

- 不再只是品牌展示
- 要同时承担案例说服、试用导向、工作流说明、商业前台锚点

### Studio

- 不再只是导航
- 要承担“今天先做什么”的工作入口职责
- 要展示最近任务、最近资产、模板入口、推荐路径

### 工作台

- 保留真实运行时链路
- 表现层改成产品化叙事
- 每个高频入口都有成熟话术、带入模板、案例预期、下一步推荐

### 任务中心

- 任务不是日志页
- 必须承担结果回看、失败解释、重做、回到工作流继续创作

### 资产与模板中心

- 不再只是素材库
- Phase 1 开始承担“素材 + 模板”的双重职责
- 目标是把结果变成下次创作入口

### 钱包页

- 不再只是补充页
- 必须让用户明确看到余额、套餐和返回提交的路径

## 当前高频工作流范围

### 设计侧

- 以文生款
- 以款生款
- 图案提取
- 四方连续

### 运营侧

- 裂变套图
- 图生视频
- 细节图

### 工具侧

- AI 超清
- 高质量缩放
- DPI 处理

## 当前经营指标

Phase 1 先只看这 5 个指标：

1. 注册后首任务发起率
2. 首任务成功可回看率
3. 7 日内二次任务发起率
4. 任务结果沉淀率
5. 低余额用户转化率

## 当前工程实现约束

- 继续使用 `podi-client-web/` 作为唯一主线
- 保留现有真实运行时链路：登录、能力调用、异步任务、结果轮询、素材沉淀
- 新增产品表现层配置：
  - `podi-client-web/src/config/clientProduct.ts`
  - `podi-client-web/src/config/toolPresentation.ts`

- 任务中心已补“回到资产 / 回到工作室 / 看余额策略”承接
