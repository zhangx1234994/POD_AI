# 03. 当前风险与待决策项

## 当前主要风险

### 1. 埋点出口还未正式接入

当前情况：

- 已经有本地事件汇总
- 已经有可替换的统计出口协议
- 但还没有接正式统计后端

影响：

- 经营看板可用于本地验证
- 但还不能直接作为正式运营数据源

### 2. 资产沉淀仍以客户端本地为主

当前情况：

- 上传图和结果图已能沉淀
- 继续创作链路已经可用
- 但仍主要依赖前端本地存储

影响：

- 当前足够支撑 Phase 1 验证
- 但不适合长期作为正式资产中心

### 3. 智能分流规则还是第一版

当前情况：

- 素材继续创作已按图案 / 连续纹理 / 商拍 / 视频 / 交付等场景做基础分流
- 任务继续创作也有兜底分流

影响：

- 能支撑第一阶段体验
- 但还不适合视为最终业务编排规则

### 4. 商业闭环还没到完整支付阶段

当前情况：

- 低余额拦截可用
- 充值单创建和返回原任务页可用
- 推荐套餐可用

影响：

- 可以完成“产品验证级”回流
- 但还不是完整的正式支付闭环

### 5. 构建体积仍偏大

当前情况：

- `aliyun-oss-sdk`
- `tdesign`

影响：

- 当前不阻塞构建和测试
- 但会影响后续性能优化阶段

## 当前必须拍板的决策

### A. 正式埋点出口接谁

需要明确：

- 接哪个服务
- 数据格式是否沿用当前前端协议
- 是否需要身份、环境、版本字段扩展

### B. 资产中心什么时候从本地沉淀切到后端

需要明确：

- 是继续前端推进体验，后补后端
- 还是当前阶段就同步建设后端资产中心

### C. Phase 1 后续优先级顺序

建议在下面 3 组里做排序：

1. 正式统计 / 经营看板对接
2. 资产中心后端化
3. 商业闭环继续深化

### D. 是否继续扩高频工作流

需要明确：

- 是先做深当前高频 10 个左右工作流
- 还是先把更多能力端上来

## 不建议在当前阶段做的决策

- 不建议重新开启双客户端并行
- 不建议把对话式助手提前拉成主入口
- 不建议在正式埋点、正式资产中心、完整支付都未定时就扩太多新工具
