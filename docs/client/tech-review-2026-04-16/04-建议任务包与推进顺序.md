# 04. 建议任务包与推进顺序

> 目的：技术负责人讨论后可以直接按任务包下发，不需要再从聊天记录里拆。

## Task Pack A：正式统计出口

### 目标

把当前本地经营看板升级成正式可上报的数据链路。

### 范围

- 统一埋点字段
- 确认上报接口
- 增加环境 / 版本 / 用户上下文
- 打通前端上报
- 补运营校验说明

### 产出

- 前端正式上报实现
- 埋点字段表
- 校验文档

## Task Pack B：资产中心后端化

### 目标

把当前本地资产沉淀升级成后端正式资产中心。

### 范围

- 统一资产记录模型
- 上传图 / 结果图 / 视频统一沉淀
- 资产列表真实分页 / 筛选
- 从任务和素材继续创作统一走后端资产数据

### 产出

- 前后端接口对接
- 客户端资产中心改造
- 回归用例更新

## Task Pack C：继续创作规则深化

### 目标

把当前第一版智能分流从“可用”升级成“更像真实业务工作流”。

### 范围

- 任务继续创作规则完善
- 素材继续创作规则完善
- 不同能力的默认 prompt / 下一步动作更准确
- 项目页 / 任务页 / 资产页回流统一

### 产出

- 规则清单
- 前端分流实现
- 用例和回归项补齐

## Task Pack D：商业闭环深化

### 目标

把当前低余额回流从基础可用升级为正式前台体验。

### 范围

- 余额不足提示更细
- 套餐推荐更准确
- 充值完成自动回原任务
- 钱包页和工作台的消耗口径统一

### 产出

- 钱包与工作台联动优化
- 商业文案口径统一
- 低余额回流回归测试

## Task Pack E：体验与性能收口

### 目标

在不改主路径的前提下，把前台从“能用”继续推向“可上线”。

### 范围

- 大 chunk 优化
- 加载态 / 错误态 / 空状态继续收口
- 移动端和窄屏适配补强

### 产出

- 性能优化记录
- 体验问题清单
- 构建体积优化结果

## 建议推进顺序

如果按当前状态继续推进，建议顺序是：

1. `Task Pack A` 正式统计出口
2. `Task Pack C` 继续创作规则深化
3. `Task Pack D` 商业闭环深化
4. `Task Pack B` 资产中心后端化
5. `Task Pack E` 体验与性能收口

## 建议任务下发方式

### 产品 / 技术负责人先拍板

1. 正式统计出口接入方案
2. 资产中心是否立即后端化
3. Phase 1 后续优先级

### 再按包下发

- 每次只下发一个主任务包
- 每个任务包需要附带：
  - 目标
  - 边界
  - 是否允许改接口
  - 验收标准
