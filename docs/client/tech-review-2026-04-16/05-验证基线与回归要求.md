# 05. 验证基线与回归要求

## 当前基础验证结果

当前客户端主线 `podi-client-web/` 已验证：

- `npm run lint`
- `npm run build`
- `npm run test:ui`

当前浏览器冒烟已覆盖：

1. 首页
2. 首页模板带入
3. Studio 工作入口
4. Studio 统计出口成功上报
5. Studio 统计出口结构化失败提示
6. 登录态首任务成功 -> 结果沉淀 -> Studio 看板更新
7. 登录态异步任务提交 -> 轮询成功 -> 任务中心继续 / 重做分流
8. 登录态低余额拦截 -> 钱包 -> 返回原页恢复草稿
9. 资产中心继续创作
10. 项目页继续创作
11. 任务中心结果预览 / 重做
12. 钱包页充值与账单入口

## 后续每轮都必须保住的回归路径

### 主路径

- 首页 -> Studio -> 工作台 -> 结果 -> 资产 -> 继续创作
- 登录态首任务成功 -> Studio 经营看板
- 登录态异步任务提交 -> 轮询成功 -> 任务中心继续 / 重做
- 低余额拦截 -> 钱包 -> 返回原工作台
- 统计出口成功 -> 保留 cursor
- 统计出口失败 -> 返回结构化提示并保留待发事件

### 任务链路

- 提交任务
- 回看结果
- 重做
- 回工作台继续创作

### 资产链路

- 上传素材沉淀
- 结果素材沉淀
- 从素材继续创作

### 商业链路

- 余额不足拦截
- 跳转钱包
- 创建充值单
- 返回原任务页

## 后续每轮必须明确的风险项

1. 本轮是否改了接口
2. 本轮是否影响任务回流
3. 本轮是否影响资产沉淀
4. 本轮是否影响低余额回流
5. 本轮是否影响埋点口径

技术负责人后续下发任务时，建议每个任务都必须带：
