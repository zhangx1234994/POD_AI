# 06. 统计出口协议与字段建议

## 目标

给客户端 `Phase 1` 经营看板提供一个正式可对接的统计出口协议，而不是只做一个裸 `POST JSON`。

当前前端已经支持通过以下环境变量控制统计出口：

- `VITE_CLIENT_ANALYTICS_ENDPOINT`
- `VITE_CLIENT_ANALYTICS_PROJECT`
- `VITE_CLIENT_ANALYTICS_AUTH_HEADER`
- `VITE_CLIENT_ANALYTICS_AUTH_TOKEN`

## 当前上报方式

### 请求方式

- `POST`
- `Content-Type: application/json`
- `X-Podi-Client-Source: podi-client-web`
- `X-Podi-Protocol-Version: phase1.v1`
- 若配置 `VITE_CLIENT_ANALYTICS_PROJECT`
  - 额外附带 `X-Podi-Analytics-Project`
- 若配置 `VITE_CLIENT_ANALYTICS_AUTH_TOKEN`
  - 会按 `VITE_CLIENT_ANALYTICS_AUTH_HEADER` 写入鉴权头
  - 默认头名：`Authorization`
  - 当头名为 `Authorization` 且值不以 `Bearer ` 开头时，前端会自动补 `Bearer `

### 前端触发位置

- `Studio` 页的“尝试上报”按钮

## 字段说明

### 顶层字段

- `source`
  - 固定为 `podi-client-web`
- `protocolVersion`
  - 当前固定为 `phase1.v1`
- `batchId`
  - 当前这批上报包的唯一批次标识
- `generatedAt`
  - 前端生成上报包的时间
- `project`
  - 当前客户端项目标识，来自 `VITE_CLIENT_ANALYTICS_PROJECT`
- `range`
  - 本次上报事件范围摘要，便于后端做批次追踪、排查和幂等
- `context`
  - 当前整包上报时的客户端上下文
- `summary`
  - 前端已汇总的 `Phase 1` 经营看板摘要
- `events`
  - 待上报事件数组

### event 字段

- `id`
  - 前端生成的事件 ID
- `name`
  - 事件名
- `at`
  - 事件发生时间
- `payload`
  - 业务字段
- `context`
  - 事件发生时的客户端上下文快照

### context 字段

- `app`
  - 固定值：`podi-client-web`
- `env`
  - 来自 `VITE_APP_ENV` 或 `import.meta.env.MODE`
- `appVersion`
  - 来自 `VITE_APP_VERSION`，未配置时回退到 `package.json version`
- `sessionId`
  - 当前浏览器会话 ID
- `authenticated`
  - 是否登录
- `userId`
  - 当前登录用户 ID，无则 `null`
- `userRole`
  - 当前登录角色，无则 `null`
- `page`
  - 当前页面语义名，如 `home`、`studio`、`tasks`
- `route`
  - 当前路由，如 `/studio`、`/wallet?returnTo=...`

## 推荐后端处理方式

### 最低要求

1. 原样接收 payload
2. 原样记录请求头里的 `X-Podi-*`
3. 保存 `batchId`
4. 保存 `protocolVersion`
5. 保存 `generatedAt`
6. 保存 `events[].id`
7. 保存 `events[].name`
8. 保存 `events[].context`
9. 保存 `events[].payload`

### 建议附加能力

1. 按 `sessionId` 关联行为序列
2. 按 `userId` 聚合首任务、二次任务、低余额转化
3. 按 `page + route` 统计流失点
4. 按 `appVersion` 做版本对比
5. 按 `batchId + range` 做重复包去重
6. 记录项目标识和鉴权来源，避免测试环境与正式环境混流

## 当前前端默认行为

1. 未配置 `VITE_CLIENT_ANALYTICS_ENDPOINT`
   - 不发请求
   - `Studio` 仍保留本地经营事件和复制快照能力
2. 已配置出口但没有待发事件
   - 返回“没有待上报的新事件”
3. 已配置出口且有待发事件
   - 只发送尚未成功上报过的事件
   - 成功后以前端本地 cursor 记录最后一条事件时间
4. 上报失败
   - 不推进 cursor
   - 下次仍会带着相同待发事件继续重试

## 当前待后端确认的点

1. 是否接受前端同时上传 `summary`
2. 是否需要响应里返回服务端批次 ID
3. 是否以 `batchId` 作为幂等键，还是由后端自行生成幂等策略
4. 是否沿用 `Authorization`，还是要求专用头例如 `X-Analytics-Token`
5. 是否需要区分正式环境和测试环境的接收地址 / project
6. 是否要求失败时返回结构化错误体，便于前端在 `Studio` 里给出更具体提示
