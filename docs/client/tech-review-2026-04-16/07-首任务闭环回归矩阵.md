# 07. 首任务闭环回归矩阵

## 自动化已覆盖

### 访客态

1. 首页价值表达与主 CTA 可见
2. 首页模板带入工作台
3. Studio 工作入口与经营看板入口
4. 资产中心继续创作
5. 项目页继续创作
6. 任务中心结果预览
7. 钱包页基础展示
8. 钱包页通过 query 恢复低余额回流上下文

### 登录态 + Mock API

1. `以文生款` 工作台读取真实余额与能力定价
2. 发起首任务并拿到同步结果
3. 结果自动沉淀到素材中心
4. 沉淀后的结果资产会跳到更合理的下一步工作台
5. Studio 经营看板累计“首任务发起 / 结果沉淀”
6. 低余额时拦截提交
7. 从低余额弹窗跳转钱包
8. 从钱包返回原工作台并恢复当前表单草稿

### 异步任务

1. `以款生款` 工作台会创建异步任务
2. 前台轮询会从 `queued -> running -> succeeded`
3. 异步结果会自动沉淀到素材中心
4. 任务中心里的“继续”会按下一步工作流分流
5. 任务中心里的“重做”会保留原工作台和原表单

### 统计出口

1. `Studio` 上报按钮会发送 `phase1.v1` 协议头
2. payload 会包含 `batchId / project / range / context / events`
3. 出口返回 `401 + 结构化错误体` 时，前台会显示可读失败原因和失败码

## 当前自动化边界

- 自动化现在验证的是“客户端行为和状态收口”，不替代真实后端联调。
- 登录态路径通过 Playwright 拦截 `/api/abilities`、`/api/wallet/*`、`/api/abilities/{id}/invoke` 来稳定回归。
- 统计出口路径通过 Playwright 拦截 `__client_analytics__` 来验证请求头、批次字段和失败提示。
- 这样做的目的，是先保住前台闭环不会因为壳层调整、状态管理调整而退化。

## 仍需手工或联调验证

1. 真实登录态下的接口鉴权与 token 失效处理
2. 异步任务 `createTask -> poll -> success/failed` 全链路
3. 真实 OSS 上传、素材沉淀和继续创作
4. 真实充值单支付完成后的自动回流
5. 正式统计出口的鉴权、幂等与失败重试

## 当前建议验收口径

### P0

- 首任务同步成功链路必须自动化可回归
- 低余额拦截和回流必须自动化可回归
- 资产沉淀必须能在 UI 层看到结果，不接受“数据写了但前台无反馈”

### P1

- 异步任务轮询成功 / 失败至少各有一条自动化或稳定联调记录
- 正式统计出口至少有一轮联调通过记录

## 对后续任务包的要求

- 每新增一条高频工作流，必须说明是否纳入这份矩阵
- 每改一次低余额、任务回流、资产沉淀逻辑，必须同步更新本矩阵
- 若本轮未补自动化，必须在任务说明中明确原因和补回归时间
