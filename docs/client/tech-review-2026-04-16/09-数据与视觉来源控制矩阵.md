# 09-数据与视觉来源控制矩阵

## 目的

这份矩阵回答 4 个问题：

1. 每个主页面的数据从哪里来  
2. 每类视觉从哪里来  
3. 这些来源目前在哪里做控制  
4. 后续要替换成正式内容时，应该改哪一层

## 为什么要把视觉控制统一到 registry

如果每个页面自己写图片链接，会出现 4 个问题：

1. 无法解释这张图为什么在这里  
2. 无法批量替换成正式品牌素材  
3. 无法知道哪个页面还在使用临时占位图  
4. 设计和研发很难对齐控制边界

统一 registry 之后，视觉就从“散落的实现细节”变成“可治理的产品资产”。

## 当前控制原则

### 数据控制原则

- 真实业务数据，优先走真实接口
- 仍未后端化的数据，集中放在配置层或本地服务层
- 页面组件不承担数据定义职责，只承担消费职责

### 视觉控制原则

- 图片 URL 不直接写在主页面组件里
- 图片属于内容资产，统一从配置层输出
- 页面只负责决定“这里需要什么类型的视觉”，不直接决定素材地址

## 后续治理建议

1. 继续把活跃主链路中的硬编码图片迁移到 `clientVisualRegistry`
2. 当品牌或运营提供正式案例图后，只替换 registry，不改页面结构
3. 资产中心后端化时，同步梳理哪些“示例图”要升级为“真实品牌案例资产”
4. 把数据来源矩阵和视觉来源矩阵视为主线文档，每次新增页面都要补登记
