# 测评端交互理念（Eval）

## 目标与边界
- 目标：以“任务流优先”重排测评端信息结构，让用户按 **配置 → 执行 → 结果 → 复盘** 顺序自然完成工作。
- 边界：仅调整前端 UI/UX 与交互节奏，不改后端 `/api/*` 合约。
- 风格：中高密度运营台，中文主导，保留必要英文术语（run/task/status）。

## 交互主路径
1. **配置**：选择功能卡片，填写参数与素材。
2. **执行**：提交任务，明确当前排队/运行状态。
3. **结果**：右侧结果区优先展示最新结果与失败原因。
4. **复盘**：历史区进行筛选、评分、备注、导出。

## 导航与信息架构
- 顶部导航 = 全局视图切换（功能评测 / 批量回归 / 任务追踪 / 接口文档 / 维护配置）。
- 左侧栏 = 仅在“功能评测域（home/tool）”显示的分类筛选器。
- 非评测域（loraBatch/tasks/docs/admin）隐藏左侧栏，避免双导航语义冲突。
- URL 同步保留：`?view=&category=&tool=`，支持刷新恢复与团队分享定位。

## 状态词规范（UnifiedStatus）
- `queued`：排队中（warning）
- `running`：执行中（warning）
- `succeeded`：成功（success）
- `failed`：失败（danger）
- `cancelled`：已取消（default）
- 其他：未知（default）

## 错误反馈分层
- **页面级**：关键加载失败（如 docs/tasks 首屏失败），在页面顶部 `Alert` 呈现。
- **模块级**：单块区域失败（如批次列表、批次明细），在模块卡片内提示并保留重试入口。
- **行内级**：单条任务失败（如 run 失败、保存评分失败），在行内展示错误码/错误文案。
- 错误文案要求：保留机器错误码（若有）+ 中文解释 + 下一步建议（重试/检查参数/稍后再试）。

## 视觉与可操作性准则
- 卡片优先展示：标题、版本、评分、主 CTA；说明文案降权。
- 快速上手只保留轻量流程提示，不再占据首页核心区域。
- 所有可点击元素必须提供 `hover / active / focus` 反馈。
- 关键操作统一落在 `ActionBar / FilterBar`，减少散落按钮造成的认知噪音。
