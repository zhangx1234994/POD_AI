# 平台范围图

## 1. 中台 owner 负责的不是单点页面

中台 owner 负责的是 POD AI Studio 的平台后端主链路，而不是某个页面报错后的局部补丁。

关注对象包括：

- 能力目录与能力调用链路
- 执行节点与厂商适配
- 工作流与绑定关系
- 异步任务、回调、状态流转
- OSS 媒资沉淀
- OpenAPI / Coze 工具箱对外契约
- 错误码、状态词、结果口径

## 2. 当前仓库对应关系

### 后端

- `backend/`
- 责任：FastAPI API、SQLAlchemy 模型、能力调用、任务链路、执行节点、Celery、媒资与日志

### 管理端

- `podi-admin-web/`
- 责任：能力管理、执行节点、工作流/绑定、能力测试、统一能力接口展示

### 评测端

- `podi-eval-web/`
- 责任：能力评测、测试配置、结果展示、参数与结果口径联调

### 客户端

- `podi-client-web/`
- 说明：V1 旧版客户端，保留参考
- `podi-client-v2/`
- 说明：V2 新版客户端，当前活跃版本

### 平台配置与文档

- `config/executors.yaml`
- `docs/`

## 3. 中台变更的典型影响面

任何一个中台改动，都至少要判断以下影响：

- 管理端能力测试是否仍能正常使用
- 评测端参数与结果展示是否仍然一致
- 客户端调用 `/api/abilities`、任务中心、媒资展示是否受影响
- Coze 工具箱 / OpenAPI 是否需要同步
- 错误码总表、状态词口径、接口文档是否要更新

## 4. 中台 owner 的主链路视角

最小完整链路通常是：

1. ability 定义
2. executor / workflow / binding 配置
3. 中台 API 契约
4. 执行与异步任务状态
5. 结果媒资沉淀到 OSS
6. 日志与问题追查
7. 管理端 / 评测端 / 客户端 / Coze 同步
8. 文档、错误码、回归记录补齐

只改其中一个点，不检查整条链路，默认视为未完成。
