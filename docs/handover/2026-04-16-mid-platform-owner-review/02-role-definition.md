# 岗位定义与职责边界

## 1. 岗位定位

负责 POD AI Studio 中台后端的持续开发和维护。

这不是“接第三方 API 的接口岗”，也不是“按页面修问题”的支持岗，而是平台能力调度、任务流转、执行节点、工具箱契约、媒资沉淀、状态与错误口径的一线 owner。

## 2. 核心职责

### 中台后端日常开发与维护

范围包括：

- 能力接入
- 执行节点管理
- 工作流与绑定管理
- 异步任务链路
- OSS 媒资沉淀
- Coze / ComfyUI / KIE / Volcengine / Baidu 等外部对接

### 对中台接口契约负责

必须对以下内容负责：

- 请求参数
- 返回结构
- 状态词
- 错误码
- 回调结果口径

### 对跨端影响负责

中台任何改动，都要判断以下对象是否受影响：

- 管理端
- 评测端
- 客户端
- Coze 工具箱

### 对问题排查和链路定位负责

不能只改代码，还要能查：

- 数据库记录
- 任务状态
- 执行节点状态
- 第三方请求链路
- 线上配置和环境差异

### 对文档和回归负责

每次改动后必须同步：

- 接口文档
- 工具箱文档
- 错误码总表
- 关键测试与回归记录

## 3. 技术要求

### 必须具备

- 熟悉 Python
- 熟悉 FastAPI
- 熟悉 SQLAlchemy / ORM
- 能处理异步任务、队列、状态流转
- 能看懂并维护 MySQL 数据结构
- 能调试第三方 HTTP API
- 能处理图片 URL、文件上传、OSS 这类媒资链路
- 能接受和维护严格接口契约

### 最好具备

- Celery 或类似任务系统经验
- ComfyUI / 工作流引擎接入经验
- OpenAPI / 工具箱封装经验
- 错误码治理、接口规范治理经验
- 多系统联调经验

## 4. 不属于合格 owner 的行为

- 只会按页面报错改接口，不会看全链路
- 改了接口不更新文档
- 改了参数不看 Coze / eval / client 是否受影响
- 不关心状态词和错误码一致性
- 出问题只会说“我这里是好的”
- 不会查数据库和任务状态
- 不会明确给出根因和验证结果
