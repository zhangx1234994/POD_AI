# 试用期核验任务

以下任务适合用来判断一个人是否真的能承担中台 owner 角色。

## 1. 接一个新的 Coze 工具箱

看他能不能把以下内容一起做完整：

- ability
- workflow
- binding
- OpenAPI
- 文档
- 测试

如果只完成其中一半，说明还停留在“局部实现”阶段，不是 owner 视角。

## 2. 修一个中台链路 bug

重点看 4 件事：

- 能不能定位根因
- 能不能判断影响范围
- 能不能给出回归结论
- 能不能把验证结果写清楚

## 3. 做一次跨端参数对齐

重点看是否会同步以下对象：

- 中台
- 评测端
- Coze
- 文档

## 4. 评估标准

### 合格表现

- 先看真源文档再下手
- 能明确区分现象、根因、影响面
- 能识别跨端和外部系统联动
- 能补文档、错误码、回归记录
- 能交付一份可追溯的变更说明

### 不合格表现

- 只盯当前页面或当前报错
- 不补文档
- 不核对错误码和状态词
- 不给验证结论
- 不会查任务链路、数据库和执行节点状态

## 5. 试用期最该验证的不是编码速度

最该验证的是 3 个能力：

1. 全链路意识
2. 契约意识
3. 可追溯交付意识

这 3 项比“单次写代码速度”更重要。
