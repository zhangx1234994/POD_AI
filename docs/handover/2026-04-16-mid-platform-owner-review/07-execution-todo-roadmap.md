# 中台产品化改造 Todo 与分步执行路线

## 1. 执行原则

后续所有动作都遵守 4 条原则：

1. 不改现有接口路径
2. 不破坏现有请求 / 响应契约
3. 不影响现有业务链路和 Coze 调用
4. 每一批改动都必须能独立回归、独立停下

这意味着后续不是“大改版”，而是**兼容式分层改造**。

## 2. Todo 总表

### P0. 必须先收口

#### T1. 统一术语表

目标：

- 把用户看到的核心词汇统一成一套语言

要解决的问题：

- 英文过多
- 技术词过多
- 同一个东西在不同端叫法不一致

交付物：

- 术语对照表
- 对内名 / 对外名映射
- 禁止直接外露的技术词清单

验收标准：

- 客户端、Coze、文档的高频名称统一

#### T2. 建立能力展示层规范

目标：

- 让 `ability` 不再直接裸露成用户语言

要解决的问题：

- 表单像接口调试页
- 字段标签、描述、占位语零散

交付物：

- `metadata.presentation` 字段规范
- 可见性规则
- 高级参数规则

验收标准：

- 不改调用契约的前提下，用户端默认只看到业务语言

#### T3. 建立多端暴露矩阵

目标：

- 明确一个能力应该出现在哪些端

要解决的问题：

- 内部能力提前外露
- Coze、客户端、管理端口径混乱

交付物：

- `internal_only / admin_and_eval / client_enabled / coze_enabled / advanced_only` 规则

验收标准：

- 任一能力都能回答“在哪些端出现，为什么”

#### T4. 建立页面对象控制表

目标：

- 明确每个页面上的数据、图片、文案分别由谁控制

要解决的问题：

- 图片来源分散
- 内容写死在页面
- 后面不知道该改前端、改中台还是改素材库

交付物：

- 页面对象级控制清单
- 当前来源 / 当前控制 / 目标控制

验收标准：

- 能明确回答登录页图、首页图、模板封面、案例图、钱包统计分别从哪来

### P1. 可以并行推进

#### T5. 客户端首页内容层收口

目标：

- 把首页 Hero、案例、模板推荐、角色案例从页面常量里抽离

交付物：

- surface content 配置文件
- 首页内容统一读取层

验收标准：

- V1 / V2 首页内容不再散落在多个页面文件里

#### T6. 客户端工作区去技术化

目标：

- 把工作区从 schema 渲染器继续改成任务引导器

交付物：

- 分组后的字段展示
- 高级参数折叠策略
- 结果页下一步推荐规范

验收标准：

- 用户默认只需要回答“我想做什么”和“给系统什么”

#### T7. Coze 工具出口重命名

目标：

- 让 Coze 工具对外叫业务动作，而不是中台能力名

交付物：

- Coze 工具标题规范
- 工具摘要规范
- 参数提示规范

验收标准：

- Coze 工具列表里不再默认出现明显内部技术词

#### T8. 管理端分层

目标：

- 把“运营判断”和“高级配置”从大页面里拆开

交付物：

- 日常运营视图
- 高级配置视图
- 内部对象可追溯关系视图

验收标准：

- 非研发同学也能在管理端理解当前能力状态，而不是只能看配置项

### P2. 后续接真实数据

#### T9. 素材中心真实化

目标：

- 把浏览器本地素材库逐步替换成真实资产系统

交付物：

- 真实素材接口接入
- 本地壳层兼容迁移
- 结果资产统一沉淀策略

验收标准：

- 素材可跨设备、跨会话、跨团队查看

#### T10. 钱包与经营数据真实化

目标：

- 让钱包页和经营指标页不再展示静态占位信息

交付物：

- 钱包真实数据接入
- 指标口径定义
- 用户可见经营解释文案

验收标准：

- 钱包页能解释“余额 / 消耗 / 返还 / 套餐 / 为什么付费”

#### T11. 品牌媒资库

目标：

- 让首页、登录、案例、模板图逐步脱离外部公共图库

交付物：

- 自有 OSS 品牌图目录
- 展示样本审核流程
- 页面图片引用规范

验收标准：

- 关键入口页不再依赖 `Unsplash`

## 3. 分步执行方案

### 第一批

先做认知层收口，不碰真实业务数据：

1. T1 统一术语表
2. T2 能力展示层规范
3. T3 多端暴露矩阵
4. T4 页面对象控制表

这一批的目标不是“更好看”，而是让后面所有改动有统一语言和统一边界。

### 第二批

再做用户能直接感知的前台收口：

1. T5 首页内容层收口
2. T6 工作区去技术化
3. T7 Coze 工具出口重命名

这一批的目标是让用户真正感觉系统“不再像技术平台”。

### 第三批

最后接真实资产与真实经营数据：

1. T8 管理端分层
2. T9 素材中心真实化
3. T10 钱包与经营数据真实化
4. T11 品牌媒资库

这一批的目标是让平台从“产品化壳层”进入“真正的业务系统”。

## 4. 我的执行顺序

我建议按下面顺序推进，不并发乱做：

1. 先出术语表和暴露矩阵
2. 再补能力展示层规则
3. 再改首页 / 工作区 / Coze 的对外表达
4. 最后接真实素材、钱包和品牌资产

原因很简单：

- 如果没有统一术语，前端怎么改都会反复返工
- 如果没有暴露矩阵，能力会继续无序外露
- 如果没有展示层，工作区会一直像接口面板
- 如果不最后再接真实数据，前面会被数据接入工作拖慢

## 5. 当前我建议立刻开做的事项

下一步我建议马上进入第一批，只做这 3 件事：

1. 输出统一术语表
2. 输出多端暴露矩阵
3. 把现有高频能力补齐 `presentation` 规范

这三件事做完，后面的首页、工作区、Coze 改造就会快很多，也更稳。
