# 01. 产品定位

## 1. 这次改版的本质

这次不是“测评端 UI 优化”，而是一次**能力体验中心重构**。

原因很简单：

- 当前系统已经能跑通单次评测、批量回归、打分、文档、维护配置
- 现在真正暴露出来的问题，不再是“功能够不够”，而是“这套东西看起来不像一个体验中心”
- 页面在承载“体验中心职责”的同时，仍然保留了强烈的“内部联调台 / 工程操作台”气质

因此，本次改版要解决的核心问题不是视觉风格，而是**产品角色和信息组织方式**。

## 2. 为什么不能继续用“测评端”思路做加法

如果继续按“测评端”思路演进，页面会自然往下面这些方向继续膨胀：

- 更多参数
- 更多任务状态
- 更多文档
- 更多管理入口
- 更多技术字段

这会让它越来越适合“会操作系统的人”，但越来越不适合“需要快速形成判断的人”。

而现在这个产品实际承担的职责，已经不是“做测试”这么简单，而是：

- 给决策人展示效果和投入价值
- 给业务展示商用边界
- 给开发提供接入依据
- 给产品沉淀下一步规划线索

这就是“体验中心”的职责，不是单纯的“测评台”。

## 3. 新定位建议

建议将该产品定义为：

**能力体验中心**

一句话定义：

> 一个面向决策、商用判断、接入沟通和能力规划的内部体验与评审中心。

## 4. 这个产品应该做什么

它应该优先帮助团队回答 4 个问题：

1. 这项能力现在效果怎么样
2. 它适合哪些场景，不适合哪些场景
3. 它能商用到什么程度
4. 接下来应该继续优化什么

## 5. 这个产品不应该做什么

它不应该把所有后台能力都放在用户主路径里。

具体包括：

- 不把维护配置放在主体验流里
- 不把联调细节放在首页
- 不把文档页和任务页抢成主入口
- 不把“工作流 / 节点 / 调度 / 运行链路”等工程概念暴露为默认视角

这些内容可以保留，但应该进入二级或三级视图。

## 6. 这次改版的主原则

### 原则 1：先结论，后操作

用户先看“能力状态、商用等级、代表案例、风险摘要”，再决定是否进入测试或接入。

### 原则 2：先场景，后工具

不要再从“工具分类”开始讲故事，而应该从“这个能力能解决什么业务问题”开始。

### 原则 3：先证据，后参数

单能力页先看效果、边界、坏例，再看参数和调用方式。

### 原则 4：先角色视角，后系统视角

四类角色需要的信息不同，页面不能继续让所有人在同一个视图里翻找。

## 7. 本轮定位结论

本轮评审建议直接确认以下结论：

- 接受“能力体验中心”作为新定位
- 接受这次改版优先解决产品动线，而不是局部视觉问题
- 接受未来页面结构围绕“结论、证据、测试、接入”四类内容组织
