# 04. 商用分级标准（草案）

## 1. 为什么必须先定分级

如果没有统一商用等级，团队内部很容易出现这些表达：

- “这个能力还行”
- “应该能卖”
- “能用，但不稳定”
- “感觉还差一点”

这些表达无法支撑决策、业务沟通和排期。

因此，体验中心必须给每个能力一个**明确等级**。

## 2. 建议采用 4 级口径

### L1 可演示

定义：

- 能跑出不错结果
- 适合内部展示或客户演示
- 但稳定性、覆盖率或人工修补成本仍偏高

适用：

- 销售演示
- 概念验证
- 内部汇报

不适用：

- 直接承诺交付
- 大规模复制使用

### L2 可试卖

定义：

- 在部分标准场景中结果稳定
- 可以向客户小范围试卖或试单
- 但仍需挑样本、挑场景，且需要人工复核

适用：

- 小范围客户试用
- 特定案例试卖
- 限定条件下的业务验证

不适用：

- 全量放量
- 无人工兜底直接上线

### L3 可交付

定义：

- 在限定业务范围内可稳定交付
- 失败模式已知且可控
- 人工修补成本在可接受范围内

适用：

- 限定行业、限定样本、限定流程下正式交付

不适用：

- 跨大量场景无差别推广

### L4 可规模商用

定义：

- 稳定性高
- 场景覆盖较广
- 失败成本低且可控
- 具备规模化推广条件

适用：

- 稳定客户交付
- 产品化放量
- 业务常态使用

## 3. 分级判断参考维度

建议至少看这 6 个维度：

1. 结果质量
2. 场景覆盖率
3. 稳定性
4. 失败可恢复性
5. 人工修补成本
6. 客户可接受度

## 4. 建议的落标方式

每个能力在体验中心都要显示：

- 当前等级
- 判定理由
- 主要风险
- 升级到下一等级的前提

例如：

```text
当前等级：L2 可试卖
判定理由：标准样本集中 70% 可用，复杂纹理和文字类场景仍不稳定
主要风险：边缘残留、文字失真、批量一致性不足
升级条件：坏例率降到 15% 以下，并完成 3 轮批量回归
```

## 5. 为什么这套分级对四类角色都有价值

- 决策人：知道值不值得继续投
- 业务测试：知道能不能对外试
- 产品：知道下一步目标是什么
- 开发：知道当前能力的风险边界

## 6. 当前建议

本轮评审建议先确认：

- 是否采用 4 级模型
- 是否要求每个重点能力都必须有明确等级
- 是否接受等级判断基于“批量证据 + 代表案例 + 风险摘要”共同给出
