# 06. 轻量测评端改版方向 V2

> 说明：这是在进一步讨论后的收敛版方向。
> 核心前提：**测评端不区分用户，不做复杂分层，它就是一个轻量、扁平、好用的内部体验台。**

## 1. 这次到底改什么

这次不是把测评端改成一个复杂的“角色门户”，也不是做成重型中台首页。

这次真正要改的是 3 件事：

1. 让整体动线更顺
2. 让每个功能更好理解、更好上手
3. 让每个功能的使用场景表达更清楚

一句话说：

**把现在“能用但零散”的测评端，整理成一个轻量、直觉、顺手的体验工作台。**

## 2. 当前问题重新定义

当前问题已经不是“功能不够”，而是：

- 首页没有明确动线
- 各功能入口组织比较散
- 进入功能后信息堆叠，没有主次
- 用户不知道这个功能适合什么场景
- 接口、任务、历史、参数都在抢主视图

所以这次不应该继续做“内容加法”，而应该做“主路径收敛”。

## 3. 改版目标

### 目标 1：用户进来就知道先做什么

进入测评端后，不应该先思考系统结构，而应该自然进入：

```text
看功能
  -> 理解场景
  -> 输入素材 / 参数
  -> 开始体验
  -> 看结果
  -> 判断值不值得继续
```

### 目标 2：每个功能页都更像体验页

功能页不该再像“参数表单 + 结果面板 + 历史列表 + 文档块”的拼接页。
它应该更像一个顺手的功能体验页：

- 先讲这个功能是干嘛的
- 再讲适合什么场景
- 再进入输入和体验
- 最后展示结果和轻量沉淀

### 目标 3：技术信息后置

参数、历史、文档、接口这些都重要，但不应该压在最前面。
它们应该保留，但降权。

## 4. 新的页面动线

## 4.1 首页动线

首页应该先解决两个问题：

1. 这里有哪些功能
2. 每类功能适合什么场景

建议首页结构：

1. 顶部一句话说明
   - 这是一个内部能力测评与体验台

2. 功能分类卡片
   - 花纹提取
   - 图延伸
   - 四方/两方连续
   - 图裂变
   - 通用类

3. 每类下直接显示代表功能
   - 不要只显示分类名，要让用户能直接进入高频功能

4. 每类给一行场景说明
   - 比如：
   - 花纹提取：用于从成品图中提取可复用花纹
   - 图延伸：用于补全边缘、扩展构图
   - 四方连续：用于做连续平铺效果验证

### 首页不该太重

首页不建议出现：

- 大段说明文案
- 复杂统计
- 任务明细表
- 接口文档区
- 维护配置入口

首页的目标只是：

- 快速理解
- 快速进入

## 4.2 功能页动线

建议统一改成 4 段结构：

### 第一段：功能说明

放最短必要信息：

- 功能名称
- 一句话用途
- 适用场景
- 不适合的场景

### 第二段：输入区

这是主操作区，只保留当前体验真正需要的输入。

要求：

- 必填和可选区分明确
- 字段分组清楚
- 默认值合理
- 不常用高级项收进折叠区

### 第三段：结果区

结果区要成为第二视觉中心。

至少包含：

- 当前状态
- 结果预览
- 出错时怎么理解
- 结果好不好怎么看

### 第四段：轻量沉淀区

只保留最有价值的沉淀信息：

- 最近几次结果
- 简单评分 / 备注
- 必要时再展开看更多历史

## 5. 各功能页应该怎么表达“使用场景”

这是本轮改版最值得补的一层。

每个功能页建议固定有一个“适合 / 不适合”模块。

### 建议模板

#### 这个功能适合

- 哪类素材
- 哪类目标
- 哪类业务场景

#### 这个功能不适合

- 哪些图容易失败
- 哪些场景结果不稳定
- 哪些需求不建议在这里验证

#### 体验建议

- 首次体验推荐怎么测
- 推荐上传什么图
- 结果重点看什么

这样用户在点进功能前后，都会知道：

- 为什么要用它
- 什么时候不该用它

## 6. 哪些内容该降权

当前测评端里，有些内容不该删，但应该明显后置。

### 降权内容 1：接口文档

保留，但不应该和主体验抢视图。
建议放到二级标签或折叠区。

### 降权内容 2：任务追踪

保留，但它更像“辅助追溯能力”，不是主功能入口。

### 降权内容 3：维护配置

这个入口不属于主测评流。
建议弱化，甚至后续从主导航中移走。

### 降权内容 4：历史记录

历史重要，但应该是轻量列表，不应该在单功能页里长篇占屏。

## 7. 哪些内容该前置

### 前置内容 1：场景说明

每个功能先说明“解决什么问题”。

### 前置内容 2：输入要求

告诉用户：

- 传什么图
- 有没有尺寸要求
- 哪些字段影响最大

### 前置内容 3：结果判断

用户看到结果后，页面要帮助他快速判断：

- 成了没
- 好不好
- 值不值得继续测

## 8. 首页和功能页的改版原则

### 原则 1：少解释系统，多解释功能

不要先解释测评端结构，要先解释功能用途。

### 原则 2：少暴露技术，先服务体验

技术信息保留，但后置。

### 原则 3：少做大而全，多做直觉顺手

让用户不用理解系统，也能开始体验。

### 原则 4：少堆信息，多给动作顺序

页面要让用户自然知道下一步点哪里。

## 9. 这一版建议优先落的页面

如果后面进入设计阶段，建议优先做这 3 类页面：

1. 首页总览
2. 单功能页
3. 批量页

原因：

- 首页决定第一印象和进入效率
- 单功能页决定大部分日常体验
- 批量页决定重度使用体验

接口说明和任务追踪先不作为第一优先级重做对象。

## 10. 本轮评审建议确认

建议这轮讨论只确认以下几点：

1. 是否接受“轻量、扁平、以功能体验流程为主”的方向
2. 是否接受首页以“功能理解 + 快速进入”为主
3. 是否接受单功能页统一按“说明 -> 输入 -> 结果 -> 轻量沉淀”组织
4. 是否接受场景说明成为每个功能页的固定模块
5. 是否接受文档、任务、维护配置整体降权

## 11. 下一步建议

如果这个方向确认，就进入下一阶段：

1. 首页低保真框架
2. 单功能页低保真框架
3. 批量页低保真框架
4. 各分类功能的场景说明文案模板

这一步不用先写代码，先把结构和交互走顺。
