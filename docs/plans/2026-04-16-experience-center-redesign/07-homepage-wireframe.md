# 07. 首页低保真框架

## 1. 首页目标

首页只做两件事：

1. 让用户快速理解这里有哪些功能
2. 让用户快速进入对应功能体验

首页不承担：

- 深度结果分析
- 任务追踪
- 接口接入解释
- 后台维护操作

## 2. 首页结构

### 区块 A：顶部轻说明

建议内容：

- 标题：`PODI 能力测评`
- 副标题：一句话解释用途
  例：`内部快速体验与回归验证台`

要求：

- 不做大 Hero
- 不做长段说明
- 只给用户建立一个轻认知

### 区块 B：分类入口

展示当前 5 类功能：

- 花纹提取类
- 图延伸类
- 四方/两方连续图类
- 图裂变
- 通用类

每个分类卡建议包含：

- 分类名称
- 一句话场景说明
- 当前功能数量
- 1 到 3 个代表功能快捷入口

### 区块 C：高频功能区

目的：

- 不让用户必须先理解分类再点击
- 让高频功能直接可达

建议展示：

- 最近常用
- 当前推荐
- 最近新增 / 最近调整

每张功能卡建议只保留：

- 功能名
- 一句话用途
- 标签（如 LoRA / 多图 / 批量）
- 主 CTA：`开始体验`

### 区块 D：轻提示区

只保留最有价值的 3 条提示：

- 测什么图更合适
- 第一次体验怎么开始
- 批量回归什么时候用

要求：

- 不做复杂教程
- 不把页面变成说明文档

## 3. 首页信息优先级

优先级顺序建议：

1. 功能分类
2. 快捷进入
3. 高频功能
4. 轻提示

降权内容：

- 评分总览
- 历史任务
- 文档入口
- 维护配置

## 4. 首页交互原则

### 原则 1：尽量少滚动

用户进入首页后，首屏和半屏内最好就能完成选择。

### 原则 2：卡片信息短而准

功能卡不讲系统结构，只讲：

- 它做什么
- 适合什么
- 点进去做什么

### 原则 3：分类与功能双入口并存

用户可以：

- 先按分类找
- 也可以直接点具体功能

## 5. 首页推荐文案格式

### 分类说明文案模板

`用于 ______ ，适合 ______ 。`

示例：

- 花纹提取类：用于从成品图中提取可复用花纹，适合做印花整理与二次设计。
- 图延伸类：用于补全边缘和扩展构图，适合做海报延展和素材扩边。

### 功能卡说明文案模板

`适合 ______ ，重点验证 ______ 。`

## 6. 首页低保真排序草案

```text
顶部轻说明
分类入口区
高频功能区
轻提示区
```

这是一个“快进快出”的首页，不应该把用户拦在这里。
