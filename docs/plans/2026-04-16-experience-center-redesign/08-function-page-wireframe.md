# 08. 单功能页低保真框架

## 1. 单功能页目标

单功能页是测评端最核心的页面。
它的目标不是展示系统能力，而是让用户顺手完成一次体验。

一句话定义：

> 用户点进来后，快速理解功能用途，输入最少必要信息，得到结果，并能轻量复盘。

## 2. 统一结构

建议所有功能页统一使用以下 4 段结构：

1. 功能说明
2. 输入区
3. 结果区
4. 轻量沉淀区

## 3. 区块设计

### 区块 A：功能说明

放在页面最上方，必须比现在更短、更像“功能介绍卡”。

建议包含：

- 功能名称
- 一句话用途
- 适合场景
- 不适合场景

可选：

- 输入要求提示
- 推荐测试方式

不建议放：

- 长文档
- 大段业务接入说明
- 大量版本和技术字段

### 区块 B：输入区

这是页面主操作区。

设计要求：

- 必填字段靠前
- 可选字段靠后
- 高级参数收折叠区
- 上传和文本输入放在第一屏完成

建议字段排序：

1. 素材输入
2. 主要参数
3. 次要参数
4. 高级参数（折叠）
5. 主 CTA

### 区块 C：结果区

结果区应和输入区同级，成为第二视觉中心。

建议包含：

- 当前状态
- 最新结果预览
- 错误时的可读解释
- 结果判断提示

结果判断提示示例：

- 花纹提取：重点看边缘、完整度、背景残留
- 图延伸：重点看拼接感、主体完整性、延伸自然度

### 区块 D：轻量沉淀区

只展示对当前体验最有帮助的内容：

- 最近几次结果
- 简单评分
- 简短备注

设计原则：

- 默认展示少量记录
- 更多历史放到展开区或跳转区

## 4. 推荐布局

建议统一为：

```text
顶部：功能说明
中部：左输入 / 右结果
底部：轻量历史与标注
```

为什么这样排：

- 用户的自然顺序就是左到右、上到下
- 输入和结果同时可见，减少来回滚动
- 历史放底部，不打断主流程

## 5. 交互规则

### 规则 1：第一次进入时，默认状态必须清楚

用户一打开页面，要立刻知道：

- 先上传什么
- 哪个字段最关键
- 点哪个按钮开始

### 规则 2：提交时不让页面“失控”

提交后应明确显示：

- 已提交
- 排队中 / 执行中
- 当前这次任务对应的结果区域

### 规则 3：错误要贴近结果区

不要把错误只放在全局通知里。
功能页的错误应直接出现在结果区附近。

### 规则 4：文档入口保留但降权

接口示例和接入说明可以保留，但不要占主操作区。

## 6. 页面内容前后置建议

### 应前置

- 功能用途
- 适合 / 不适合场景
- 素材输入
- 主要参数
- 主 CTA
- 最新结果

### 应后置

- 历史记录
- 详细文档
- 技术字段
- 维护说明

## 7. 不同功能页可共用的“结果判断提示”

建议统一增加一个小模块：

`怎么看这次结果是不是好`

用途：

- 帮助业务或产品快速判断
- 降低“看到了结果但不知道怎么看”的问题

## 8. 单功能页低保真顺序草案

```text
功能说明
输入区 + 结果区
轻量沉淀区
辅助入口（文档 / 更多历史）
```
