# 09. 批量页低保真框架

## 1. 批量页目标

批量页的核心目标不是“管理很多任务”，而是：

- 让用户高效发起一轮批量验证
- 快速看出这一轮整体质量
- 方便筛出问题样本并导出

一句话：

> 批量页是“验证一组结果”的地方，不是“看一堆任务”的地方。

## 2. 页面结构建议

建议改成 3 段结构：

1. 批量配置
2. 执行进度
3. 结果复核

## 3. 区块设计

### 区块 A：批量配置

建议包含：

- 选择工作流
- 选择 LoRA / 关键参数
- 测试次数
- 输出尺寸策略
- 上传批量图片
- 主 CTA：开始批测

优化建议：

- 把“说明文字”压缩成短提示
- 配置区以“快速开始”为目标
- 不把所有规则全文写在页面上

### 区块 B：执行进度

这是批量页的中间反馈区。

建议只保留这些核心信息：

- 当前批次
- 样本数
- 已提交数
- 已完成数
- 失败数
- 未入库数

同时提供：

- 刷新
- 停止批次
- 切换历史批次

设计原则：

- 进度区是“看整体”的，不是看明细的
- 明细作为下层展开，不要先堆满

### 区块 C：结果复核

这是真正最有价值的部分。

建议包含：

- 原图 / 结果图对照
- 满意 / 不满意标记
- 不满意原因
- 备注
- 导出全部 / 导出不满意

优化重点：

- 让复核动作尽可能短
- 让图和判断区域靠近
- 不让用户在一页里来回跳

## 4. 批量页应该强化什么

### 强化 1：批次摘要

批次一结束，页面应让用户一眼看到：

- 这批总体行不行
- 最大问题是什么
- 要不要继续测

### 强化 2：问题样本筛选

用户最想找的是：

- 哪些失败了
- 哪些不满意
- 哪些值得导出给算法或产品看

### 强化 3：复核节奏

批量页不应该只是一长页明细。
它应该帮助用户用固定节奏完成：

```text
看批次整体
  -> 看问题样本
  -> 标记
  -> 导出
```

## 5. 批量页应该弱化什么

### 弱化 1：过多文字说明

规则可以保留，但不要用大段说明占屏。

### 弱化 2：执行明细先于结果复核

执行明细是辅助排查，不该抢在“结果复核”前面。

### 弱化 3：复杂状态词堆积

面向页面主视图时，只保留对用户有用的状态摘要。

## 6. 推荐页面顺序

```text
批量配置
批次进度
结果复核
明细排查（折叠或后置）
```

## 7. 批量页设计原则

### 原则 1：先看结果，再看明细

### 原则 2：先做复核，再做排障

### 原则 3：让“问题样本”比“全部样本”更容易被看到

## 8. 批量页低保真目标

后续在低保真里，建议把页面视觉中心放在：

- 配置主表单
- 批次摘要卡
- 结果复核区

而不是把主视觉给到表格和状态明细。
