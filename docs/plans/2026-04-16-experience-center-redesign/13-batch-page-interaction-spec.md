# 13. 批量页交互说明

## 1. 页面目标

批量页的目标不是展示系统复杂度，而是让用户高效完成一轮批量验证。

## 2. 主交互链路

```text
选择配置
  -> 上传素材
  -> 开始批测
  -> 看批次进度
  -> 看结果复核
  -> 导出问题样本
```

## 3. 页面区块交互

### 区块 A：批量配置

交互目标：

- 尽快开始一轮批测

交互要求：

- 关键字段靠前
- 上传区明显
- 开始按钮位置稳定

不建议：

- 把所有规则都写成长文

### 区块 B：执行进度

交互目标：

- 让用户知道这批现在到了哪一步

交互要求：

- 摘要优先于明细
- 失败数、未入库数要醒目
- “刷新 / 停止 / 切换历史批次”清晰可见

### 区块 C：结果复核

交互目标：

- 快速筛出问题样本
- 快速完成满意 / 不满意标记

交互要求：

- 原图和结果图距离近
- 操作按钮贴近图片
- 理由和备注跟在当前结果旁边

### 区块 D：明细排查

交互目标：

- 仅在需要时提供排障

交互要求：

- 默认不抢主视图
- 可折叠或后置

## 4. 页面状态

### 未开始

- 配置区为主
- 进度和复核区为占位说明

### 执行中

- 进度区为主
- 配置区部分锁定
- 复核区弱化

### 已完成

- 复核区为主
- 进度区提供摘要

### 存在失败

- 问题摘要突出
- 允许快速切换到失败样本

## 5. 页面体验原则

### 原则 1：先总览，再细看

用户先看整体批次状态，再决定是否进入单条问题。

### 原则 2：复核优先于排障

批量页首先服务“结果判断”，其次才是“任务排查”。

### 原则 3：导出路径要短

用户发现问题样本后，应尽快导出，不应在明细表里翻很久。

## 6. 批量页交互验收点

1. 用户能快速开始一轮批测
2. 执行中时能一眼看懂批次整体状态
3. 完成后能快速进入复核
4. 不满意标记动作足够短
5. 问题样本导出路径清晰
