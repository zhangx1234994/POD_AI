# 16. 单功能页页面稿 V1

## 1. 页面定位

单功能页是整个测评端最核心的页面。
它不是参数配置页，而是一个**功能体验页**。

## 2. 页面骨架

建议采用固定结构：

1. 顶部功能说明卡
2. 左右双栏主工作区
3. 底部轻量沉淀区
4. 更深信息入口

## 3. 页面稿结构

### A. 顶部功能说明卡

建议内容：

- 功能名
- 一句话用途
- 适合场景
- 不适合场景
- 体验建议

推荐布局：

```text
功能名
一句话用途
适合：...
不适合：...
建议：首次体验建议上传...
```

设计要求：

- 信息压缩
- 不做长文
- 不做复杂说明折叠

### B. 左栏：输入区

这是主操作区。

建议顺序：

1. 素材输入
2. 主要参数
3. 高级参数折叠
4. 开始体验按钮

建议设计细节：

- 上传区第一眼可见
- 主参数控制在第一屏
- 高级参数默认折叠
- CTA 固定在输入区底部，位置稳定

### C. 右栏：结果区

这是主反馈区。

建议顺序：

1. 当前状态卡
2. 最新结果预览
3. 错误解释
4. 结果判断提示

结果判断提示示例：

```text
怎么看这次结果
- 重点看边缘是否干净
- 重点看主体是否完整
- 重点看是否有明显拼接痕迹
```

### D. 底部：轻量沉淀区

建议内容：

- 最近 3 到 5 条记录
- 当前记录的评分
- 当前记录的备注

布局建议：

- 以卡片或简短列表展示
- 不做长表格

### E. 更深信息入口

放在页面较低权重位置：

- 更多历史
- 接口说明
- 开发接入文档

形式建议：

- 折叠区
- 次级标签
- 跳转入口

## 4. 页面主视线

建议用户视线顺序：

```text
先看说明
  -> 看左侧输入
  -> 看右侧结果
  -> 再看底部沉淀
```

这条路径不能被长历史区或长文档打断。

## 5. 页面重点问题修正

当前常见问题：

- 信息堆太多
- 用户进来不知道先看哪
- 结果区不够强

页面稿里应重点修正：

- 说明前置
- 输入和结果同屏
- 历史和文档后置

## 6. 页面稿目标

这版单功能页页面稿要达成：

- 用户一眼看懂这个功能做什么
- 用户第一屏就能开始体验
- 用户能很快看懂这次结果是否正常
