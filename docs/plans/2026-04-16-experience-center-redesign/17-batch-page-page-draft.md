# 17. 批量页页面稿 V1

## 1. 页面定位

批量页是一个**批量验证与复核页**。
它不是任务列表中心，也不是执行器监控页。

## 2. 页面骨架

建议结构：

1. 顶部页面说明
2. 配置区
3. 批次进度区
4. 结果复核区
5. 明细排查区

## 3. 页面稿结构

### A. 顶部页面说明

建议内容：

- 标题：`批量回归`
- 一句话说明：`适合对一批样本做统一验证与问题筛看`

只保留很短说明，不放一大段规则解释。

### B. 配置区

建议内容：

- 工作流选择
- LoRA / 关键参数
- 测试次数
- 输出尺寸策略
- 批量上传图片
- 主 CTA：`开始批测`

布局建议：

- 左侧大表单
- 视觉上保持紧凑
- 上传区明显

### C. 批次进度区

建议内容：

- 当前批次名称 / ID
- 样本数
- 已完成
- 失败
- 未入库
- 刷新 / 停止 / 切换历史批次

设计目标：

- 一眼看懂“这批现在到哪儿了”
- 不先展开每条明细

### D. 结果复核区

这是批量页真正的主区。

建议内容：

- 原图 / 结果图对照
- 满意 / 不满意按钮
- 不满意原因
- 备注
- 导出全部 / 导出不满意

布局建议：

- 图在左，判断在右
- 或图上、判断下
- 但两者必须紧贴

### E. 明细排查区

建议内容：

- 执行明细
- 错误信息
- 排障辅助

建议处理方式：

- 默认折叠
- 放在页面后部

## 4. 页面主视线

建议顺序：

```text
先配批次
  -> 看进度摘要
  -> 看结果复核
  -> 再看明细排查
```

批量页最容易做错的点就是把“明细表”放得太靠前。

## 5. 页面重点问题修正

当前批量页常见问题：

- 说明文字过多
- 任务状态信息抢主视图
- 结果复核不够突出

页面稿里应重点修正：

- 压缩规则说明
- 强化批次摘要
- 把结果复核抬到明细之前

## 6. 页面稿目标

这版批量页页面稿要达成：

- 用户能快速开始一轮批测
- 用户能快速判断这一批总体质量
- 用户能快速筛出问题样本并导出
