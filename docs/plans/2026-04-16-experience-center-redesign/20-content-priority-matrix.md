# 20. 内容优先级矩阵

## 1. 用途

这份矩阵用于避免页面继续“什么都想放”，导致主次混乱。

规则：

- P0：必须第一屏可见
- P1：重要，但可在首屏下半段或第二层
- P2：保留即可，应降权
- P3：不建议放在该页面主路径

## 2. 首页

| 内容 | 优先级 | 说明 |
| --- | --- | --- |
| 功能分类入口 | P0 | 首页第一任务就是让用户选功能。 |
| 高频功能卡 | P0 | 直接进入高频体验。 |
| 一句话用途说明 | P1 | 建立轻认知即可。 |
| 轻提示区 | P1 | 只做辅助，不抢主视图。 |
| 复杂统计 | P2 | 不删，但不应进入主视觉层。 |
| 文档入口 | P2 | 保留轻入口即可。 |
| 历史任务 | P3 | 不应出现在首页主内容区。 |
| 维护配置 | P3 | 不属于首页主路径。 |

## 3. 单功能页

| 内容 | 优先级 | 说明 |
| --- | --- | --- |
| 功能说明 | P0 | 用户先理解用途与场景。 |
| 素材输入 | P0 | 主操作起点。 |
| 主要参数 | P0 | 必须第一屏完成。 |
| 开始体验按钮 | P0 | 位置必须稳定。 |
| 当前状态 | P0 | 体验过程中的关键反馈。 |
| 最新结果预览 | P0 | 结果是页面核心。 |
| 结果判断提示 | P1 | 帮助快速判断。 |
| 轻量历史 | P1 | 保留复盘，但不打断主流程。 |
| 高级参数 | P2 | 折叠处理。 |
| 接口说明 | P2 | 保留但降权。 |
| 长历史列表 | P3 | 不应压到主视图。 |
| 维护说明 | P3 | 不应进入主体验页。 |

## 4. 批量页

| 内容 | 优先级 | 说明 |
| --- | --- | --- |
| 批量配置 | P0 | 发起批测的前提。 |
| 上传入口 | P0 | 高关注度。 |
| 开始批测按钮 | P0 | 主动作。 |
| 批次摘要 | P0 | 必须一眼可见。 |
| 结果复核区 | P0 | 页面真正核心。 |
| 导出动作 | P1 | 复核后的关键动作。 |
| 历史批次切换 | P1 | 保留，但不要压主视图。 |
| 明细排查 | P2 | 仅在需要时查看。 |
| 长规则说明 | P3 | 不应占据页面主区。 |

## 5. 使用方式

后续无论是做 Figma 还是开发实现，都建议先看这张矩阵：

- 如果 P0 内容没进入第一屏，说明页面主次错了
- 如果 P2/P3 内容抢了主视图，说明页面还不够收敛
