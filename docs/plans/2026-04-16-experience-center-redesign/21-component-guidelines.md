# 21. 组件与状态建议

## 1. 用途

这份文档用于统一后续页面稿和高保真设计中的组件行为，避免每个页面都重新发明一套样式和交互。

## 2. 核心组件

### 分类卡

用途：

- 首页功能分类入口

应包含：

- 分类名
- 一句话说明
- 数量
- 快捷功能入口

状态：

- default
- hover
- active

### 功能卡

用途：

- 首页高频功能入口

应包含：

- 功能名
- 一句话用途
- 标签
- 主 CTA

状态：

- default
- hover
- disabled

### 输入卡

用途：

- 单功能页和批量页中的主配置区

建议：

- 保持统一内边距
- 标题清晰
- 字段分组明确

### 结果卡

用途：

- 承载当前状态、结果图、错误说明

建议：

- 比普通信息卡更重要
- 内部图片区占比大
- 状态信息固定在上方

### 轻量历史卡

用途：

- 承载最近记录、评分、备注

建议：

- 不做复杂表格
- 单条信息压缩

## 3. 按钮体系

### 主按钮

只保留在真正关键动作上：

- 开始体验
- 开始批测

### 次按钮

用于：

- 刷新
- 更多历史
- 进入批量页

### 危险按钮

只用于：

- 停止批次
- 删除等不可逆动作

## 4. 状态表现

### 成功

- 清晰但不过量
- 可用轻绿色标记

### 执行中

- 重点是“正在处理”
- 可用橙色 / 黄色强调

### 失败

- 错误信息必须可读
- 只在当前模块高亮，不污染全页

### 空态

- 提供轻说明
- 提供下一步动作

## 5. 统一规则

### 规则 1：能卡片化就不要长表格化

尤其首页和单功能页。

### 规则 2：能局部反馈就不要整页打断

例如单功能提交失败，应先在结果卡反馈，而不是只在全局 toast 提示。

### 规则 3：主操作必须稳定

同类页面的主按钮位置尽量固定，减少用户重新找按钮。

## 6. 开发实现时需要注意

- 不要为了复用旧区块，把已经降权的内容重新抬回主视图
- 先保证页面主路径成立，再考虑把旧信息补回
- 如果组件复用会破坏主次，宁可先做轻量变体
