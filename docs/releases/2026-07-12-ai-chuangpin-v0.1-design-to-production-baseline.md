# AI创品 v0.1 设计到生产内测基线

日期：2026-07-12
状态：内测可验收，不是公开商业版

## 版本目标

验证 AI创品 最小但真实的设计生产链路：用户素材不直接作为供应商生产文件；中台按产品规格生成生产图、执行预检、保存 OSS 证据；平台订单支付后由运营核对，确认后才推送蜂鸟。

品牌口径：**AI创品，有品，不必一样。** 本版本只验证“把一份表达安全地变成可生产订单”，不把临时页面预览或供应商未回传数据包装成真实履约结果。

## 已完成范围

1. 生产画布与预检
   - `cover`、`tile`、`seamless` 三种合成模式均在中台执行。
   - 生产文件按产品表的目标像素和 DPI 保存到自有 OSS。
   - 生产前校验像素、DPI、格式；失败不允许推供应链。
2. 订单状态机与证据
   - 状态顺序：`awaiting_payment -> ops_review -> submitted_to_supplier`。
   - 保存生产文件、预检结果、平台订单号、运营操作事件、蜂鸟订单号及安全响应摘要。
   - 客户端只能创建和读取自己的订单；蜂鸟凭证只存在中台受控配置。
3. 蜂鸟真实联调
   - 已验证一个 CN 地址的受控订单被蜂鸟接收。
   - 受控参数：`10167 / OneSize / white / firstCraft=17 / secondCraft=2`。
   - 未验收的模板、颜色、工艺会被 `FENGNIAO_TEMPLATE_NOT_VERIFIED` 阻断，禁止猜参数下单。
4. 前端与运营入口
   - 登录后的业务端订单页读取 `/api/client/production-orders` 真源，不再填充示例订单。
   - 业务端仅对受控已验收杯型开放“创建待支付订单”；创建时必须填写收货信息。
   - 运营端新增“生产订单”表格：核对生产图/预检、受控测试代付、运营确认推蜂鸟、同步蜂鸟回传。
   - 商品端只展示 32 款具备完整设计尺寸的杯型；模板号、主体编码和缺尺寸商品不再暴露给用户。
   - 业务端品牌统一为“AI创品 / 有品，不必一样”；已完成桌面与移动端线上截图复核，浏览器控制台无错误。

## 本次验收证据

| 环节 | 结果 |
| --- | --- |
| 生产画布 | 真实生产文件为 `2717 x 1772 px / 150 DPI / PNG`，预检通过。 |
| 平台订单 | 生成待支付订单，受控支付后进入运营核对。 |
| 蜂鸟下单 | 成功返回供应商订单号；平台订单和供应商订单均可在运营端追溯。 |
| 蜂鸟查询 | 可查询订单明细与订单级状态字段；本次尚未返回效果图或运单。 |
| 自动化 | `backend/tests/test_production_orders.py` 通过；业务端与运营端 TypeScript 类型检查通过。 |
| 页面验收 | 线上客户端 `/`、`/products` 和运营端 `/admin/` 均可达；移动端商品列表无横向溢出。 |

## 明确未完成，不得对外承诺

1. 微信支付尚未接入，运营端“测试代付”只用于受控验收，正式支付必须由支付回调改写订单状态。
2. 订单金额、商品售价、订单级物流成本、产品券抵扣尚未进入真实结算。
3. 当前只有一个蜂鸟模板参数组合经过成功验收；其他商品即使有尺寸或模型，也不能直接推单。
4. 蜂鸟查询本次没有返回效果图、物流或完整生产状态；中台已支持同步和 OSS 归档，但需补供应商回调或确认查询字段。
5. 商品页的页面预览不等于供应商效果图；供应商回传效果图只能在真实收到后展示。
6. 未完成全量商品的定价、工艺、颜色、设计面、安全区和真实样例验收。
7. 数据库迁移需要建立干净的 Alembic 基线；当前内测库已通过建表保证生产订单表存在，不能长期替代迁移治理。
8. 业务端当前主构建包约 277KB gzip；不阻断内测，但 v0.2 需按路由拆包并复测首屏加载。

## v0.2 准入条件

1. 微信支付 Native/H5 回调验签、幂等、金额核对和订单状态回归通过。
2. 运营端商品售价、订单级物流成本、产品券规则写入真实订单金额。
3. 蜂鸟效果图、生产、物流回传至少有一个可验证渠道，并将外链归档到 OSS。
4. 至少 3 个模板完成“工艺/颜色/生产文件/蜂鸟接收”成功矩阵。
5. 业务端、运营端分别完成桌面和移动端真实订单走查，不保留误导性的模拟成功状态。
