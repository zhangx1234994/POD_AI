# 业务能力线上状态口径

本文固定 v0.6 收口阶段的展示口径，避免把“能调用”“可推荐”“已验收”“可封版”混成一个标签。

## 1. 两类状态必须分开

业务能力、业务版本和模型目录都必须至少区分两件事：

- **线上状态**：当前版本是否已经能被线上链路稳定调用。
- **推荐状态**：当前版本是否适合作为默认入口、生产推荐或封版依据。

不能只用 `可上线`、`待确认`、`待上线` 一类笼统文案覆盖所有场景。

## 2. 线上状态

| 状态 | 使用条件 | 说明 |
| --- | --- | --- |
| `线上可用` | 启用版本已有真实成功输出，且没有明显阻塞项 | 表示用户或业务方可以继续按当前入口调用。 |
| `受限可用` | 已有成功输出，但仍有验收、治理、回填、计费或近期失败风险 | 表示能跑通，但需要在页面上同步暴露限制和下一步。 |
| `线上待验证` | 默认版本已启用，但缺最近成功输出 | 表示入口存在，封版或对外说明前必须跑真实样本。 |
| `候选验证` | 草稿、候选或非默认版本，尚未完成真实链路证据 | 表示只能试运行，不承接默认业务请求。 |
| `不可用` | 缺主能力、治理阻塞、门禁阻塞且无成功输出 | 表示不能作为业务入口。 |
| `已下线` | 停用、废弃、归档版本 | 只保留追溯、对照或回滚说明。 |

## 3. 推荐状态

| 状态 | 使用条件 | 说明 |
| --- | --- | --- |
| `生产推荐` | 默认入口、验收、真实输出、回填计费和回滚证据齐全 | 可作为管理端主推荐和封版证据。 |
| `灰度可用` | 有成功输出和验收记录，但仍缺回滚、安全垫或其他非阻断证据 | 可小流量使用，不宜直接当成最终生产推荐。 |
| `备选可用` | 非默认版本有成功输出和验收记录 | 可用于回滚、对照或灰度。 |
| `待补验收` | 已有真实成功样本，但缺验收通过记录 | 页面必须提示补证据，而不是显示成“未上线”。 |
| `需复核` | 存在阻塞、失败、治理或切换风险 | 需要先定位和确认，再决定是否推荐。 |
| `历史版本` | 已下线或被替代版本 | 不推荐，只用于追溯和回滚说明。 |

## 4. 页面规则

- 总览页和业务页优先展示 `线上状态 + 推荐状态`，再展示门禁、验收、样本、回滚等证据。
- 模型目录只表达模型是否 `生产可用` 或 `不可推荐`，不能替代业务版本推荐结论或平台发版结论。
- 平台发布登记、发版 SOP 或明确的人工封版动作使用 `可发版` / `暂缓发版` / `阻塞发版`，不要和业务能力的线上状态混用。
- 如果某功能已有成功样本但缺验收，页面应显示 `线上可用 / 待补验收` 或 `受限可用 / 待补验收`。
- 如果某功能只在本地或候选路径跑通，不得显示 `线上可用`。
