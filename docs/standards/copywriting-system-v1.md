# 文案系统 V1（任务 / 结果 / 错误）

> 目标：让管理端、评测端、文档三处用同一套语言，减少“状态理解偏差”与“排障沟通成本”。

## 1. 统一规则

1. 同一概念只使用一个词：提交阶段 / 回调阶段 / 最终状态。
2. 错误提示必须三段式：`发生了什么 + 为什么 + 下一步`。
3. 所有错误提示必须保留机器错误码（便于排障）。
4. 空状态必须给出动作建议，不能只显示“暂无数据”。

## 2. 状态文案模板（任务链路）

### 2.1 提交阶段
- `待提交`：任务已创建，等待提交到执行节点。
- `提交中`：任务正在发送到执行节点，请稍候。
- `提交失败`：任务提交失败（{error_code}），请检查节点可用性后重试。
- `已提交`：任务已提交成功，等待回调结果。

### 2.2 回调阶段
- `待回调`：任务已提交，等待执行平台回传结果。
- `回调中`：已收到执行进度，正在写入结果。
- `回调失败`：回调处理失败（{error_code}），可在任务事件查看明细。
- `回调成功`：回调处理完成，结果可读取。

### 2.3 最终状态
- `进行中`：任务尚未完成，请继续等待。
- `成功`：任务完成，结果已可用。
- `失败`：任务失败（{error_code}），请按建议动作处理。
- `已取消`：任务已取消，不再继续处理。

## 3. 错误文案模板（必须带建议动作）

| 场景 | 文案模板 | 建议动作 |
| --- | --- | --- |
| 参数错误 | 请求参数不完整（{error_code}）：{field} 缺失。 | 检查必填字段并重新提交。 |
| 执行节点不可达 | 执行节点暂时不可用（{error_code}）。 | 到“执行节点”检查状态或切换节点。 |
| 队列拥塞 | 当前队列已满（{error_code}）。 | 稍后重试或切换空闲节点。 |
| 回调超时 | 回调超时（{error_code}），任务仍可能在执行。 | 在任务列表继续观察，不要重复提交。 |
| 结果回填失败 | 结果回填失败（{error_code}）。 | 打开任务事件查看失败步骤并重试回填。 |

## 4. 空状态文案模板

| 场景 | 文案模板 |
| --- | --- |
| 无数据（初始） | 还没有数据，先创建第一条任务开始验证。 |
| 筛选后为空 | 当前筛选条件下无结果，可放宽筛选后重试。 |
| 功能未配置 | 当前功能尚未配置完成，请先完成基础配置。 |
| 权限受限（内部系统可选） | 当前账号无访问权限，请联系管理员开通。 |

## 5. 前端渲染约束

1. 列表页状态列统一显示三个状态：提交 / 回调 / 最终。
2. 错误提示区必须展示：
   - 中文可读文案
   - 原始 `error_code`
   - 可点击“查看详情/事件”入口
3. 导出 CSV 必须包含 `submit_status/callback_status/final_status/error_code/error_message`。

## 6. 验收清单

- [ ] 管理端与评测端均使用统一状态词。
- [ ] 高风险错误（节点不可达/队列满/回调超时）有统一提示模板。
- [ ] 空状态文案不再出现“只有暂无数据、无动作建议”。
- [ ] 文档与页面术语保持一致（提交/回调/最终）。
