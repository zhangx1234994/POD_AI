# 能力测评端交互状态模型

日期：2026-06-07

适用范围：`podi-eval-web` 的能力分类首页、能力工作台、AI 改图助手、直接图编辑、任务追踪和业务接入文档区。

本文是 v0.6 收口阶段的交互治理标准。后续测评端页面改动必须先对齐本状态模型，再做视觉细节。

## 1. 定位

测评端不是客户端，也不是管理端。它的职责是让内部业务方、运营、运维和能力工程师用同一套入口验证能力是否可用、效果是否可推荐、失败是否可排查。

测评端围绕能力组织信息，不围绕项目、工作单或客户端业务流程组织信息。

### 目标

- 业务方第一次进入时能判断用哪个能力、传什么、结果在哪里、失败后怎么办。
- 运营能看到样例、质量标签、近期成功和推荐版本。
- 运维能看到 runId、taskId、错误码、节点、队列和排障入口。
- 能力工程师能看到版本、参数、workflow/model/LoRA、路由证据和回滚线索。

### 非目标

- 不做客户端项目流、素材夹、订单流或工作单。
- 不把辅助工具做成业务方主入口。
- 不用大段文字解释代替明确状态和操作。
- 不把 Agent 对话改图做成直接图编辑的内部模式。

## 2. 页面层级

### 2.1 分类首页

默认顺序固定为：

1. 当前分类判断条：当前分类、推荐状态、固定样例数、近 72 小时成功数、任务追踪。
2. 样例起步：有固定样例展示真实样例图；无固定样例展示轻量图例和可点击意图。
3. 推荐入口：业务方最可能要跑的能力或版本。
4. 版本列表：默认可见，不折叠；用于指定版本、候选版本、回滚和底层链路确认。
5. 辅助能力导航：紧凑展示，只服务排障、自检和补充验证，不抢主路径。

禁止把无关分类、旧项目主语、历史工具卡片放在当前分类首屏主路径里。

### 2.2 能力工作台

默认结构固定为：

1. 输入区：主图/文本/参数，必填项靠前。
2. 当前对象区：用户上传或选择的主图必须立即可见。
3. 执行动作区：提交、刷新、重试、任务追踪。
4. 状态与结果区：排队、执行、成功、失败必须在当前操作流里可见。
5. 历史与复盘区：最近任务、固定样例、质量记录。
6. 排障区：默认折叠，保留 runId、taskId、执行节点、错误码、原始摘要。

结果不能沉到底部，也不能只出现在全局历史列表里。用户在哪发起任务，结果就应该优先回到哪里。

### 2.3 Agent 类工作台

AI 改图助手按“图片版 AI 助手”设计，不按表单任务设计。

固定规则：

- 一个新改图任务对应一条会话线程。
- 当前基准图必须可见，并标明是主图、上一轮结果还是历史结果。
- 用户消息、助手建议、执行状态、结果图都在消息流中出现。
- 二轮继续输入时默认基于最新成功输出。
- 点击“新建”后进入新会话，但旧线程必须能从历史恢复。
- 模糊意图必须追问或阻断，不能直接执行。
- 方案建议可以有结构化计划，但不能要求用户先选择硬分类才能表达自然语言意图。
- 执行结果气泡必须包含状态、结果图、runId 或排障编号。

AI 改图助手可以暂时归在“图编辑”分类下用于发现，但不是直接图编辑的模式，也不是可视化画布编辑器的子功能。

## 3. 全局状态模型

| 状态 | 用户应该看到 | 允许动作 | 禁止做法 |
| --- | --- | --- | --- |
| 首次进入 | 当前分类、推荐入口、样例或图例、版本列表、辅助导航 | 打开推荐版本、使用样例、查看版本、任务追踪 | 首屏堆无关分类、只展示技术版本、用说明文字替代入口 |
| 目录加载中 | 骨架屏或轻量加载提示 | 等待、刷新 | 空白大屏、按钮可点但无反馈 |
| 目录加载失败 | 可读错误、错误码、刷新按钮、排障详情 | 刷新、复制错误、任务追踪 | 只显示 `Failed to fetch` 或吞掉错误 |
| 无固定样例 | 轻量图例、意图示例、推荐入口 | 点击意图进入工作台 | 把硬编码示例塞进输入框让用户删除 |
| 输入未完成 | 主图占位、必填项、缺失提示 | 上传/粘贴主图、填写必填项 | 提交按钮可用但后端报缺参 |
| 图片已上传 | 图片预览、尺寸/来源、可替换入口 | 提交、替换、打开大图 | 上传后页面看不到图片 |
| 提交中 | 当前任务正在提交、按钮 loading、防重复提交 | 等待、取消输入编辑 | 重复创建 run、无状态反馈 |
| 已排队 | runId、队列/等待状态、刷新节奏 | 自动轮询、任务追踪 | 让用户不知道是否开始工作 |
| 执行中 | 已等待时长、执行状态、结果占位 | 自动轮询、查看任务追踪 | 状态只在隐藏日志里出现 |
| 成功有结果 | 结果图/视频/文本、复制链接、查看大图、继续操作 | 继续改图、对比、质量标记、复制结果 | 结果只在底部历史或另一个页面出现 |
| 成功无可见结果 | “结果回填中”或“成功但无结果”、刷新、排障编号 | 刷新、任务追踪、上报 runId | 显示为空白或 `—`，让用户以为成功 |
| 失败 | 可读错误、错误码、下一步动作、是否可重试 | 安全重试、复制排障信息、任务追踪 | 只显示原始 traceback、丢失错误码 |
| 历史恢复 | 历史线程/任务、当前基准图、最近结果 | 继续、复制、打开历史 | 新任务覆盖旧历史、恢复后上下文不清 |
| 排障展开 | runId、taskId、节点、版本、错误码、原始摘要 | 复制、跳转任务追踪 | 默认把排障字段压住主路径 |

## 4. 关键能力路径

### 4.1 图编辑分类首页

- 顶部必须明确两个独立入口：AI 改图助手、直接图编辑。
- AI 改图助手适合目标不清、需要讨论、多轮追改。
- 直接图编辑适合用户已知道哪里要改、需要上传主图、标注区域、提交任务。
- 版本列表保持可见，推荐版本保持主注意力。
- 辅助能力只保留紧凑导航，不作为业务方主入口。

### 4.2 AI 改图助手

- 首屏主任务是“添加主图并开始对话”，不是选择技术分类。
- 对话输入框只放占位提示，不预填必须删除的硬文字。
- 发送消息后必须出现正在思考/整理建议的状态。
- 确认执行后必须出现工具执行气泡。
- 出图中必须展示等待时长。
- 出图成功后结果图进入消息流；继续输入默认基于该结果。
- 新建任务必须清晰提示会开启新线程，不污染旧上下文。

### 4.3 直接图编辑

- 上传后主图必须可见。
- 标注/参考图/提示词/执行按钮围绕图片组织。
- 结果图和原图对比入口必须靠近当前任务。
- 中间画布、mask、模型原始输出只放排障区，不作为业务轻量结果。

### 4.4 花纹提取

- 首屏必须告诉用户这是从原图提取可复用花纹资产。
- 固定样例优先展示花纹类输入，不用纯技术 workflow 名称做主标题。
- 成功结果优先展示提取结果图，并提供复制 URL、查看大图、进入任务追踪。
- 失败时优先区分图片不可访问、队列/节点、模型失败、OSS 回填失败。

### 4.5 产品设计

- 首屏必须说明输入素材/花纹、产品类型、场景或设计 brief。
- 固定样例至少覆盖服装、家纺、箱包、包装、电商主图。
- 结果需要保留质量标记入口：可推荐、候选、需优化、失败。
- 若能力或样例未达推荐门槛，不得在主路径上伪装成稳定推荐能力。

## 5. 错误与恢复

错误展示固定三层：

1. 人能看懂的主提示。
2. 标准错误码。
3. 折叠排障详情。

高频错误处理：

| 错误 | 页面口径 | 动作 |
| --- | --- | --- |
| `Q1001 / COMFYUI_QUEUE_FULL` | 队列已满 | 等待或稍后重试，不重复快速提交 |
| `Q1002 / COMFYUI_EXECUTOR_UNAVAILABLE` | 没有可用执行节点 | 短时网络波动可重试一次；持续出现时联系中台检查节点和路由 |
| `TASK_TIMEOUT` | 等待超时 | 刷新任务结果；必要时打开任务追踪 |
| `BUSINESS_RUN_GET_FAILED` | 查询临时异常 | 稍后刷新，不立即判定生图失败 |
| `AGENT_PLAN_REQUIRES_CLARIFICATION` | 目标不够明确 | 继续对话补充要改哪里、保留什么、希望变成什么 |

提交成功判断必须遵循接口契约：HTTP 2xx、真实 `runId/taskId`、`queued/running` 状态、无 `ERR|...`、无 `errorCode`。否则页面不能进入正常“等待结果”状态。

## 6. 六顶思考帽评审

每次测评端核心页面整改，至少用以下六个视角自检：

| 思考帽 | 问题 |
| --- | --- |
| 白帽 | 当前页面有哪些事实数据、状态、runId、样例、错误码？ |
| 红帽 | 用户第一眼会不会焦虑、迷路、不知道是否在工作？ |
| 黑帽 | 哪些地方会误导用户提交错任务、误判成功、丢失历史？ |
| 黄帽 | 哪些设计能提升效率、复用样例、减少沟通成本？ |
| 绿帽 | 是否有更少、更清楚的表达方式？ |
| 蓝帽 | 当前页面主任务、次任务、排障任务的层级是否稳定？ |

评审结论必须写清：删掉什么、保留什么、折叠什么、上移什么。

## 7. 页面改动验收清单

改动测评端页面时，至少检查：

- 当前分类首屏只展示相关能力。
- 样例或图例常显。
- 推荐入口清楚。
- 版本列表默认可见。
- 辅助能力紧凑且不抢主路径。
- 上传后主图可见。
- 提交后有明确状态。
- 排队/执行/成功/失败都在当前操作流里。
- 成功结果有图、有链接、有下一步动作。
- 失败结果有错误码、有可读提示、有排障编号。
- 历史任务可恢复，不被新任务覆盖。
- Agent 结果在消息流里，不沉到底部。
- 排障信息默认折叠但可复制。
- 移动端不出现文字重叠、按钮溢出或结果不可见。

## 9. 执行顺序

1. 先用本模型审查图编辑分类首页。
2. 再审查 AI 改图助手。
3. 再审查直接图编辑工作台。
4. 再审查花纹提取。
5. 再审查产品设计。
6. 每条路径都必须用浏览器模拟用户操作，不只看截图。
