# 版本开工与封版验收模板

最后更新：2026-06-05

本文是每个新版本开工前必须复制填写的模板。它补充 `docs/standards/release-sop.md`，解决“先开发、后补验收标准”导致的漏测问题。

使用规则：

- 新版本或补丁开始前，先在唯一 TODO 或版本方案中贴入本模板并填完“开工验收标准”。
- 版本封版前，按同一模板补齐“封版验收记录”。
- 如果某项不适用，写明“不适用原因”；不能删除。
- 如果用户要求真实业务全链路测试，成本不作为跳过理由。

## 3. 角色视角验收

每个版本至少从四类视角过一遍，不允许只按开发视角验收。

| 视角 | 必走路径 | 一眼要看到什么 | 不能出现什么 |
| --- | --- | --- | --- |
| 业务方 | 进入测评端或业务入口 -> 选择能力 -> 上传/输入 -> 提交 -> 看结果 | 选哪个能力、传什么、结果在哪里、失败怎么处理 | 无关模块占首屏、项目主语混入中台、结果沉底不可见 |
| 运营 | 查看固定样例、质量标签、成功率、失败类型、复盘入口 | 当前效果好不好、哪类图差、下一步优化动作 | 只有 runId，没有质量结论 |
| 运维 | 查看路由、节点、队列、错误聚合、日志线索 | 哪台机器、哪个能力、哪个队列、是否可恢复 | 只显示“失败”，没有节点和错误码 |
| 能力工程师 | 查看版本、参数、workflow/model/LoRA、路由证据、回滚口径 | 能改哪里、如何验证、如何回滚 | 参数散落在前端或文档里，无法追溯 |

## 4. 响应速度与并发标准

默认阈值如下；如果版本有特殊情况，必须在开工前改写并说明原因。

| 类型 | 默认标准 | 本版标准 | 证据路径 |
| --- | --- | --- | --- |
| `/health` | p95 <= 300ms |  |  |
| 高频只读接口 | p95 <= 1500ms |  |  |
| 控制面 20 并发只读 | 成功率 100%，p95 <= 3000ms |  |  |
| 业务提交接口 | p95 <= 3000ms，不含模型运行时长 |  |  |
| 业务查询/轮询接口 | p95 <= 1000ms |  |  |
| 业务真实并发 | 3-5 并发真实任务，按影响面决定 |  |  |

必须记录 loopback 与公网差异；loopback 用于判断服务端处理耗时，公网用于观察链路风险。

## 6. Agent Runtime 回归

如果版本触碰 Agent、AI 图片助手、路由、planner、上下文、执行边界或工具调用，必须执行 `docs/standards/agent-runtime-regression-matrix.md`。

最低门槛：

- 首轮真实执行成功。
- 二轮续改默认基于上一轮成功输出。
- 新任务隔离，不污染旧会话。
- 模糊意图必须追问或阻断，不能乱执行。
- 消息与执行边界幂等。
- 每次执行可见 `routeReason/confidence/baseImageRole/parentRunId`。
- 预期 4xx 必须在封版报告中标注，不得误判为异常 4xx。

## 7. 错误路径与副作用

新增或修改接口必须列出错误路径、错误码和副作用检查。

| 错误场景 | 期望 HTTP | 错误码 | 是否创建 run/步骤/计费 | 页面提示 | 测试证据 |
| --- | ---: | --- | --- | --- | --- |
| 缺少必填字段 | 400/422 |  | 否 |  |  |
| 鉴权失败 | 401/403 |  | 否 |  |  |
| 依赖失败 | 502/503 |  | 视业务定义 |  |  |
| 超时 | 504/业务错误 |  | 视业务定义 |  |  |
| 队列满/并发限制 | 429/业务错误 |  | 否或可恢复 |  |  |
| 低置信追问 | 409/业务错误 |  | 否 |  |  |

必须同步：

- `docs/standards/error-catalog.md`
- `docs/standards/error-contract.md`
- `docs/standards/interface-consistency.md`
- 对应 `docs/api/modules/*.md`

## 8. 页面与交互走查

如果版本涉及前端，必须用真实浏览器检查静态产物，不允许只看 dev server。

测评端页面必须先按 `docs/standards/eval-ability-interaction-state-model.md` 复核状态模型，再做视觉判断。

| 页面 | 角色视角 | 必走路径 | 结果 | 截图/记录 |
| --- | --- | --- | --- | --- |
| 管理端 8199 | 运维/能力工程师 | 登录 -> 业务能力 -> 接口调用 -> 任务详情 |  |  |
| 测评端 8200 | 业务方/运营 | 分类 -> 能力 -> 上传/输入 -> 提交 -> 结果 |  |  |

正式线上端口以 114 的 `8199/8200` 为准；如果本地为了避开端口占用使用 `8299` 等临时端口，必须在记录里标明“本地临时端口”，不能写成线上口径。

通用交互要求：

- 主路径首屏只展示当前分类相关内容。
- 推荐版本区域保持主注意力，版本列表默认可见。
- 辅助工具有独立导航，但不得抢业务方主路径。
- 首次使用必须有样例或图例，不靠大段硬文字解释。
- 结果图片、状态和错误必须出现在用户当前操作流里。
- 上传后主图必须可见；提交后必须有排队/执行/成功/失败状态；Agent 类结果必须回到消息流。
