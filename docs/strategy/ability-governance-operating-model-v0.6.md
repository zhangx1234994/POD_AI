# v0.6 能力优先治理模型

最后更新：2026-06-03

本文用于纠正 v0.6 方案和客户端交接中的视角偏差：中台的第一对象是**能力**，不是项目。能力定义以 `docs/strategy/ability-definition-v0.6.md` 为准；调用上下文、资产、选择和交付证据只服务于能力调用追踪，不能反向成为中台产品主视角。

## 1. 核心判断

- 中台要解决的是能力管理得好、封装得好、可优化、可迭代、可控。
- 客户端要解决的是把能力组织成用户可理解、可操作的业务动线。
- 多次能力调用的输入、输出、选择和交付结果只作为调用证据串联。
- 管理端优先围绕能力治理组织信息，再下钻到 run、调用上下文、资产和错误。
- 测评端优先围绕能力效果和版本对照组织信息，不围绕客户端项目流组织。

## 2. 中台核心对象顺序

建议所有 v0.6 讨论按以下对象顺序展开：

1. `BusinessCapability`：对外业务能力，例如花纹提取、图裂变、产品设计图、模特图、推广视频。
2. `BusinessCapabilityVersion`：能力版本和配方，包含默认版本、候选版本、回滚版本。
3. `AbilityBinding / RoutePolicy`：能力到原子能力、workflow、executor、LoRA、模型和第三方 API 的绑定。
4. `BusinessRun`：一次能力调用，是排障和状态追踪主键。
5. `BusinessRunStep / AbilityLog`：能力内部步骤、原子调用、上游响应、回填、成本和错误。
6. `BusinessOutputReview / QualitySample / QualityActionRule`：能力效果复盘、样例、问题标签、优化动作。
7. `InvocationContext / Asset / Selection / DeliveryEvidence`：能力调用产生的资产和交付证据。

调用上下文排在最后，不是因为不重要，而是因为它是证据索引，不能替代能力治理。

## 3. 能力生命周期

每个业务能力都应该进入同一套生命周期：

1. 接入：定义业务输入输出、错误码、默认参数和结果资产类型。
2. 封装：隐藏底层模型、workflow、节点、LoRA、Key 和厂商差异。
3. 验证：用固定样例、测评端、管理端能力测试和真实业务样本验证。
4. 发布：设置默认版本、灰度版本、回滚版本、路由策略和并发限制。
5. 观察：持续看成功率、失败类型、耗时、成本、输出质量和用户选择。
6. 优化：按问题类型分流、换模型、换 LoRA、改提示词、调 workflow 或降级。
7. 回滚：当质量或稳定性下降时，能回到上一个可用版本并保留证据。

## 4. 管理端信息架构原则

管理端 v0.6 后续页面应按能力优先组织：

- 能力总览：每个能力的默认版本、可用性、近窗口调用量、成功率、成本和最近风险。
- 能力详情：版本、路由、执行节点、参数、质量样例、问题标签、优化动作和回滚口径。
- 调用证据：从能力下钻到 runId、步骤、AbilityLog、OSS 结果和错误。
- 上下文证据：作为能力调用的聚合视图，展示某个客户端工作单或业务上下文下发生了哪些能力调用。
- 质量复盘：按能力和版本聚合，不先按项目聚合。

上下文观察入口可以保留，但它是管理端排障和交付追踪的下钻视图，不是首页主导航，也不是 v0.6 主验收。

落地记录：

- 2026-06-02：管理端“业务能力”模块新增默认页签“能力治理”，按业务能力聚合默认版本、候选/回滚、近窗口调用、质量风险、成本、门禁证据和当前动作；原审批、版本对比、回滚和操作日志保留在“变更治理”。

## 5. 客户端边界口径

客户端可以有工作单、项目、素材夹或订单概念，但这些属于客户端业务组装。面向用户时应优先表达“要完成哪个生产动作”：

- 提取花纹。
- 生成裂变候选。
- 扩展画面。
- 编辑图片。
- 生成产品设计图。
- 生成多角度组图。
- 生成模特图。
- 生成推广视频。
- 打包交付。

客户端调用中台时可以传 `clientContextId`、兼容 `projectId`、`flowStepKey`、`inputAssetIds`，但这些字段只是上下文和证据。客户端不应该把兼容上下文 API 当成自己的产品核心，也不应该绕过业务能力 API 直接调用原子能力。

## 6. 文档评审检查项

后续任何 v0.6 文档、交接包或页面方案如果出现以下倾向，需要退回修改：

- 把“项目管理”写成中台第一卖点。
- 只描述上下文、资产和交付包，没有描述能力版本、路由、质量和回滚。
- 让客户端选择 executor、workflow、LoRA、模型或厂商。
- 让管理端上下文视图取代能力治理视图。
- 让测评端围绕客户端流程而不是能力效果验证组织。

正确口径是：**能力是中台产品；项目/工作单是客户端概念；中台只保存必要调用上下文和证据。**
