# 认证方案选型结论（2026Q2）

> 对应待办：`docs/strategy/todo-master-2026q2.md`（本周执行单 3）。  
> 目标：先给出 Q2 可落地方案，保证“上线可用 + 可扩展”。

## 1. 结论（建议执行）

Q2 采用：**邮箱 + 密码 + 邀请码** 方案，手机号登录延期到 Q3。

理由：
1. 当前系统是内部/半内部业务，邀请码可控，开通链路最短。
2. 邮箱链路实现成本低，不引入短信供应商与发送风控复杂度。
3. 与后续团队协作/账单通知天然兼容（邮箱可作为通知主通道）。

## 2. 方案边界

### Q2 内必须做
- 邮箱注册、邮箱登录、密码重置（管理员触发或邮件链路二选一）
- 邀请码生成与失效（一次性/时效）
- 会话管理（登录、续期、登出、踢出）
- 基础角色：`owner/member/admin`

### Q2 不做
- 手机号验证码登录
- 第三方 OAuth（微信/企业微信/Google）
- 多租户组织树与细粒度 RBAC

## 3. 接口最小集合（草案）

1. `POST /api/auth/register`（邮箱 + 密码 + 邀请码）
2. `POST /api/auth/login`
3. `POST /api/auth/logout`
4. `POST /api/auth/refresh`
5. `POST /api/auth/invite-codes`（管理端）
6. `GET /api/auth/sessions`（当前账号会话管理）

## 4. 风险与缓解

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 邀请码泄漏 | 被非目标用户注册 | 邀请码短时效 + 单次使用 + 操作日志 |
| 弱密码 | 安全风险 | 密码强度校验 + 登录失败限流 |
| 会话滥用 | 多地并发登录不可控 | 会话列表 + 主动踢出 + 强制过期 |

## 5. 里程碑

1. M1：完成数据模型与迁移（users/sessions/roles/invite_codes）
2. M2：完成接口与管理端入口
3. M3：灰度发布 + 风险回归（登录失败、邀请码失效、会话续期）
