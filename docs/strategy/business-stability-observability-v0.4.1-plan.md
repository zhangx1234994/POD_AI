# v0.4.1 稳定性监控与管理端降噪方案

最后更新：2026-05-26

## 1. 版本定位

v0.4.0 已完成业务编排工作台产品化封版。v0.4.1 不扩大业务能力范围，重点处理上线后的稳定性、监控、发版门禁和页面可读性。

本版本名称：**稳定性监控与管理端降噪版**。

## 2. 必做范围

1. 稳定性监控
   - 连接池、后台线程、健康看板、ComfyUI 队列、OSS 回填纳入固定观察。
   - 发布 smoke 扫描近期 backend 日志，出现 `QueuePool` 或业务 finalize loop 错误时阻断。
   - health-watch 和 live patrol 的观察窗口明确记录结论。

2. 连接池与后台线程治理
   - 后端数据库连接池使用显式配置，不再依赖 SQLAlchemy 默认值。
   - 请求路径和指标路径不得隐式创建会启动后台线程的 service。
   - 后续继续评估将 finalize/worker 从 web 进程拆出。

3. ComfyUI 状态收敛
   - 处理“中台 running 但 ComfyUI 队列为空”的残留诊断。
   - 对 running 过久任务增加补偿检查：history 查询、OSS 回填、失败标记或人工复核。
   - 158/233 节点同构检查继续留在发版门禁。

4. 管理端视觉与文案降噪
   - 首页优先展示“是否可用、异常在哪、下一步动作”。
   - 业务能力页减少技术字段直出，优先展示业务入口、默认版本、最近运行和风险状态。
   - 接口调用中心继续以 runId 为主线组织提交、轮询、回调、结果和错误。
   - ComfyUI 资源页突出节点健康、队列、路由证据和异常任务。

## 3. 不做范围

1. 不新增大业务能力。
2. 不做完整低代码编排器。
3. 不重构客户端。
4. 不为单台 GPU 写业务特判；节点差异通过同构、标签和健康门禁处理。

## 4. 验收标准

1. 发布 smoke 能发现近期连接池和 finalize loop 回归。
2. 114 线上 backend 线程数、DB 连接池错误、业务 failed/running/queued/unresolved 可被固定观察。
3. business live patrol 和 eval production patrol 能作为封版后观察证据。
4. 管理端核心页面能用业务语言判断当前是否可用、异常位置和下一步动作。
5. v0.4.1 发版记录中明确已覆盖的监控项、页面走查项和剩余风险。
