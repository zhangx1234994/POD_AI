# 市场端 AI 能力规划（2026-06-11）

## 背景

本轮参考旧项目 `/Volumes/MAC 1/shipin/` 的 AI 摄影棚形态，重点吸收其中的商品棚拍组图、模特精修、多角度展品、讲解视频和 15 秒短片方法论。旧项目的价值不在于直接迁移代码，而在于它已经把“市场端素材交付”拆成了可理解的业务工坊和工作台。

PODI 前一阶段主要围绕生产侧能力建设：花纹提取、裂变、扩图、产品设计、图编辑。这些能力服务于“把设计和素材生产出来”。下半年方向需要向市场端靠：产品生产完成之后，围绕上架、详情页、广告、社媒、视频和投放，提供可复核、可生成、可追踪、可迭代的 AI 能力。

## 边界定义

### 生产端能力

生产端解决“产品和素材从无到有”的问题：

- 花纹提取：从参考图得到可用图案。
- 图裂变：扩展花纹/图案变体。
- 扩图：改变画布或补全场景。
- 产品设计：把图案应用到产品上。
- 可视化图编辑：对图片局部或整体做明确编辑。
- 对话式改图：长期归属 Agent Runtime，可临时放在图编辑下，但必须和画布编辑拆开。

### 市场端能力

市场端解决“产品生产后如何卖”的问题：

- 产品文案：上架标题、五点描述、详情页介绍、广告短文案、关键词、平台化表达。
- 产品组图：主图、白底图、细节图、场景图、卖点图、社媒封面、活动图。
- 模特/穿搭/使用场景图：服饰、配件、家居、宠物、礼品等需要人体或生活场景的展示。
- 多角度/多视图图：正侧背、局部细节、包装/尺寸、材质特写。
- 产品视频：商品展示、详情讲解、社媒广告、15 秒短片、多段合成、首尾帧控制。
- 营销内容包：文案 + 图 + 视频 + 渠道建议 + 审核提示 + 下载交付包。

中台仍然只管理能力、能力版本、路由、调用、结果、质量、成本、错误、证据和审计。完整业务项目、批量运营排期、素材资产库、店铺发布流程属于客户端或业务系统组装，不塞进中台。

## 能力组抽象

市场端不应按“页面工具”抽象，而应按可复用能力组抽象。旧项目里的商品棚拍、模特精修、多角度、讲解视频、15 秒短片，最终可以归并为四组核心能力和一个上层 Agent 能力。

### 从旧 AI 摄影棚吸收的不可变规则

旧项目可借鉴的是“业务拆解和交付方法论”，不是旧代码和旧页面。当前市场端能力统一吸收以下规则：

- AI 首次产物都是中间稿，不直接视为最终交付；标准语法是 `生成 -> 编辑/复核 -> 确认 -> 派生`。
- 图片、视频、文案都必须有确认门：高成本下游动作不能由预览自动触发。
- 多图、多帧、多参考输入必须显式声明角色，例如产品图是主体真源，风格参考只提供质感/氛围，首帧/尾帧只约束视频镜头。
- 市场端输出应是“素材包”，不是孤立单张图或单条视频；脚本、分镜、关键帧、分段视频、配图 prompt、质量标签都要保留。
- 视频合成失败不能废掉已成功素材；分段视频、首尾帧和脚本仍然是可交付资产。
- 测评端每个能力页只保留一个当前主 CTA；接口详情、调试 JSON、模型画像作为折叠辅助信息，不抢主路径。
- 任务状态、进度、失败原因由后端统一给出，前端不自行推断第三方任务状态。

### 能力组 1：商品理解与内容策略

定位：所有市场端生成动作的前置能力，不直接生成图片或视频。

输入：

- 产品图、设计图。
- 可选产品导出 JSON。JSON 只能作为说明材料或补充字段，不能作为必填入口，也不能压过产品图的视觉事实。
- 市场、平台、语言、目标人群、卖点角度、禁用声明。
- 可选参考素材：竞品链接、品牌语气、历史爆款内容。

输出：

- `resolvedProductFacts`：统一商品事实源。
- `contentStrategy`：平台、受众、卖点、风险边界。
- `copyPlan`：文案场景规划。
- `visualPlan`：组图/模特图/多角度图需求。
- `videoPlanBrief`：视频方向、时长、分镜需求。

标准步骤：

1. 识别商品：以产品图为最高优先级事实源。
2. 核对字段：导出 JSON 缺失时继续执行；导出 JSON 与产品图冲突时以产品图为准并标记风险。
3. 选择市场策略：平台、语言、人群、卖点、禁用声明。
4. 输出内容策略：供文案、图片、视频复用。

中台能力名建议：`product_market_strategy`。

### 能力组 2：文案内容包

定位：把商品理解转成可上架、可投放、可复核的文本资产。

输入：

- `resolvedProductFacts`。
- `contentStrategy`。
- 目标平台和输出语言。
- 文案场景选择。

输出：

- 上架标题、五点描述、详情页介绍。
- 广告短文案、社媒 Hook、CTA。
- SEO/搜索关键词、禁用词提醒。
- 平台审核提示和事实边界。

标准步骤：

1. 选择文案场景：上架、详情页、广告、社媒、SEO。
2. 生成结构化文案包。
3. 进行事实守卫和平台风险检查。
4. 输出可复制/可下载内容包。

中台能力名建议：`product_copy_package`。

### 能力组 3：图片资产包

定位：把商品事实转成成组可交付图片资产，而不是单张随机配图。

子能力：

- `product_image_set`：产品组图/营销套图。
- `model_scene_image`：模特/穿搭/使用场景图。
- `product_multi_angle`：多角度/多视图图。

输入：

- 产品图或产品设计图。
- `resolvedProductFacts` 和 `contentStrategy`。
- 场景清单：主图、白底图、细节图、场景图、卖点图、社媒封面、模特图、多角度图。
- 可选风格参考、模特参考、品牌视觉要求。

输出：

- 成组 OSS 图片。
- 每张图的用途、prompt、模型、能力版本、质量标签。
- 异常项：主体变形、图案漂移、文字错误、材质错误、画幅错误。

标准步骤：

1. 选择图片资产包类型：上架组图、详情页组图、社媒图、模特图、多角度图。
2. 生成资产计划：每张图的用途、画幅、参考素材、生成策略。
3. 显式提交生成任务：返回统一 `runId`。
4. 逐张回填结果：成功、失败、重试、质量标签。
5. 人工复核：先处理异常项，再一键接受正常项。
6. 打包交付：下载图文包或返回接口结果。

中台能力名建议：`product_image_set` 为第一优先级，`model_scene_image` 和 `product_multi_angle` 作为后续扩展。

### 能力组 4：视频资产包

定位：把商品事实、文案和图片资产转成可投放/可展示的视频资产。

子能力：

- `promo_video`：产品展示短视频/社媒短片。
- `product_explainer_video`：详情讲解视频。
- `video_composition`：多段裁剪合成。
- `video_reference_remix`：参考视频复刻，后置且需合规控制。

输入：

- 产品图、组图、模特图或首尾帧。
- `resolvedProductFacts`、`contentStrategy`、已确认脚本。
- 视频供应商画像：KIE/Vidu/后续模型，支持时长、画幅策略、首尾帧能力、成本和耗时。

输出：

- 视频素材包：脚本、分镜、首帧、尾帧、分段视频、可选合成视频。
- 单段视频、多段视频或最终合成视频 OSS URL。最终合成片不是唯一交付物。
- 执行 prompt、供应商任务 ID、成本证据。
- 视频质量标签：主体漂移、画幅不符、文字水印、动作异常、商品变形。

标准步骤：

1. 选择视频场景：商品展示、社媒广告、详情讲解、活动营销。
2. 根据模型画像规划分镜：不能把单模型限制写成全局规则。
3. 生成可编辑脚本和分镜计划。
4. 生成或确认首帧/尾帧：固定画幅或稳定主体时必须前置。
5. 提交分段视频任务：统一 `runId`，每段独立记录状态和 OSS 结果。
6. 可选合成：合成失败不能废掉已生成素材；分段素材仍应作为可交付结果保留。
7. 轮询和 OSS 回填。
8. 复核并标记质量问题。

中台能力名建议：`promo_video`，多段合成内部能力为 `video_composition`。

### 能力组 5：市场营销 Agent

定位：上层编排能力，不替代底层能力。它根据方法论组合文案、图片和视频能力。

输入：

- 商品图、产品字段、市场目标、渠道目标、预算/成本策略。

输出：

- 上架内容包。
- 社媒内容包。
- 广告内容包。
- 节日营销内容包。

标准步骤：

1. 判断目标：上架、广告、社媒、活动、详情页。
2. 调用 `product_market_strategy` 形成事实和策略。
3. 路由到文案、组图、模特图、视频能力。
4. 汇总资产，生成交付包。
5. 根据质量标签和人工反馈迭代。

中台能力名建议：`marketing_agent`。该能力必须遵守 Agent Runtime 的后端控制边界：工具白名单、schema 校验、置信度、成本限制、幂等和审计。

## 与现有中台架构的匹配

市场端能力组必须落在当前中台业务主线里：

```text
调用方
  -> 业务入口
    -> 业务任务 runId
      -> 业务版本 / 编排配方
        -> 处理步骤
          -> 原子能力 / 模型 / ComfyUI / 第三方 API
        -> 结果回填 / 轮询 / 可选回调
      -> 计费 / 验收 / 复测 / 回滚证据
```

因此，旧项目里的“工具 / 工坊 / 项目 / 批次 / 工作台”不能原样搬到中台。它们可以作为客户端或测评端交互参考，但中台主语仍然只能是业务能力、业务版本、业务 run、处理步骤、结果资产、质量证据和成本审计。

### 能力组到中台对象的映射

| 市场端能力组 | 中台对象 | 入口形态 | 是否创建 runId | 底层依赖 |
| --- | --- | --- | --- | --- |
| 商品理解与内容策略 | 业务能力或业务步骤 | `POST /api/business/product-market-strategy/preview` 或作为其他业务的前置步骤 | 预览可同步；成本/长耗时策略可异步 | VL/LLM、字段标准化、事实守卫 |
| 文案内容包 | 业务能力 | `POST /api/business/product-copy-package/preview`；必要时 `/runs` | 预览可同步；下载包/批量可异步 | VL/LLM、平台策略、文案审核 |
| 图片资产包 | 业务能力 | `POST /api/business/product-image-set/runs` | 必须 | GPT Image 2、ComfyUI、image-ops、OSS |
| 模特/场景图 | 业务能力 | `POST /api/business/model-scene-image/runs` | 必须 | 模特/姿态/换背景/图像编辑模型 |
| 多角度图 | 业务能力 | `POST /api/business/product-multi-angle/runs` | 必须 | 多视图生成、图像编辑、必要时 3D/视角模型 |
| 视频资产包 | 业务能力 | `POST /api/business/promo-video/runs` | 必须 | KIE、Vidu、ffmpeg 合成、首尾帧/参考视频能力 |
| 市场营销 Agent | Agent 业务能力 | `POST /api/business/marketing-agent/sessions` 或 `/runs` | 每个工具执行必须创建 runId | 白名单业务能力 + Agent Runtime |

短期可以继续用 `product_commercialization` 作为试验入口，但它必须逐步拆成上表中的业务能力。拆分原则是：业务目标、输入输出、计费边界、验收标准明显不同，就应该是不同业务能力；仅仅是模型或 workflow 替换，则作为同一业务能力的版本升级。

### 业务版本和配方

每个市场端业务能力必须有版本和配方，不允许把模型、prompt 或供应商写死在前端。

建议版本族：

- `quality_first`：质量优先，默认 GPT Image 2 / 高质量视频模型。
- `batch_fast`：批量快速，使用固定 workflow 或低成本模型。
- `marketplace_main`：平台上架主图/文案策略。
- `social_ads`：社媒广告素材策略。
- `fallback_safe`：上游不可用时的兜底版本，只能排障或低质量预览，不能作为正式验收通过。

业务版本需要记录：

- `businessKey`
- `version`
- `versionLine`
- `recipeSteps`
- `primaryAbilityId`
- 默认模型画像和路由条件
- 成本口径
- 质量样例和验收记录

### 处理步骤标准化

市场端能力的处理步骤建议统一为以下类型，便于管理端展示和排障：

| stepType | 说明 | 例子 |
| --- | --- | --- |
| `product_fact_resolution` | 商品事实识别和字段冲突处理 | 产品图优先、JSON 可选、冲突标记 |
| `strategy_planning` | 市场、平台、场景策略规划 | Amazon 上架、TikTok 社媒、礼品场景 |
| `copy_generation` | 文案生成 | 标题、五点、详情、广告短文案 |
| `asset_plan_generation` | 图片/视频资产计划 | 组图清单、脚本、分镜、首尾帧、画幅、素材需求 |
| `image_generation` | 图片生成 | 主图、细节图、模特图、场景图 |
| `video_generation` | 视频生成 | KIE/Vidu 单段或分段素材 |
| `video_composition` | 视频合成 | 多段裁剪、拼接、转码；失败时保留分段素材 |
| `quality_review` | 自动质量和风险检查 | 主体漂移、文字错误、合规风险 |
| `media_ingest` | 外部结果沉淀到 OSS | 图片/视频自有 URL 回填 |
| `billing_record` | 成本和计费证据 | quotaUnits、billingUnit |

管理端 run 详情应先展示业务结果，再展示这些处理步骤。底层原子能力日志只能作为步骤证据，不能替代业务 run 的成功判断。

### 原子能力复用

市场端能力不是新增一套模型调用系统，而是复用现有原子能力层：

- VL/LLM：商品理解、文案、策略、分镜。
- GPT Image 2：质量优先图片编辑、商业化配图、组图。
- ComfyUI / image-ops：批量、固定工作流、低成本或专项处理。
- KIE / Vidu：视频生成。
- ffmpeg / image-ops-service：视频合成、画幅归一化、DPI/元数据处理。
- OSS 媒资沉淀：所有第三方临时链接必须回填自有 OSS。

普通业务方和客户端只调用 `/api/business/*`。`/api/abilities/*` 只给内部编排、测评端、管理端和高级开发使用。

### 数据和状态约束

市场端能力必须遵守现有中台状态口径：

- 提交成功必须返回真实 `runId/taskId`。
- 状态只使用 `queued/running/succeeded/failed/cancelled` 等统一词。
- 成功必须有可访问结果：`imageUrls`、`videoUrls`、`texts` 或 `resultPayload`。
- 视频类结果允许以素材包成功作为阶段成功：`script`、`storyboards`、`keyframes`、`segmentVideoUrls`、`composedVideoUrl` 应分别记录，不能只用最终合成片覆盖全部状态。
- 成功但无结果不能静默展示空白，必须是“结果回填中”或失败。
- 失败必须返回 `errorCode/errorMessage/debugResponse`。
- 所有成本动作必须保留 `billingUnit/quotaUnits/costBreakdown`。
- 所有结果必须带能力版本、模型/供应商、prompt/脚本摘要、OSS URL 和质量标签。

### 前端和客户端边界

测评端只做能力验证，不做完整客户端项目流。

客户端可以把这些能力组装成“营销项目”“素材包”“店铺上架工作流”，但这属于客户端业务编排。中台只接收必要上下文，例如：

- `clientContextId`
- `clientStepKey`
- `clientRequestId`
- `inputAssetIds`
- `traceId`

中台不能因为市场端能力增加，就重新以“项目”为主语。

### 迁移路径

当前 `product_commercialization` 的合理演进路径：

1. 保留现有入口作为市场端试验入口，继续收集真实样例。
2. 把前置商品理解抽成 `product_market_strategy` 内部步骤或独立 preview 能力。
3. 把文案输出拆成 `product_copy_package`。
4. 把 `action=visual_generate` 拆成 `product_image_set`。
5. 把 `action=video_generate` 拆成 `promo_video`。
6. 最后把 `marketing_agent` 做成上层编排，调用上述业务能力，而不是直接调用原子模型。

拆分完成后，`product_commercialization` 可以退化为兼容入口或聚合演示入口，不作为长期业务能力主语。

## 场景穷举

### 文案能力

| 场景 | 目标用户 | 输入 | 输出 | 关键要求 |
| --- | --- | --- | --- | --- |
| 平台上架文案 | 电商运营 | 产品图、可选导出字段、平台、市场、语言 | 标题、五点、详情、关键词 | 平台限制、海外表达、禁用声明 |
| 独立站详情页 | 品牌运营 | 产品图、设计故事、材质、尺寸 | 分段详情、卖点模块、FAQ | 语气更品牌化，不机械堆关键词 |
| 社媒广告短文案 | 投放/社媒 | 产品图、目标人群、痛点、活动 | Hook、短标题、正文、CTA | 可 A/B，多语气，多平台 |
| 节日/活动营销 | 运营 | 节日、价格带、目标人群 | 活动标题、卖点、礼品话术 | 避免虚假折扣和违规承诺 |
| SEO/搜索词包 | 上架运营 | 商品事实、平台、竞品方向 | 关键词、长尾词、禁用词 | 不混入错误商品词 |
| 多语言本地化 | 跨境运营 | 基础文案、目标国家 | en/zh/bilingual 等 | 不是直译，要符合市场语感 |

当前已有产品文案内容包可以作为第一版基座，但后续必须按平台策略和 golden cases 打磨质量，而不是只看 `fallback=false`。

### 图片能力

| 能力 | 场景 | 输出资产 | 优先级 | 说明 |
| --- | --- | --- | --- | --- |
| `product_image_set` 产品组图 | 上架/详情页/广告 | 主图、细节图、场景图、社媒封面 | P0 | 从当前配图按钮升级为独立能力 |
| 白底/干净主图 | Marketplace 主图 | 白底/浅背景商品图 | P0 | 保持商品形状、材质、图案准确 |
| 详情卖点图 | 详情页 | 材质、尺寸、结构、工艺图 | P0 | 可叠加图文但需平台合规 |
| 生活场景图 | 社媒/独立站 | 使用场景、氛围图 | P1 | 不得扭曲商品主体 |
| 模特/穿搭图 | 服饰/配件 | 模特图、穿搭图、肤色/年龄多样化 | P1 | 需要身份/姿态/商品一致性 |
| 多角度图 | 展品/详情页 | 正面、侧面、背面、局部图 | P1 | 可借鉴旧项目机位控制，但中台只定义能力 |
| 包装/尺寸图 | Listing/详情页 | 包装、尺寸标注、对比图 | P1 | 要有事实来源，不能瞎标尺寸 |
| 活动营销图 | 广告/社媒 | 节日、促销、banner、封面 | P2 | 后续可接 Agent 或模板策略 |

图片能力默认质量优先可走 GPT Image 2；批量、低成本、固定工作流场景可分流到 ComfyUI/专用模型。路由必须由后端能力画像和策略控制，不能让前端硬编码。

### 视频能力

| 能力 | 场景 | 输入 | 输出 | 优先级 |
| --- | --- | --- | --- | --- |
| 商品展示短视频 | 商品详情/广告 | 产品图、文案、场景、模型画像 | 脚本、首尾帧、3/5/8 秒单段视频 | P0 |
| 15 秒社媒短片 | TikTok/Reels/广告 | 产品图、多镜头规划、节奏 | 脚本、分镜、分段视频、可选合成视频 | P0 |
| 详情讲解视频 | 详情页/独立站 | 产品事实、卖点、分镜 | 脚本、首尾帧、讲解型短视频素材包 | P1 |
| 首尾帧控制视频 | 固定画幅/稳定主体 | 首帧、尾帧、产品图 | 首尾帧和画幅稳定视频 | P1 |
| 一键营销成片 | 广告投放 | 产品素材包、营销目标 | 分段素材包 + 可选完整广告片 | P1，待 Vidu 场景接入 |
| 参考视频复刻 | 品牌/竞品风格 | 参考视频、产品素材 | 风格复刻视频 | P2，需版权/合规提示 |
| 多角度动态展示 | 展品/详情 | 多角度图或 3D 视图 | 转场/旋转视频 | P2 |

视频不能继续按“一个 8 秒按钮”设计。必须先有模型画像：供应商、端点、支持时长、是否支持首尾帧、是否支持多参考图、画幅策略、成本、预计耗时、失败原因。规划模型读取画像后产出脚本和分镜，再生成首尾帧或关键帧，最后才调用视频模型。最终合成是可选交付，不是唯一成功口径；分段素材本身也必须可下载、可复用、可追溯。

## 技术结构

### 统一事实源

产品图是最高优先级视觉事实源，导出 JSON 是可选说明材料。后端需要先生成 `resolvedProductFacts`，作为文案、组图、模特图和视频的统一下游事实源。

要求：

- 不允许因为没有导出 JSON 而阻断文案、组图或视频规划。
- 图片和 JSON 冲突时保留原始字段，但事实解析以图片为准，成本动作必须提示风险。
- 缺字段时允许模型推断，但必须标注置信度和推断来源。
- 所有生成动作记录使用的事实源版本，便于回溯。

### 能力族划分

建议中台能力族如下：

- `product_copy_package`：产品文案内容包。
- `product_image_set`：产品组图/营销套图。
- `model_scene_image`：模特/穿搭/使用场景图。
- `product_multi_angle`：多角度/多视图图。
- `promo_video`：产品视频/社媒短片/多段合成。
- `marketing_agent`：后续把文案、图、视频按方法论串成一键营销工作流。

当前 `product_commercialization` 可以保留为聚合试验入口，但正式能力定义应逐步拆成上述能力族，避免文案、配图、视频继续混在一个泛能力里。

### 调用链路

建议统一链路：

```text
产品图 + 可选导出字段 + 市场/平台/目标
  -> VL/LLM 商品理解
  -> resolvedProductFacts
  -> 场景策略/方法论规划
  -> 能力路由
  -> 异步 runId
  -> OSS 回填
  -> 质量标签/人工复核
  -> 下载包/接口结果
```

前端只负责输入、确认、展示、编辑和状态订阅；后端负责能力路由、schema 校验、模型画像、成本控制、幂等、审计和错误契约。

### 任务与状态

吸收旧项目经验：

- 所有成本动作必须是异步任务，返回统一 `runId/taskId`。
- 前端只轮询中台业务 run，不直接轮询供应商 task id。
- `queued/running/succeeded/failed/cancelled` 状态词统一。
- 长耗时任务必须展示 runId、当前状态、预计耗时、可去任务中心继续查看。
- 批量组图和多段视频不能让用户盯着按钮等，需要工作台式进度和局部回填。
- 多段视频必须支持局部成功：脚本、首尾帧、单段视频和合成视频分别回填；合成失败时保留已成功素材。

### 质量与路由

市场端不能只验“生成成功”。必须建立：

- 固定商品 golden cases：服饰配件、家居软装、宠物用品、节日礼品、包装商品。
- 质量标签：主体变形、图案漂移、材质错误、文字错误、画幅错误、风格不符、合规风险。
- 分流策略：质量优先走 GPT Image 2，批量/低成本走专用模型或 ComfyUI，视频按 KIE/Vidu/后续供应商画像路由。
- 复盘机制：每类失败沉淀为可查样例，更新默认 prompt、模型、LoRA 或工作流。

## 产品交互原则

从旧项目吸收但要适配中台测评端：

- 每个能力只保留一个主路径和一个主 CTA。
- 文案、图片、视频不能混成一个表单；可以联动，但入口和状态必须独立。
- 预览不触发成本动作；生成图片/视频必须显式点击。
- 结果不是 raw JSON，而是商家可理解的资产包。
- 批量结果要先处理异常，再一键接受正常项。
- 日志、接口、调试 JSON 默认折叠。
- 页面必须像“市场素材工作台”，不能像后台配置表。
- 业务方不知道怎么用时，要有示例商品、示例输出、使用场景，而不是大段说明文字。

## 决策点

需要后续会议确认：

1. `product_commercialization` 是否继续作为聚合入口，还是立刻拆为 `product_copy_package/product_image_set/promo_video` 三个业务能力。
