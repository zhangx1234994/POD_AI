# 市场端视频能力体验走查与整改方案（2026-06-12）

## 1. 结论

本次用本地图片在 114 测评端走了两条完整路径：

- `产品视频`：本地产品图上传、目标时长 15 秒、补充镜头要求、生成视频素材包规划。
- `3D 渲染视频`：本地花纹图上传到 1660 杯子材质槽、检查贴图方案、生成并打开 6 秒本地视频。

功能层面，两条链路都已经具备可验证闭环；体验层面，还不能按“业务用户可自然使用”交付。当前最大问题不是缺一个按钮，而是用户路径、状态反馈、事实来源和交付物层级还没有足够清楚。

整改总原则：

- 产品视频是大模型规划 + 能力模型产出的视频素材包能力，核心是商品理解、脚本分镜、首尾帧/关键帧、分段素材和可选合成。
- 3D 渲染视频是确定性 3D 贴图渲染路线，核心是模型、材质槽、贴图、相机、场景、浏览器预览和后续服务端渲染。
- 两者必须在命名、页面流程、接口契约、状态反馈和文档中持续拆开，不能共享一个含糊的“生成视频”心智。

2026-06-13 追加交互修正：

- 3D 渲染视频不能把镜头运动做成默认“画路径工具”。普通用户默认只选择推荐镜头模板；自定义镜头必须在真实 3D 画面中拖动视角并保存开始/结束镜头，不能回到右侧小地图或路径点编辑器。
- 3D 工作台应拆为“左侧贴图设置 + 右侧预览摄影棚”。贴图表单只处理模型、材质槽和当前贴图点；场景、镜头、远近、比例、时长、轨迹播放和导出都在预览棚中完成。
- 贴图颜色验收必须排除渲染器二次染色。Three.js 预览中有贴图的材质槽应以颜色保真显示，不能被光照、金属度、粗糙度或选中高亮改变颜色判断。
- 如果用户上传的贴图本身带底色，模型材质槽显示底色是素材/UV 问题，不是镜头或光照问题；后续要补透明 PNG、去底色、区域遮罩和 UV 区域检查。

## 2. 测试证据

### 2.1 产品视频

测试环境：

- 页面：`http://114.55.0.56:8200/?view=home&category=产品视频`
- 本地图片：`/Users/zhangxin/Desktop/1780284303351.jpg`
- 用户目标：15 秒产品展示短视频，突出星条旗图案、布料垂坠和电商展示效果。

已跑通：

- 本地产品图可以上传并进入视频规划流程。
- 无导出 JSON 时可以继续，不阻断。
- 可以填写核心信息和镜头偏好。
- 规划结果返回大模型证据：`volcengine / doubao-seed-2-0-lite-260428 / volcengine_chat`。
- 规划结果能识别桌布、星条旗图案、家居餐桌场景、慢速环绕、细节推进和完整商品收尾。
- 15 秒目标被规划成 3 个镜头，符合“素材包 / 分段执行”方向。
- 2026-06-12 付费链路已继续补齐视频执行试点：Vidu 固定画幅链路改为“GPT Image 2 商业首帧 -> 1280x720 归一化 -> Vidu 动态段 -> ffmpeg 组合推荐成片”。最终 runId `da48605620cf4f4e90f0d69fea2c7206` 返回 `videoUrls[0]` 推荐成片和 `videoUrls[1]` 原始 Vidu 素材段，推荐成片 `1280x720`、`8s`、开场约 `3.04s` 完整商品展示。

发现的问题：

- 1280 宽度附近，右侧当前产品面板会拦截上传按钮点击，导致用户点“上传”无反应。
- 上传入口仍像“URL 输入 + 小按钮”，不像主路径。非技术用户会以为必须先准备公网 URL。
- 上传后当前商品摘要仍显示“未识别商品名 / 未识别分类 / 未识别材质 / 未识别型号”，用户会以为图片理解失败。
- 规划结果里部分来源文案仍偏“导出字段”，但这次实际没有填写 JSON，应该明确来源是产品图 / VL。
- 关键帧提示词仍有模板味，例如泛化成 `POD product in clean studio ecommerce set`，没有充分继承规划中已识别出的桌布、星条旗图案、家居使用场景。
- 长耗时阶段只有普通 loading 文案，缺少阶段性反馈。用户不知道系统是在上传、识别、规划还是等待模型。
- 成本动作确认按钮的禁用原因不够直观。用户需要知道“必须先确认脚本分镜，才可以生成视频素材”。
- 真实视频执行耗时仍偏长：本轮 Vidu 任务后端执行约 204-222 秒，脚本端等待更长。页面必须按异步素材包心智展示阶段、预计等待和已产出资产，不能让用户只看到一个长时间 loading。

### 2.2 3D 渲染视频

测试环境：

- 页面：`http://114.55.0.56:8200/?view=home&category=3D渲染视频`
- 模型：`1660 杯子`
- 本地贴图：`/Users/zhangxin/Desktop/642b3710-1779126201.png`
- 贴图槽：`正面主贴图区 / front`
- 镜头：`360 环绕`
- 场景：`干净摄影棚`
- 时长：`6 秒`

已跑通：

- 本地花纹图可以上传到当前材质槽。
- 3D 预览会立即显示 `已按材质名应用 1 个贴图`。
- 方案检查可以返回模型文件、准备度、贴图区域、UV、贴图点、场景和镜头参数。
- 可以点击 `生成并预览 6s MP4`。
- 结果区出现视频大小和格式，并提供 `打开视频` 和 `下载 MP4`；浏览器不支持 MP4 时明确回退 WebM。
- 点击 `打开视频` 会打开浏览器 blob 视频页，说明浏览器本地视频交付闭环成立。
- 补充本地系统 Chrome 复测：页面生成 `598 KB · MP4`，`下载 MP4` 触发真实浏览器下载事件，保存文件 `podi-3d-cup_1660-6s-*.mp4` 约 610KB；截图证据为 `output/playwright/market-video-ux-remediation-20260612/product-3d-mp4-result.png`。

发现的问题：

- 当前页面虽然有按钮，但首屏到视频产出路径太长。用户第一次进入时不一定能马上理解“贴图之后还要继续往下找拍摄步骤”。
- 3D 视窗、槽位列表、URL 输入、拍摄参数和结果区全部堆在长页面里，像工程测试台，不像业务用户的拍摄工作台。
- 输出视频区域位置较低；生成成功后虽然有回显，但缺少自动滚动、显著成功态或常驻结果入口。
- 材质槽绑定已经支持一槽一图，但槽位可视化还不够直观。用户需要更明确地知道“我正在给模型哪个区域贴图”。
- 镜头、场景、时长仍是下拉字段，缺少卡片化预设和可预览解释。对业务用户来说，“360 环绕 / 干净摄影棚”应该像拍摄模板，而不是技术参数。
- 当前只交付浏览器本地 MP4，服务端 MP4 / 封面 / OSS worker 待接入。页面已经有说明，但交付层级仍应更明确，避免用户误以为这就是最终生产能力。

## 3. 用户视角问题与整改

### 3.1 产品视频

| 用户看到的问题 | 用户为什么会困惑 | 应改成什么 | 原因 |
| --- | --- | --- | --- |
| 上传是 URL 输入 + 小按钮 | 用户不知道是否必须先有公网图，主任务不明显 | 首屏主入口改成大上传区：拖拽 / 选择本地图片 / 粘贴 URL，URL 放到高级入口 | 视频能力的第一步是提供产品图，不能让技术输入框抢主路径 |
| 1280 宽度上传按钮被右侧面板遮挡 | 用户点击无反馈，会认为系统坏了 | 修复响应式布局；右侧摘要在窄屏下折叠或进入下方，不得覆盖主表单 | 这是 P0 可用性问题，不是美观问题 |
| 上传后商品摘要全是未识别 | 用户以为图片没被理解，信任下降 | 上传后显示“已锁定产品图，待规划后识别”；规划后显示 VL 识别事实、置信度和来源 | 避免把“尚未识别”和“识别失败”混在一起 |

| 关键帧提示词模板味重 | 用户会怀疑规划和生图不是一套逻辑 | 关键帧提示词必须继承商品事实、材质、图案、场景和镜头动作；禁止识别成功后仍写泛化 `POD product` | 首尾帧 / 关键帧是后续视频质量核心，不能只做调试文本 |

| 生成规划耗时 20-90 秒但缺少进度 | 用户不知道系统是否还在工作 | 增加阶段状态：上传完成 -> 商品理解 -> 规划脚本 -> 生成分镜 -> 准备成本动作 | 长耗时任务必须持续给确定感 |
| 成本按钮禁用原因不明显 | 用户不知道下一步为什么不能点 | 禁用按钮显示原因：`确认脚本分镜后可生成素材包`；确认后主 CTA 变为可点 | 成本动作必须显式确认，但确认门不能变成迷路点 |

| 检查方案和生成视频像两个并列按钮 | 用户不知道是否必须先检查 | 主 CTA 按状态变化：未检查时为“检查并生成预览”；检查完成后为“重新生成 6s MP4” | 减少两个按钮并列带来的决策成本 |
| 本地 MP4 / 服务端 MP4 / OSS 层级不清 | 用户不知道生成结果能否交付 | 页面明确三层：浏览器预览 MP4 已可用；服务端渲染 MP4 待接入；OSS 回填待 worker | 避免把技术预览误包装成最终生产交付 |

## 4. 优先级与执行顺序

### P0：先修阻断和信任问题

1. 修复产品视频 1280 宽度上传按钮被右侧面板遮挡。
2. 产品视频首屏改为主上传区，URL 作为高级输入。
3. 产品视频合并后的第 2 步必须真正同时承载商品事实和视频策略；不再让用户先看“未识别”摘要再跳下一步。
4. 产品视频规划结果的事实来源必须准确：无 JSON 时来源为产品图 / VL。
5. 关键帧提示词从实际规划结果生成，识别成功时不得继续出现泛化 `POD product`。
6. 3D 渲染视频生成成功后自动聚焦结果，结果卡固定显示打开 / 下载。

### P1：把页面从 demo 调试台改成工作台

1. 产品视频增加阶段性进度：商品理解、脚本规划、分镜规划、关键帧计划、可执行策略。
2. 产品视频把目标时长、模型画像和拆段策略放在同一张策略卡，不让用户误以为时长被供应商枚举限制。
3. 产品视频脚本、分镜、关键帧以可编辑卡片展示；编辑后确认状态失效。
4. 3D 渲染视频改成左侧 3D 画布常驻、右侧步骤表单、底部固定主 CTA。
5. 3D 材质槽增加可视化高亮和绑定状态，避免只靠材质名理解。
6. 3D 镜头和场景改为卡片化模板，并展示适用场景；手动画轨迹默认收起，展开后必须在 3D 模型画面内所见即所得调整。
7. 3D 贴图预览使用颜色保真策略；新增透明底、去底色、区域遮罩和 UV 检查作为后续素材质量能力。

### P2：生产化补齐

1. 产品视频继续扩展真实首帧 / 尾帧 / 关键帧生成与多段视频素材包执行；当前单段 Vidu 已完成首帧归一化、原始素材段、ffmpeg 推荐成片和 OSS 回填。
2. 产品视频继续保存并展示每个素材资产：脚本、分镜、关键帧图、分段视频、可选合成片、OSS、runId、错误；当前 `videoAssetPackage.composition` 已回填组合成片证据。
3. 3D 接服务端 Blender / 渲染 worker，输出 MP4、封面帧、manifest 和 OSS 回填。
4. 3D 增加模型资产管理和贴图点校准工具，支持后续更多商品模型。

## 5. 验收标准

### 产品视频

- 1280、1440、移动宽度下，上传按钮都可点击，右侧摘要不得覆盖主输入。
- 只上传本地产品图、无 JSON，也能完成规划。
- 上传后页面不显示“识别失败式”的空摘要；规划后必须显示产品图识别事实、来源和置信度。
- 15 秒目标时长返回清晰拆段策略，页面解释供应商限制和素材包交付口径。
- 规划器证据、脚本、分镜、关键帧计划、风险检查全部可见；fallback 必须醒目标记为排障结果。
- 关键帧提示词必须包含当前产品可见事实；识别出桌布时，不得泛化为 `POD product`。
- 未确认脚本分镜时不能触发视频成本动作；按钮必须说明禁用原因。

### 3D 渲染视频

- 选择 1660 杯子、上传本地贴图到 `front` 后，3D 预览立即显示贴图状态。
- 默认镜头选择区展示推荐模板卡片；用户不展开高级面板也能完成播放确认和导出。
- 自定义镜头作为明确入口；进入后在 3D 模型画面内手动转动视角，分别保存开始镜头和结束镜头，且修改后需要重新播放确认。
- 贴图预览不得被光照、金属度、粗糙度或选中态染色；如图片本身带底色，应在验收记录中归为素材/UV 问题。
- 检查方案返回模型、UV、贴图点、场景、镜头和准备度。
- 点击生成后能得到 MP4，页面显示大小、打开、下载；浏览器不支持 MP4 时必须明确提示 WebM fallback。
- 结果必须在当前工作台可见，并同步到右侧摘要或固定结果区。
- 页面明确区分：浏览器 MP4 预览已可用；服务端 MP4 / OSS worker 待接入。
- 多材质槽模型必须允许逐槽绑定，不允许退回到单上传位。

## 6. 自动化回归要求

- 产品视频 1280 宽度点击上传，不得被右侧摘要遮挡。
- 产品视频本地图片上传后，进入合并后的商品事实 + 视频策略阶段。
- 产品视频 15 秒规划返回 3 个分镜，并展示模型证据和拆段策略。
- 产品视频关键帧提示词必须继承 `resolvedProductFacts` 或 storyboard 商品事实。
- 3D 渲染视频上传贴图后，槽位状态变为已绑定。
- 3D 渲染视频点击检查方案后出现准备度。
- 3D 渲染视频点击生成 MP4 后出现大小、打开、下载。

## 7. 本轮不做

- 不恢复产品文案入口；文案后续按 `product_copy_package` 独立能力重做。
- 不把 3D 渲染视频接入 KIE / Vidu / GPT Image 2。
- 不承诺 3D 服务端 MP4 已可用；当前只验收浏览器本地 MP4 预览和下载。
- 不把产品视频最终合成片作为唯一成功口径；分段素材和关键帧同样是交付资产。
