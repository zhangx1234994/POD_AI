# 产品商业化能力整改记录（2026-06-10）

## 背景

本轮产品商业化能力在测评端暴露出明显问题：页面不能稳定下拉，文案实际是模板拼接而不是大模型生成，配图只停留在建议层，没有形成图文并茂的可交付结果；视频场景、Vidu 模型选择、产品导出 JSON 字段、图片和字段一致性校验都没有按前期讨论落地。该问题不是单个样式缺陷，而是“能力定义、业务价值、前端交互和验收口径没有对齐”的系统性问题。

## 根因判断

1. 能力定义错误：把“产品设计后的电商上架与营销内容包”做成了接口调试页，没有站在电商商家视角输出可直接使用的商品内容资产。
2. 文案链路错误：`preview()` 里实际是确定性模板拼接，没有经过大模型理解商品、场景、平台和营销角度，却在页面和汇报中被当成“文案生成”。
3. 图文关系错误：配图被做成孤立按钮，没有与标题、五点描述、详情页、广告短文案和社媒场景建立使用关系。
4. `visualSupportMode=generate` 在后端目前只是计划字段，测评端没有提供显式生成动作和结果展示。
5. 视频能力只暴露了单段 8 秒生成，没有把前期讨论的场景枚举、供应商选择、Vidu 路径和后续一键成片/复刻边界说清楚。
6. 产品导出字段样例过窄，只覆盖了少量袜子字段，没有覆盖模板、主体、分类、工艺、包装、物流、关键词等实际导出信息。
7. 图片与 JSON 不匹配时没有任何确认或风险提示，容易把错误商品字段带入付费生成。
8. 线上端口和本地端口口径没有在当前工作记忆中严格区分：线上测评端是 `8200`，本地开发临时端口才可能是 `8299`。

## 本轮处理原则

- 先文档和 TODO，后代码；每项必须能验收。
- 用最简洁、最安全的方式解决：不新增厂商直连，不绕过中台业务 API。
- 前端只负责清晰交互、显式动作、状态和下载；后端继续负责能力路由、runId、OSS 回填、成本和错误契约。
- 配图生成先复用 `product_design` 业务能力，提交 run 后轮询结果；后续如果需要专门的 `product_image_set`，再独立定义能力契约。
- 视频先明确当前可执行路径：KIE Veo3.1 Fast、Vidu viduq3-turbo。Vidu 一键成片、视频复刻、viduq3-ad/reference2video 先作为“待接入场景”，不伪装成已完成。
- 文案必须由大模型生成结构化 JSON。模板只能作为降级兜底，并且响应和页面必须明确标记 `template_fallback`，不能作为验收通过证据。
- 产品商业化输出必须是“商家内容包”：商品理解、上架文案、详情介绍、营销文案、关键词、配图规划、可选配图生成、视频规划和交付包下载。

## P0 整改清单

1. 页面滚动
   - 修复测评端工作区不能下拉的问题。
   - 验收：产品文案、产品视频页面在 1440x900、1280x720、移动宽度都能滚动到底部。
   - 状态（2026-06-10）：已上线验证，产品文案页可完成输入、确认、生成、结果区浏览。

2. 产品导出字段
   - 扩展默认 JSON，覆盖模板编号、主体编码、产品型号、品类、工厂、重量、材质、成分、包装、关键词、描述等字段。
   - 验收：用户乱填或删字段时，预览不崩溃，能明确显示缺失、推断和低置信提示。
   - 状态（2026-06-10）：默认样例已扩展到 25 个字段；乱填/错配的自动识别仍未完成，下一轮需加强字段缺失、图片不匹配和低置信提示。

3. 图片与字段一致性
   - 生成图片或视频前要求用户确认“当前图片与 JSON 属于同一商品”。
   - 验收：更换图片或 JSON 后确认状态自动失效；未确认时可以预览文案，但不能触发付费生成动作。
   - 状态（2026-06-10）：已加入人工确认；下一轮需补 VL 自动核对建议，但不能绕过人工确认。

4. 文案场景
   - 把场景做成可选项，而不是只显示内部字段名。
   - 文案必须过大模型，结合产品图、导出字段、目标市场、平台/场景和补充要求生成结构化结果。
   - 验收：至少覆盖上架标题、五点描述、详情页介绍、广告短文案、SEO/搜索关键词，并能按选择输出；响应包含 `copyGeneration.method`、`provider/model` 和是否 fallback 的证据。
   - 状态（2026-06-10）：已上线，真实接口返回 `volcengine_chat`、`fallback=false`，页面显示模型证据。已修复大模型返回分组 `keywordPack` 时页面显示对象文本的问题。

5. 配图生成
   - `不配图 / 只给建议 / 生成配图` 三种模式分清。
   - `生成配图` 必须显式调用中台生图能力，当前先复用 `product_design` run。
   - 输出区展示生成图、runId、状态、下载/打开链接。
   - 验收：至少能从产品图生成 1 张社媒封面或详情配图，并回填 OSS URL。
   - 状态（2026-06-10）：页面已有显式配图生成入口和配图 brief；下一轮要重点验证真实配图质量、失败提示、并发与下载包沉淀。

6. 图文并茂下载
   - 结果区提供下载图文包动作。
   - 验收：能下载一个 HTML 或 JSON 包，包含商品理解、各场景文案、产品图、生成配图链接、配图用途说明和审核提示；视频只作为后续联动信息，不作为文案能力本身的交付物。
   - 状态（2026-06-10）：已提供下载入口；审核区已从 raw JSON 改为结构化展示。

7. 视频场景和供应商选择
   - 暴露当前可执行供应商：KIE Veo3.1 Fast、Vidu viduq3-turbo。
   - 暴露当前可执行视频场景：商品展示、社媒广告、详情讲解。
   - 标明待接入场景：Vidu 一键成片、Vidu 视频复刻、Vidu Ad/reference2video。
   - 验收：选择 Vidu 时 payload 带 `executorId=executor_vidu_default`；选择 KIE 时走默认 KIE；目标时长超过 8 秒时仍按多段生成/合成接口处理。

8. 文档同步
   - 更新唯一 TODO、v0.7 方案、业务 API 文档和本整改记录。
   - 验收：新 agent 只看文档能知道当前问题、处理顺序、已完成项和保留风险。

- 线上提交：`564e6006`。
- 发布门禁：`python3 -m pytest backend/tests` 142 passed；管理端/测评端 TypeScript 检查和生产构建通过；发布 smoke 通过。
- 线上接口验证：`POST /api/business/product-commercialization/preview` 使用真实产品图和产品字段，返回 `copyGeneration.method=volcengine_chat`、`fallback=false`、`keywordPack` 为字符串数组。
- 线上页面验证：测评端 `产品文案` 分类能完成产品图输入、字段核对、确认、生成文案内容包；结果区展示模型证据、文案结果、配图建议、渠道建议和结构化审核提示。
- 边界确认：文案能力不生成视频；产品视频是独立入口。文案结果中的“可联动产品视频”只表示后续可进入视频能力，不能作为文案验收输出。

## 下一轮打磨清单

1. 文案质量和场景模板
   - 按平台拆模板策略：Amazon、Shopify、Etsy、TikTok Shop、通用海外电商。
   - 每个平台至少准备 3 组 golden cases，观察标题长度、语气、关键词密度、禁用声明遵守情况。
   - 验收：同一商品切换平台/语气/人群后，文案有明显差异，且不出现机械模板味。

2. VL 图片和 JSON 一致性
   - 用 VL 对产品图进行轻量识别，输出“可能匹配 / 需人工复核 / 明显不匹配”的提示。
   - 不做自动拦截，仍以人工确认为成本动作门槛。
   - 验收：乱填 JSON 或更换不相关图片时，页面能明确提示“本次结果可能不可靠”。

3. 配图生成质量闭环
   - 对商品主图、详情细节图、社媒广告封面分别跑真实样例。
   - 记录 runId、模型/版本、OSS 图、是否可用、问题标签。
   - 验收：至少沉淀 3 类商品的可用/不可用样例，决定是否继续复用 `product_design`，还是独立定义 `product_image_set`。

4. 下载包交付形态
   - 优化 HTML 下载包排版，明确“可直接复制文案 / 可下载图片 / 后续视频入口”。
   - 验收：运营或业务方不看后台也能从下载包复核商品字段、文案、配图用途和审核提示。

5. 视频能力单独验收
   - 产品视频入口继续按独立能力验收，重点跑 KIE/Vidu、8 秒单段、15 秒多段合成、失败重试和 OSS 回填。
   - 验收：视频能力的文档、接口和页面不得依赖文案页面的隐藏状态。

## 暂不在本轮承诺

- 不在本轮完成 Vidu 一键成片 Agent、视频复刻 Agent、viduq3-ad/reference2video 的完整接入。
- 不在本轮完成专门的 `product_image_set` 后端能力；先用 `product_design` 做显式配图生成闭环。
- 不在本轮做完整图片内容识别自动判定“图片和 JSON 是否匹配”；先用人工确认和低置信提示防止误触发成本动作。
