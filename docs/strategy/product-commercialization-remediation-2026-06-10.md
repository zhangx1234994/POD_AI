# 产品商业化能力整改记录（2026-06-10）

## 背景

本轮产品商业化能力在测评端暴露出明显问题：页面不能稳定下拉，配图只停留在建议层，没有形成图文并茂的可交付结果；视频场景、Vidu 模型选择、产品导出 JSON 字段、图片和字段一致性校验都没有按前期讨论落地。该问题不是单个样式缺陷，而是“后端已有一部分能力契约，前端没有按业务工作台方式产品化”的系统性问题。

## 根因判断

1. 入口交互按“接口调试表单”实现，而不是按业务方真实操作路径实现。
2. `visualSupportMode=generate` 在后端目前只是计划字段，测评端没有提供显式生成动作和结果展示。
3. 视频能力只暴露了单段 8 秒生成，没有把前期讨论的场景枚举、供应商选择、Vidu 路径和后续一键成片/复刻边界说清楚。
4. 产品导出字段样例过窄，只覆盖了少量袜子字段，没有覆盖模板、主体、分类、工艺、包装、物流、关键词等实际导出信息。
5. 图片与 JSON 不匹配时没有任何确认或风险提示，容易把错误商品字段带入付费生成。
6. 线上端口和本地端口口径没有在当前工作记忆中严格区分：线上测评端是 `8200`，本地开发临时端口才可能是 `8299`。

## 本轮处理原则

- 先文档和 TODO，后代码；每项必须能验收。
- 用最简洁、最安全的方式解决：不新增厂商直连，不绕过中台业务 API。
- 前端只负责清晰交互、显式动作、状态和下载；后端继续负责能力路由、runId、OSS 回填、成本和错误契约。
- 配图生成先复用 `product_design` 业务能力，提交 run 后轮询结果；后续如果需要专门的 `product_image_set`，再独立定义能力契约。
- 视频先明确当前可执行路径：KIE Veo3.1 Fast、Vidu viduq3-turbo。Vidu 一键成片、视频复刻、viduq3-ad/reference2video 先作为“待接入场景”，不伪装成已完成。

## P0 整改清单

1. 页面滚动
   - 修复测评端工作区不能下拉的问题。
   - 验收：产品文案、产品视频页面在 1440x900、1280x720、移动宽度都能滚动到底部。

2. 产品导出字段
   - 扩展默认 JSON，覆盖模板编号、主体编码、产品型号、品类、工厂、重量、材质、成分、包装、关键词、描述等字段。
   - 验收：用户乱填或删字段时，预览不崩溃，能明确显示缺失、推断和低置信提示。

3. 图片与字段一致性
   - 生成图片或视频前要求用户确认“当前图片与 JSON 属于同一商品”。
   - 验收：更换图片或 JSON 后确认状态自动失效；未确认时可以预览文案，但不能触发付费生成动作。

4. 文案场景
   - 把场景做成可选项，而不是只显示内部字段名。
   - 验收：至少覆盖上架标题、五点描述、详情描述、广告短文案、关键词包，并能按选择输出。

5. 配图生成
   - `不配图 / 只给建议 / 生成配图` 三种模式分清。
   - `生成配图` 必须显式调用中台生图能力，当前先复用 `product_design` run。
   - 输出区展示生成图、runId、状态、下载/打开链接。
   - 验收：至少能从产品图生成 1 张社媒封面或详情配图，并回填 OSS URL。

6. 图文并茂下载
   - 结果区提供下载图文包动作。
   - 验收：能下载一个 HTML 或 JSON 包，包含文案、产品图、生成配图链接、视频链接和审核提示。

7. 视频场景和供应商选择
   - 暴露当前可执行供应商：KIE Veo3.1 Fast、Vidu viduq3-turbo。
   - 暴露当前可执行视频场景：商品展示、社媒广告、详情讲解。
   - 标明待接入场景：Vidu 一键成片、Vidu 视频复刻、Vidu Ad/reference2video。
   - 验收：选择 Vidu 时 payload 带 `executorId=executor_vidu_default`；选择 KIE 时走默认 KIE；目标时长超过 8 秒时仍按多段生成/合成接口处理。

8. 文档同步
   - 更新唯一 TODO、v0.7 方案、业务 API 文档和本整改记录。
   - 验收：新 agent 只看文档能知道当前问题、处理顺序、已完成项和保留风险。

## 暂不在本轮承诺

- 不在本轮完成 Vidu 一键成片 Agent、视频复刻 Agent、viduq3-ad/reference2video 的完整接入。
- 不在本轮完成专门的 `product_image_set` 后端能力；先用 `product_design` 做显式配图生成闭环。
- 不在本轮做完整图片内容识别自动判定“图片和 JSON 是否匹配”；先用人工确认和低置信提示防止误触发成本动作。
