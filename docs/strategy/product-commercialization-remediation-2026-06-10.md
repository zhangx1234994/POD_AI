# 产品商业化能力整改记录（2026-06-10）

## 背景

本轮产品商业化能力在测评端暴露出明显问题：页面不能稳定下拉，文案实际是模板拼接而不是大模型生成，配图只停留在建议层，没有形成图文并茂的可交付结果；视频场景、Vidu 模型选择、产品导出 JSON 字段、图片和字段一致性校验都没有按前期讨论落地。该问题不是单个样式缺陷，而是“能力定义、业务价值、前端交互和验收口径没有对齐”的系统性问题。

## 根因判断

1. 能力定义错误：把“产品设计后的电商上架与营销内容包”做成了接口调试页，没有站在电商商家视角输出可直接使用的商品内容资产。
2. 文案链路错误：`preview()` 里实际是确定性模板拼接，没有经过大模型理解商品、场景、平台和营销角度，却在页面和汇报中被当成“文案生成”。
3. 图文关系错误：配图被做成孤立按钮，没有与标题、五点描述、详情页、广告短文案和社媒场景建立使用关系。
4. `visualSupportMode=generate` 在后端目前只是计划字段，测评端没有提供显式生成动作和结果展示。
5. 视频能力只暴露了单段 8 秒生成，没有把前期讨论的场景枚举、供应商选择、Vidu 路径和后续一键成片/复刻边界说清楚。
6. 产品导出字段样例过窄，只覆盖了少量袜子字段，没有覆盖模板、主体、分类、工艺、包装、物流、关键词等实际导出信息。
7. 图片与 JSON 不匹配时没有自动一致性证据，容易把错误商品字段带入文案和付费生成。产品图必须作为最高优先级视觉事实源，JSON 只能作为对产品图的结构化说明。
8. 线上端口和本地端口口径没有在当前工作记忆中严格区分：线上测评端是 `8200`，本地开发临时端口才可能是 `8299`。
9. 二次联动错误：前端把产品文案和产品视频当成同一个工作台状态切换，图片、JSON 和旧结果会跨功能带入，让用户感觉不是两个能力。
10. 事实源传递错误：后端虽然能识别图片/JSON 冲突，但配图和视频规划仍可能沿用导出 JSON 的旧商品名，导致“页面提示以图为准，实际 prompt 仍按错商品生成”。
11. 文档/接口展示缺失：测评端没有把“怎么用、调哪个接口、查哪个 runId、哪些错误可预期”放在能力页面内，导致能力展示页变成内部调试页。

## 本轮处理原则

- 先文档和 TODO，后代码；每项必须能验收。
- 用最简洁、最安全的方式解决：不新增厂商直连，不绕过中台业务 API。
- 前端只负责清晰交互、显式动作、状态和下载；后端继续负责能力路由、runId、OSS 回填、成本和错误契约。
- 配图生成必须走 `product_commercialization` 统一业务 run，通过 `action=visual_generate` 区分图文配图动作；后续如果需要专门的 `product_image_set`，再独立定义能力契约。
- 视频先明确当前可执行路径：KIE Veo3.1 Fast、Vidu viduq3-turbo。Vidu 一键成片、视频复刻、viduq3-ad/reference2video 先作为“待接入场景”，不伪装成已完成。
- 文案必须由大模型生成结构化 JSON。模板只能作为降级兜底，并且响应和页面必须明确标记 `template_fallback`，不能作为验收通过证据。
- 产品商业化输出必须是“商家内容包”：商品理解、上架文案、详情介绍、营销文案、关键词、配图规划、可选配图生成、视频规划和交付包下载。
- 产品图与 JSON 冲突时，`productCard.sourceFacts` 保留原始导出字段供复核，`resolvedProductFacts` 作为配图/视频/下载包的下游事实源，避免后续成本动作继续使用错商品。

## P0 整改清单

1. 页面滚动
   - 修复测评端工作区不能下拉的问题。
   - 验收：产品文案、产品视频页面在 1440x900、1280x720、移动宽度都能滚动到底部。
   - 状态（2026-06-10）：已上线验证，产品文案页可完成输入、确认、生成、结果区浏览。

2. 产品导出字段
   - 扩展默认 JSON，覆盖模板编号、主体编码、产品型号、品类、工厂、重量、材质、成分、包装、关键词、描述等字段。
   - 验收：用户乱填或删字段时，预览不崩溃，能明确显示缺失、推断和低置信提示。
   - 状态（2026-06-10）：默认样例已扩展到 25 个字段；乱填/错配的自动识别仍未完成，下一轮需加强字段缺失、图片不匹配和低置信提示。

3. 图片与字段一致性
   - 生成图片或视频前要求用户确认“当前图片与 JSON 属于同一商品”。
   - 后端大模型/VL 必须按“产品图优先，JSON 补充说明”的口径输出 `imageFactAssessment`，包含图像主判断、字段冲突、缺失字段推断、采用口径和置信度。
   - 验收：更换图片或 JSON 后确认状态自动失效；未确认时可以预览文案，但不能触发付费生成动作；乱填 JSON 或上传不匹配图片时，结果区明确展示冲突/低置信提示。
   - 状态（2026-06-10）：已加入人工确认；已纠正后端提示词和 schema，新增 `imageFactAssessment` 与审核提示；线上复测发现旧事实守卫仍按导出 JSON 关键词强校验，会把“模型识别出图片/JSON 冲突并以图为准”的正确结果打回模板，已改为：无冲突声明的产品类型漂移继续打回，明确报告 `fieldConflicts` 的结果放行并输出人工复核预警。
   - 状态（2026-06-10 追加）：新增 `resolvedProductFacts`。当 VL 识别到字段冲突时，配图 prompt、视频 prompt、分镜主体和配图计划必须从该统一事实源取值；用户未确认冲突前，测评端禁止触发配图/视频成本动作。

4. 文案场景
   - 把场景做成可选项，而不是只显示内部字段名。
   - 文案必须过大模型，结合产品图、导出字段、目标市场、平台/场景和补充要求生成结构化结果。
   - 验收：至少覆盖上架标题、五点描述、详情页介绍、广告短文案、SEO/搜索关键词，并能按选择输出；响应包含 `copyGeneration.method`、`provider/model` 和是否 fallback 的证据。
   - 状态（2026-06-10）：已上线，真实接口返回 `volcengine_chat`、`fallback=false`，页面显示模型证据。已修复大模型返回分组 `keywordPack` 时页面显示对象文本的问题。

5. 配图生成
   - `不配图 / 只给建议 / 生成配图` 三种模式分清。
   - `生成配图` 必须显式调用中台产品商业化能力，当前通过 `product_commercialization` run + `action=visual_generate` 执行。
   - 输出区展示生成图、runId、状态、下载/打开链接。
   - 验收：至少能从产品图生成 1 张社媒封面或详情配图，并回填 OSS URL。
   - 状态（2026-06-10）：页面已有显式配图生成入口和配图 brief；下一轮要重点验证真实配图质量、失败提示、并发与下载包沉淀。
   - 状态（2026-06-10 追加）：配图执行统一改为 `POST /api/business/product-commercialization/runs` + `action=visual_generate`，不再复用 `product-design/runs`，避免能力边界混淆。

6. 图文并茂下载
   - 结果区提供下载图文包动作。
   - 验收：能下载一个 HTML 或 JSON 包，包含商品理解、各场景文案、产品图、生成配图链接、配图用途说明和审核提示；视频只作为后续联动信息，不作为文案能力本身的交付物。
   - 状态（2026-06-10）：已提供下载入口；审核区已从 raw JSON 改为结构化展示。

7. 视频场景和供应商选择
   - 暴露当前可执行供应商：KIE Veo3.1 Fast、Vidu viduq3-turbo。
   - 暴露当前可执行视频场景：商品展示、社媒广告、详情讲解。
   - 标明待接入场景：Vidu 一键成片、Vidu 视频复刻、Vidu Ad/reference2video。
   - 验收：选择 Vidu 时 payload 带 `executorId=executor_vidu_default`；选择 KIE 时走默认 KIE；目标时长超过 8 秒时仍按多段生成/合成接口处理。
   - 状态（2026-06-10 追加）：产品视频入口与产品文案入口前端状态强隔离；从一个能力切到另一个能力时不再继承图片、JSON 和旧输出。视频页输出从 raw JSON 改为“最终采用事实、分镜、素材需求、执行提示词”，调试 JSON 收到折叠区。

8. 文档同步
   - 更新唯一 TODO、v0.7 方案、业务 API 文档和本整改记录。
   - 验收：新 agent 只看文档能知道当前问题、处理顺序、已完成项和保留风险。
   - 状态（2026-06-10 追加）：接口文档补充 `resolvedProductFacts`、`action=visual_generate`、配图查询示例和新增错误码；测评端页面补充“怎么用”和“接口与文档口径”。

## 2026-06-11 追加整改记录

1. **文案配图失败**
   - 现象：测评端生成商品主图时报 `size` 参数不满足模型图片尺寸约束。
   - 根因：产品商业化配图默认能力边界判断错误。没有特殊说明时，商业化配图应走中台 GPT Image 2 图片编辑质量优先路径；此前误接到 Seedream/Volcengine 文生图路径，且还写死了不适合该模型的尺寸参数。
   - 改进：产品商业化配图默认改为 `openai_gpt_image_2_edit`，商品图作为事实锚点，`size=auto`，能力调用元数据写入 `routeType=image2_quality_first`。
   - 后续要求：配图验收必须记录模型、prompt、场景、OSS URL 和实际结果；除非用户明确要求低成本/批量/特定模型，否则不得把商业化配图默认路由到非 GPT Image 2。

2. **视频时长和分镜规划错误**
   - 现象：页面把 KIE/Vidu 都展示成统一的 `8 秒单段 / 16-60 秒多段合成`，没有体现不同模型接口参数和支持时长；执行层也统一传 `8`。
   - 根因：把 KIE Veo3.1 Fast 一次实测的 8 秒限制扩大成产品视频全局规则，缺少“模型画像 -> 分镜规划 -> 执行参数”的中间层。
   - 改进：新增后端 `VIDEO_MODEL_PROFILES`。KIE 当前按 `[8]` 片段规划；Vidu 当前按 `[3,5,8]` 片段规划。`videoPlan` 返回 `modelProfile/segmentDurationOptions/generationMode/storyboard/compositionPlan.segmentDurations`，执行时按每个镜头的 `durationSeconds` 调用厂商接口。
   - 页面整改：测评端目标时长下拉由所选模型画像驱动；显示当前模型、模型支持片段、可执行/规划中生成模式；不再展示静态“当前可选时长”。
   - 首尾帧模式：当前只作为 `plannedModes` 暴露，不伪装成可执行。后续接入前必须先完成首尾帧图片生成、人工确认、视频接口适配和错误契约。

3. **Vidu 比例执行口径错误**
   - 现象：本地真实 Vidu 5 秒任务成功生成并回填 OSS，但用户选择 `16:9` 时实际产物为 `960x960`。
   - 根因：Vidu 单参考图生视频接口不接受独立画幅参数，实际比例跟随上传产品图/首帧。此前页面和文档把 `aspectRatio` 展示成通用执行参数，容易让用户误以为 Vidu 会直接输出 16:9。
   - 改进：`videoPlan` 新增 `aspectPolicy`。KIE 标记为 `provider_parameter`；Vidu 标记为 `input_image_ratio`，并增加 `normalized_first_frame` 素材需求。测评端在 Vidu 模式下显示“目标比例（Vidu 跟随首帧）”，规划结果同时展示目标比例和实际比例策略。
   - 后续要求：固定 16:9/9:16 的 Vidu 视频必须先进入首帧归一化或首尾帧控制模式，不允许继续把无效 `aspectRatio` 下发给 Vidu。

4. **文档与测试闭环**
   - 已更新 `docs/api/modules/business.md`，明确 `durationSeconds/targetDurationSeconds` 受模型画像约束，配图默认走 GPT Image 2 `size=auto`，视频按单段或多段分镜执行；Vidu `aspectRatio` 是目标规划字段，不是直接厂商执行参数。
   - 已补测试：产品商业化专项测试 24 条通过；业务 OpenAPI 契约测试 68 条通过；测评端 TypeScript 和生产构建通过。

5. **视觉走查与验收门禁**
   - 现象：产品文案/产品视频页面仍有内部过程词、橙色大警告、接口说明抢占首屏和空结果区过大的问题。
   - 改进：测评端移除 `v0.7 新能力试点 · 整改版`，改为业务能力标题；提示降噪为信息提示；接口口径默认折叠；压缩流程说明、JSON 输入和空结果区；移动端确认无横向溢出。
   - 验收记录：新增 `docs/testing/2026-06-11-product-commercialization-acceptance-gate.md`，把视觉、文案、错配、配图、视频、错误路径和文档一致性作为后续封版门禁。
   - 后续要求：真实线上复测前不得再把“本地页面能打开”当成完成，必须按门禁逐项补 runId、OSS 结果和失败证据。

## 下一轮打磨清单

1. 文案质量和场景模板
   - 按平台拆模板策略：Amazon、Shopify、Etsy、TikTok Shop、通用海外电商。
   - 每个平台至少准备 3 组 golden cases，观察标题长度、语气、关键词密度、禁用声明遵守情况。
   - 验收：同一商品切换平台/语气/人群后，文案有明显差异，且不出现机械模板味。

2. VL 图片和 JSON 一致性
   - 用 VL 对产品图进行轻量识别，输出 `imageFactAssessment`：图像主判断、字段冲突、缺失字段推断、采用口径和置信度。
   - 产品图是最高优先级视觉事实源；JSON 是说明材料。字段与图片冲突时，文案以图片可见事实为主，冲突字段进入人工复核。
   - 事实守卫不能只按导出 JSON 关键词验收；如果 VL 明确产出 `fieldConflicts`，说明模型正在按产品图纠偏，此时应保留图片优先的文案并追加 `PRODUCT_IMAGE_FIELD_CONFLICT`，而不是回退到 JSON 模板。
   - 不做自动拦截，仍以人工确认为成本动作门槛。
   - 验收：乱填 JSON 或更换不相关图片时，页面能明确提示“本次结果可能不可靠”，并列出冲突字段。

3. 配图生成质量闭环
   - 对商品主图、详情细节图、社媒广告封面分别跑真实样例。
   - 记录 runId、模型/版本、OSS 图、是否可用、问题标签。
   - 验收：至少沉淀 3 类商品的可用/不可用样例，决定是否继续用 `product_commercialization action=visual_generate`，还是独立定义 `product_image_set`。

4. 下载包交付形态
   - 优化 HTML 下载包排版，明确“可直接复制文案 / 可下载图片 / 后续视频入口”。
   - 验收：运营或业务方不看后台也能从下载包复核商品字段、文案、配图用途和审核提示。

5. 视频能力单独验收
   - 产品视频入口继续按独立能力验收，重点跑 KIE/Vidu、8 秒单段、15 秒多段合成、失败重试和 OSS 回填。
   - 验收：视频能力的文档、接口和页面不得依赖文案页面的隐藏状态。

6. 验收门禁执行
   - 按 `docs/testing/2026-06-11-product-commercialization-acceptance-gate.md` 逐项复测。
   - 优先补齐真实 GPT Image 2 配图、KIE/Vidu 视频和多段合成证据。
   - 所有真实复测必须记录 runId、模型、耗时、OSS URL、错误码和人工质量判断。
