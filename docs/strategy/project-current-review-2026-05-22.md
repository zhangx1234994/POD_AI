# 当前项目回顾与待办（2026-05-22）

本文是当前项目恢复上下文时的简洁入口。详细任务仍以 `docs/strategy/todo-master-2026q2.md` 为准。

## 1. 当前状态

- 当前开发主线：`v0.4 业务编排工作台产品化版`。
- 当前维护范围：`backend`、`podi-admin-web`、`podi-eval-web`、`vendor-api-ops`、`image-ops-service`、ComfyUI 执行节点和文档。
- 当前平台主线：业务方调用业务 API 或 Coze 工具箱，中台返回 `runId`，内部把 VL、ComfyUI、OpenAI、评分、回填、回调和计费都归入同一个业务任务。
- 当前页面主线：管理端应先看“业务调用”和“业务链路”，再下钻版本、步骤、能力调用和治理记录。
- 当前发布规则：只认 `origin/main`；本地完成不等于可更新服务器；更新前必须跑发布 SOP 和逐功能检查。

## 2. 当前待办清单

### P0：本版本封版前必须完成

1. 业务链路图闭环收尾
   - 已有：节点运行证据、成功/失败样本、默认版本只读、复制草稿并编辑。
   - 还欠：在非生产或明确可写环境真实验证“复制草稿 -> 修改步骤 -> 保存 -> 试运行 -> 验收”的完整链路。

2. 业务列表和业务摘要接口性能
   - 现象：管理端走查时 `business/runs`、`usage-summary` 仍出现 15-45 秒级耗时或超时。
   - 动作：继续压缩默认查询、按需加载步骤和长字段，必要时增加缓存或独立轻量摘要接口。
   - 2026-05-25：本轮先处理业务运行摘要列表的重 payload 风险，列表摘要不再加载 `result_payload`；近 24 小时 usage 记录显示 `/api/business/runs/get` 平均约 146ms、最大约 4.8s，但直接对 `business_runs` 大 JSON 排序会触发 MySQL sort memory 风险，后续仍需继续做索引/轻量摘要治理。

3. 对外接口文档门禁
   - 每个业务接口必须有请求、响应、状态枚举、错误码、JSON 样例和参数说明。
   - 图编辑、图裂变、文字强化裂变、裂变评分优先补齐。
   - 2026-05-25：已补齐图编辑 `canvas_outpaint` 常见错误码文档入口，并通过错误码和文档引用校验脚本。

4. 图编辑组件型业务收尾
   - 交互要按“整体工作台”处理，不再像普通表单堆字段。
   - 必须完成真实 GPT Image 2 样例回归、结果导出和内部客户接入说明。
   - 2026-05-25 扩展画布 `canvas_outpaint` 已完成契约侧落地，下一步优先跑低质量真实模型样例；独立 ComfyUI 扩图 5090 节点问题按服务器同构处理，不调整中台路由。

5. 页面文案与视觉降噪

   - 技术详情放到排障区，不再把内部字段当主文案。
