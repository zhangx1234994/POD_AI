## 本轮改动

### 1. runId 七阶段流程视图

管理端业务调用详情的“业务链路判定”已改为“runId 七阶段流程”，阶段固定为：

1. 提交入口
2. 版本命中
3. 输入预处理
4. 路由/分流
5. 主执行
6. 结果入库
7. 回调/计费

数据来源复用现有 `BusinessRun` 详情，不新增后端契约：

- `apiUsage.summary`
- `flowSummary.route / ability / executor / output / callback`
- `routeInfo`
- `requestPayload`
- `steps`
- `billingStatus / callbackStatus`

2026-05-27 继续降噪：runId 详情顶部新增“流程监控结论”，把原来分散在七阶段、出图质量标注、链路问题和治理动作里的信息合并为四个首屏信号：

- 当前卡点：优先显示危险/待确认阶段。
- 质量证据：根据本次输出和标注判断“待质量标注 / 质量风险 / 质量可用”。
- 治理动作：从链路问题、质量标注建议动作和风险标签派生下一步，例如补标注、记录治理项、分流、调参、换 LoRA/workflow。
- 阶段完整度：显示七阶段中已完成、风险、待确认数量。

### 2. 业务能力流程监控摘要

业务能力页已新增“流程监控摘要”，并把后端 `flowEvidence` 链路证据接入到近窗口业务健康：

- 七阶段卡片：提交入口、版本命中、输入预处理、路由/分流、主执行、结果入库、回调/计费。
- 核心业务行：花纹提取、图裂变、图编辑、扩图、文字裂变。
- 当前能识别：样本缺失、版本/参数/执行/结果/回调/计费问题、排队/运行中、未恢复问题。
- 已补结构化字段：阶段耗时均值/P95/样本数、路由命中、候选命中、LoRA 命中、workflow 命中。该字段只做观察统计，不自动改线上路由。
- 2026-05-27 继续降噪：主屏改为“当前卡点 + 七阶段流程轨道 + 运营/运维下一步”，阶段耗时和证据默认收进“阶段明细”。

### 3. 出图效果复盘入口

业务能力页已新增“出图效果复盘”面板，并接入轻量人工标注链路：

- 覆盖核心业务：花纹提取、图裂变、图编辑、扩图、文字裂变。
- 每个业务展示固定样例池、可抽检样本、本轮建议抽检数、输入标签、问题标签和下一步动作。
- 已新增人工质量标注落库接口和近窗口质量 TopN 汇总，业务页可读取已标注统计。
- runId 详情已新增“出图质量标注”，可逐张结果保存质量档位、输入标签、问题标签、建议动作和备注。
- 默认版本切换门禁已接入质量证据，五个核心业务候选版本需要近 168 小时至少一张 `excellent` 或 `usable` 标注；缺标注、只有风险样本或存在风险样本都会在上线证据里提示。
- TopN 输入/问题标签已接入样例下钻，可从复盘统计打开对应 runId，并在详情里定位到具体输出图。
- 质量汇总已增加版本维度，业务页“候选版本对照”可按默认/候选/草稿版本展示路由、workflow、LoRA、模型、最近运行和版本级质量样例。
- 候选版本对照已接入固定样例复跑入口，提交时会带 `metadata.qualitySample`，便于后续把同一批样例归因到业务版本和候选配置。
- 固定样例复跑已升级为批量样例集：可选择同一业务下多个版本和多个样例，提交后统一写入 `batchId`，质量标注完成后通过 `byBatch` 展示同批对照报告。
- 固定样例 URL 已升级为可保存复用的样例库：新增 `business_quality_samples` 表、管理端 CRUD 接口，候选版本面板优先用样例库预填单样例/批量复跑；样例库不可用时退回内置样例类型。
- 分流 / LoRA / workflow 候选治理已升级为轻量台账：新增 `business_quality_action_rules` 表、管理端 CRUD 接口，候选版本面板可查看并新增“哪类图走哪条候选策略”的记录。
- 固定样例库的 OSS 上传、批量导入和样例版本历史已在后续“固定样例库维护链路”补齐。
- 2026-05-27 继续降噪：主屏改为“本轮关注 + 业务行 + 运营/能力工程师下一步”，输入标签、问题标签和最近质量样例默认收进“标签体系与样例下钻”。
- 标签方案见 `docs/strategy/output-quality-review-v0.5.md`。

### 4. 业务能力页视觉降噪

2026-05-27 继续按“少就是多”调整业务能力页：

- “候选对照与固定样例复跑”每个业务默认只展示结论、下一步、默认版本、候选路线、质量证据和最近运行。
- 固定样例、质量治理台账、版本明细、同批质量对照默认折叠，减少首屏表格和标签噪音。
- 运营视角保留“批量复跑”和“记录治理项”两个高频动作；运维视角保留最近运行、质量风险、样例库数量和治理台账数量。
- 版本路线、LoRA/workflow、单版本复跑、质量样例查看保留在“版本明细”下钻里，不占用默认判断路径。
- 业务版本列表默认只展示默认、草稿和候选版本；已停用、历史路线或被新版本替代的版本收进“历史版本”，排障和回滚追溯时再展开。
- 测评端图编辑工作台补充交付方式简表：托管 `/image-edit` 自动跟随中台更新，自有页面嵌入则使用源码组件，并通过 `component-config` 判断是否需要业务方更新组件包。

### 5. 交互原则

- 首屏默认看阶段结论、当前关注阶段、状态和下一步动作。
- 底层 `taskId`、workflow、完整请求响应继续放在详情下钻，不做主标题。
- 外部业务反馈时仍以 `runId` 为主线。
