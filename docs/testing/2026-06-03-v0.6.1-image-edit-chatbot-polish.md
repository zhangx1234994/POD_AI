# v0.6.1 图编辑 ChatBot 与测评端降噪本地验收

## 结论

本地候选补丁已具备进入 114 控制面发布验证的条件。

本轮不是新增底层能力，而是修正 v0.6 图编辑入口的产品边界和交互问题：对话改图作为独立 ChatBot 能力，直接图编辑作为独立工作台能力；测评端首页不再用“业务方验收入口”大板块混淆能力分类。

## 已验证

### 1. 测评端图编辑分类页

- “业务方验收入口 / 选业务，跑一次，看结果”已移除。
- 左侧仍是能力分类导航，主能力优先排序，同时保留辅助工具分类导航。
- 图编辑分类保留两个独立入口：
  - 对话改图 ChatBot。
  - 直接图编辑工作台。
- 版本列表默认展开；上方推荐入口聚焦主动作，下面版本区承接完整可测版本，不再造成页面空洞。
- 静态包页面无 Vite dev 注入。

### 2. 对话改图 ChatBot

- 初始态不再展示四种硬分类卡：只知道方向、局部调整、删除修补、扩展画面。
- 初始输入框为空，只提供自然语言示例，不要求用户删除默认硬文案。
- 已改为“图片 Codex”线程式布局：
  - 左侧为最近任务，刷新页面后仍可恢复最近会话。
  - 中间只承载对话、建议、执行反馈和错误，不再把建议拆到独立右侧大面板。
  - 右侧固定展示主图、最新结果、当前状态、图片来源和调试信息。
- 主图上传/URL 后右侧立即可见，避免“上传了但不知道改哪张图”。
- “新建改图”用于开启独立线程，不删除左侧历史任务，避免新任务污染旧上下文。
- 发送自然语言需求后会立即显示“正在理解图片”；建议返回后直接进入对话流，并提供“执行这版”。
- 确认执行后的轮询从约 180 秒扩展到约 10 分钟，界面会显示“正在出图”和等待秒数，避免长耗时任务被误判为无响应。
- 执行中/执行成功后不再常驻展示大建议卡，避免用户误以为还可以修改或重复执行；只有执行前确认和失败重试时展示建议卡。
- 输出结果设计为回到聊天消息中展示；线上真实执行后需要重点复核图片回填。

### 3. 错误展示

本地 backend 当前以 `PODI_TEST_DISABLE_BACKGROUND_THREADS=1` 启动，因此确认执行时返回 `503 BACKGROUND_WORKERS_DISABLED` 是预期行为。

已验证页面会显示明确错误：

- `当前环境未启动后台执行线程`
- `BACKGROUND_WORKERS_DISABLED`

没有再退化成泛化的“服务异常，请稍后再试”，并且错误已进入 ChatBot 对话流，不只依赖 toast。

### 4. 后端 usage log 防御

补充测试覆盖长 `requestId`：

- 写入 `business_api_key_usage_logs.request_id` 前截断到 64。
- `error_code`、`business_key`、`status_code` 仍能保留。
- 使用日志写入失败不会遮蔽真实业务响应。
