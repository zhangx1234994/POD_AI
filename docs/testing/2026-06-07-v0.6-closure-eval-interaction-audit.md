## 3. 已发现并修复的问题

### 产品设计执行面和追踪口径错误

现象：`product-design-gpt-image2-v1` 是原生中台业务 API 能力，但工作台标签仍继承旧 `routingGovernance`，显示为 `ComfyUI 执行面` 和 `当前主要靠 Coze 输出追踪`。

影响：业务方、运营或能力工程师会误以为产品设计仍走 ComfyUI/Coze 工作流，和当前“中台能力、客户端编排业务”的边界冲突。

修复：

- `podi-eval-web/src/App.tsx` 新增统一标签推导 `getWorkflowExecutionTrackingLabels`。
- `business_api` / `business_run` / `business_agent` 能力统一展示为中台业务口径。
- GPT Image 2 相关业务能力展示为 `中台业务编排 · GPT Image 2`。
- 业务 API 能力统一展示为 `中台 runId 追踪`。
- 版本卡片补充明确 `aria-label`，便于用“进入某能力工作台”的语义定位。

复验：

- 产品设计工作台已不再出现 `ComfyUI 执行面`。
- 产品设计工作台已不再出现 `当前主要靠 Coze 输出追踪`。
- 产品设计工作台已显示 `中台业务编排 · GPT Image 2`。
- 产品设计工作台已显示 `中台 runId 追踪`。
- 产品设计版本卡 `aria-label` 为 `进入产品设计 · GPT Image 2 上品设计工作台`。

## 4. 剩余风险

- 本轮未触发真实出图，因此未覆盖提交、排队、运行、成功回填、失败错误码展示。
- AI 改图助手本轮只验证空态和示例填充，未复测二轮续改、新任务隔离和结果气泡。
- 产品设计代码层已补 5 类默认固定样例 seed；但本轮未在 114 导入，部署后仍需执行 `backend/scripts/seed_default_quality_samples.py` 并确认测评端样例数量。
- 首页版本卡虽然具备整卡可点击和 `aria-label`，但可视按钮文字不是独立 `<button>`；当前可接受，后续可在交互治理中继续优化。
