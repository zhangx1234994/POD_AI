# 产品商业化能力用户场景测试用例（2026-06-10）

## 测试范围

- 环境：114 线上测评端 `http://114.55.0.56:8200/`
- 版本：`564e6006`
- 主测能力：`产品文案内容包`
- 边界能力：`产品视频`
- 测试原则：先站在用户视角验证功能是否“能用、好懂、可复核、可交付”，再回到接口和日志定位问题。

## 用户角色

1. 首次使用商家：只有产品图和产品导出字段，希望快速拿到可上架文案。
2. 运营复核人员：需要判断文案是否可信、是否违反平台要求、是否能直接复制使用。
3. 能力工程师：需要看到模型、fallback、runId、错误原因和 OSS 回填，便于排障。
4. 接入开发者：需要确认文案能力、视频能力和后续配图生成动作边界清晰，接口口径统一。

## 验收底线

- 文案能力必须经过大模型或明确标记 fallback；不能把模板拼接当成验收通过。
- 文案和视频是两个独立能力；文案页只能提供视频后续联动入口，不能隐式触发视频。
- 付费或长耗时动作必须有显式按钮、状态、任务 ID、失败提示和可追踪结果。
- 用户更换产品图或 JSON 后，原确认状态必须失效，避免错商品进入成本动作。
- 页面必须能滚动到底部，结果不能被沉底或遮挡。

## 首轮结论

- 主链路已经可以给用户开始测试：输入产品图、确认字段、生成文案内容包、显式生成配图、下载图文包、视频独立入口均可走通。
- 首轮不建议称为最终封版：输入变更后的旧结果、文案/视频状态串联、配图接口归属和图片/JSON 冲突后的事实源传递都需要先修。
- 下载包与页面证据存在 fallback 口径不一致，属于可信度问题。
- 英文输出质量还需要打磨，尤其是中文字段进入英文文案的问题。

## 整改后结论

- 输入变更、非法 JSON、旧结果误用的 P0/P1 风险已在前端拦截。
- 英文交付面已增加事实翻译、残留中文剔除和测试覆盖。
- 新增后端事实守卫和 `resolvedProductFacts`，解决“图片和 JSON 不一致时下游配图/视频继续沿用错事实”的架构风险。
- 产品文案/产品视频页面状态已隔离，切换能力不再带入上一能力的图片、JSON、结果和任务状态。
- 配图执行已统一到产品商业化 run，不再借用产品设计接口；页面和接口文档均展示调用/查询口径。
- 产品视频规划后的执行脚本已改为可编辑，生成视频时按用户当前脚本提交，不再把脚本做成只读展示。
- 发布到线上后仍需复测一次真实下载包和一次线上文案生成，因为线上模型返回内容具有不确定性。
