# 认证与计费回归测试计划（Q2）

> 目标：在认证/钱包改造上线前，确保“不丢单、不误扣、不误登出”。

## 1. 测试范围

1. 认证链路：注册、登录、刷新、注销、会话管理、邀请码。
2. 计费链路：钱包余额、充值订单、流水、任务成本快照、账单。
3. 幂等与异常：重复回调、并发扣费、超时重试、失败回滚。

## 2. 必测用例（最小集合）

## A. 认证

1. 正常登录
- 输入正确邮箱/密码 -> 返回 access/refresh token。

2. 登录失败
- 密码错误 -> `INVALID_CREDENTIALS`。
- 用户禁用 -> `USER_INACTIVE`。

3. refresh
- 正常刷新成功。
- 过期 refresh -> `INVALID_TOKEN`。
- 已注销会话 refresh -> `SESSION_REVOKED`。

4. 邀请码注册
- 正常邀请码注册成功。
- 失效邀请码 -> `INVITE_CODE_INVALID`。
- 超次数邀请码 -> `AGENT_ENROLL_CODE_USED`（或统一邀请码错误码）。

5. 会话管理
- 多端登录后可查看会话列表。
- 踢出某会话后该会话 token 失效。

## B. 钱包与账单

1. 余额查询
- 新用户余额正确初始化为 0。

2. 充值订单
- 下单成功（pending）。
- 支付成功后余额增加。
- 支付失败不增加余额。

3. 任务扣费
- 成功任务扣费一次。
- 失败任务不扣费。
- 取消任务释放冻结金额。

4. 重复回调幂等
- 同一任务重复回调 N 次，账单只写一条扣费流水。

5. 账单与流水一致性
- 月账单汇总金额 = 当月流水汇总金额（同口径）。

## 3. 压测/并发用例

1. 并发提交 100 个成功任务，验证余额扣减总额正确。
2. 并发触发重复回调（同 task_id），验证不重复扣费。
3. 模拟外部接口超时重试，验证最终只落一笔流水。
